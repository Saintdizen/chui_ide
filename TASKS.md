План оптимизации инструментов (по порядку отдачи)
1. Штампы файлов вместо тотальной чистки кеша чтений — до 16 тыс. ток. на 3 беседы. Делать: read помнит mtimeMs+size на момент чтения; при следующем read сверяет. Не менялся → отдаём заглушку «уже прочитано, строки X–Y»; менялся → читаем заново и обновляем штамп. terminal больше не обнуляет покрытие. Где: shared/read-coverage.ts — ReadRanges → {from,to,stamp}, новая stampsFresh(ranges, stat); service.ts:1824 — на touched === null не чистить; agent-tools.ts, ветка read — сверка перед выдачей текста. Проверка: тест «terminal между двумя одинаковыми read → второй отдаёт заглушку; правка файла между ними → второй отдаёт текст».

2. Покрытие чтений на всю беседу, а не на шаг. Делать: coveredReads хранить рядом с историей беседы (сейчас создаётся в service.ts:1374 на каждый sendMessage); сбрасывать при compact и при переключении ветки. Проверка: тест «читаю файл, новый турн, тот же read → заглушка».

3. Учитывать пачечное `read(paths)` в покрытии — 12 423 ток. под угрозой полного повтора. Делать: readFiles возвращает outcome.reads: {path,from,to}[] (сейчас read не заполняется), service.ts:1816 прогоняет их через rememberRead; в coveredRequest/uncoveredRequest — ветка для запроса с paths. Проверка: тест «read {paths:[a,b]}, затем read {path:a, startLine:5, endLine:9} → заглушка».

4. Покрывать чтение без `endLine`. Делать: инструмент после исполнения знает фактический диапазон — запоминать его как {from, to: фактическая последняя строка}, чтобы следующий read с тем же startLine без endLine ловился как повтор. Проверка: тест «read {path, startLine:100}, затем он же → заглушка».

5. Нудж против чтения через шелл — оценочно 5–8 тыс. ток. Делать: если в ответе terminal команда опознана как чтение (grep|rg|cat|sed|head|tail|ls|git diff) и это второй такой вызов подряд в шаге — добавить одну строку «текст дешевле через read/search, там номера строк и обрезка». Где: agent-tools.ts, ветка terminal; флаг уже считается в shared/step-counts.ts (shell-read). Проверка: тест на появление строки после второго вызова и на отсутствие после первого.

6. Окно вокруг правки в ответе `edit` — 4 713 ток. (8 %). Делать: ответ edit несёт 3–5 строк контекста вокруг каждой правки, чтобы модель не перечитывала файл. Где: agent-tools.ts, формирование результата edit. Проверка: тест «после edit следующий шаг не обязан читать файл — контекст есть в ответе».

7. Замеры закрепить в репозитории. Делать: свести три одноразовых замера (причины повторов, шелл-чтения, цена нумерации) в scripts/read-repeat-census.ts рядом с scripts/output-census.ts, чтобы прогресс по п.1–5 мерился одной командой. Проверка: npx tsx scripts/read-repeat-census.ts печатает долю «перекрытие» и «повтор после терминала» до/после.

Порядок работ: 7 → 1 → 2 → 3 → 4 → 5 → 6. Скажи «начинай» — беру п.7 и п.1.
