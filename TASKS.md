- [ ] **`tests/git-service.test.ts` — 7.2с, дальше не режется.** Замер стоимости

- [ ] **Скорость Windows: шума нет, есть один файл.** Мерили на самом раннере 24.10
       (`scripts/test-time-census.ts`, 2 прогона подряд): 114.7с и 114.6с, сумма
       времени файлов 204068 / 202405 мс — разброс 0.8%, «гуляет сильнее всего» пусто.
       Прежние «±30с» были сравнением РАЗНЫХ прогонов на разных раннерах, а не шумом.
       Сумма файлов ≈203с при прогоне 115с: файлы идут параллельно, загрузка ~1.8×.
       Главная статья одна: `tests/git-service.test.ts` — 72.5с из 203с (на Linux 8с).
       Сделано: `-c safe.directory=*` перед каждой подкомандой git в этом файле
       (git перестаёт сверять владельца с системным и глобальным конфигом машины на
       каждом опознании репозитория); на раннере 72.5 / 76.0с → 51.9 / 52.3с.
       Остаётся ~52с на Windows. Куда смотреть дальше, по замеру:
       - СДЕЛАНО 24.10: четыре `git config` при создании тестового репозитория заменены
         ОДНОЙ дописью в `.git/config` — git-запусков в файле 956 → 527, время
         7.7 → 6.95с на Linux. `-c key=val` у `init` не годится: проверено, `-c`
         живёт только свой процесс и в `.git/config` не попадает.

         внутри `git()` держит процесс 7.6 мс (528 запусков / 4.0с), латентность
         самих процессов 5.3 мс, самое дорогое — `push -u` 5.2 мс. Остальные ~3с

         бессмысленно: потолок — 528 × 7.6 мс.
       - ОТКАЗАНО проверкой 24.10 (с цифрами, чтобы не возвращаться):
         * клон «снимка» под кэш (`--shared`) — 1.5 мс против 1.4 мс у `--no-hardlinks`,
           кэшировать нечего;
         * пакетная история (`hash-object`+`mktree`+`commit-tree`+`update-ref`+
           `symbolic-ref`+`reset`) — 20-22 мс против 15-17 мс у `init`+`add`+`commit`;
           на Win7-конфигурации репо настройки через `git config -f` тоже дороже;
         * два `git init` одним процессом — `git init` берёт ровно один каталог (129);
         * `push <адрес>` вместо `push origin` — `remote.origin.*` не создаёт.
       - СДЕЛАНО 24.10: `setIdentity()` писал настройки парой процессов на каждую;
         теперь `git config -f <путь> --replace-all` (git сам раскладывает по разделам).
         Грабля: `--replace-all` с ПУСТЫМ значением оставляет целый ключ с пустым
         значением, поэтому снятие идёт `--unset-all` — поймал добавленный тест.
       - СДЕЛАНО 24.10: `identity()` в `src/main/git` читал настройки СЕМЬЮ отдельными

         `src/shared/git-identity.ts` (последнее значение ключа побеждает, как у git).
       - ОТКАЗАНО 24.10 (проверено, не повторять): общий bare-снимок для `readOnlyRepo()`.
         19 тестов из 20 не делают ни одной git-команды по `bare` — только берут адрес,
