# Что предстоит

Только открытые задачи. Сделанное живёт в README, тестах и в истории файла
(`git log --follow -p TASKS.md`).

Правило по этому файлу: пункт попадает сюда либо с воспроизведением, либо со
ссылкой на строку кода, либо с пометкой «проверить». Выдуманных дефектов здесь
быть не должно.

## Поправка к предыдущей редакции

Два пункта, помеченные дефектами, при проверке кода **опровергнуты**:

- «статус-бар считает серверами ещё не инициализированные» — нет. `lsp.ts:948`
  ждёт `await runtime.initialized` ДО `runtimes.set` (стр. 964), в учёт попадает
  только ответивший сервер.
- «нет inlay hints» — есть целиком: запрос `textDocument/inlayHint`
  (`lsp-features.ts:354`), разбор (`shared/lsp-inlay-hints.ts`), показ
  (`editor-view.ts:1468`), перезапрос по правкам (`editor-host.ts:2290-2322`).

Ошибка была моя: искал в одном файле транспорта, а клиентская половина живёт в
`lsp-features.ts`. Урок: метод протокола ищется по всему `src`.

## Ловушка окружения (не забывать)

`web` (поиск) отвечает 404, `fetch` на `code.visualstudio.com` — «нет связи».
Документация читается через `terminal`: `curl -sSL <url>.md` (HTML — SPA, отдаёт
только шапку). Спецификация LSP — `metaModel.json`, полный:

```
curl -sSL https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/metaModel/metaModel.json
```

`.../specification.md` отдаёт **обрезанный** файл (42 КБ вместо полного) — по нему
список методов составлять нельзя. Сверку делать по metaModel, разбором JSON:

```python
c2s=[r['method'] for r in m['requests'] if r.get('messageDirection')=='clientToServer']
```

## Часть 1. LSP и подсказки

Сверка 02.11 по metaModel 3.17: клиентских запросов 53, уведомлений 19. Дальше —
всё, что в этом списке есть, а у нас не шлётся.

### Уведомления: не шлём 6 из 6 недостающих

1. **`workspace/didCreateFiles` / `didRenameFiles` / `didDeleteFiles`.** Создали
   файл в проводнике — сервер о нём не знает: импорт нового модуля не находится до
   перезапуска сервера. Самая заметная дыра (`grep` по `src/main` — ноль
   совпадений).
2. **`workspace/didChangeConfiguration`.** Поменяли настройки сервера — он живёт со
   старыми до перезапуска.
3. **`window/workDoneProgress/cancel`.** Человек отменил поиск ссылок — сервер
   продолжает считать по всему проекту.
4. **`workspace/didChangeWorkspaceFolders`.** Добавили корень в многокорневой
   проект — сервер видит один.

### Запросы: не хватает 10

5. **`textDocument/inlineCompletion`** — подсказки серые вперёд, как Copilot. У нас
   свои, по слову; серверные не спрашиваются.
6. **`typeHierarchy/supertypes` / `subtypes`.** `prepareTypeHierarchy` шлём, а сами
   уровни — нет: иерархия типов открывается и не разворачивается. Оговорка:
   `callHierarchy` есть, но живёт в `renderer/core/call-hierarchy.ts`, а не в
   `lsp.ts` — его при сверке по одному файлу тоже легко потерять.
7. **`textDocument/rangesFormatting`** — форматирование нескольких диапазонов
   разом. Сейчас только `formatting` и `rangeFormatting`.
8. **`textDocument/semanticTokens/range`** — подсветка видимого куска вместо всего
   файла; на больших файлах заметно.
9. **`textDocument/semanticTokens/full/delta`** — правка на символ перекрашивает
   весь файл.
10. **`textDocument/willSaveWaitUntil`** — форматирование перед сохранением
    (`editor.formatOnSave`). Одного `willSave` для этого мало.
11. **`resolve` у codeAction / codeLens / documentLink / inlayHint.** Сейчас
    `resolve` есть только у `completionItem` и `workspaceSymbol`; остальные
    приходят «как пришли» и теряют заголовки и команды. Звать, если сервер объявил
    `resolveProvider`.
12. **Pull-диагностика** (`textDocument/diagnostic`, `workspace/diagnostic`).
    Работаем на push-модели и так её и объявляем — честно, но на больших проектах
    push дороже. Отдельная задача: кэш, `resultId`, отмена.
13. **`didSave` для не открытых в редакторе файлов:** сохранение через файловый
    менеджер тоже стоит сообщать серверу.

### Качество запросов

14. **Диапазон inlay hints = весь файл.** `app.ts:616` зовёт с `endOfText(text)`.
    По спецификации `range` — «хотя бы этот кусок», но серверы считают по-своему:
    на больших файлах это лишняя работа на каждую правку. Просить видимую область

15. **Отмена запросов** (`$/cancelRequest`): проверить, уходит ли при брошенном

## Часть 2. IDE

1. **Нет недавних в командной палитре.** VS Code ставит `Ctrl+Shift+P` первым делом
   по MRU, потом всё остальное. У нас алфавит: человек, живущий в двух командах,
   ищет их каждый раз заново.
2. **Нет `Ctrl+Tab` по порядку использования.** VS Code держит MRU-список
   редакторов отдельно от порядка вкладок; нужно то же, и переживающее перезапуск.
3. **Состояние окна не восстанавливается точно.** Раскладка панелей пишется, а
   скролл, курсор и свёрнутые папки — нет: после перезапуска файл на первой строке.
4. **Множественный выбор в дереве не переживает перерисовку.** Выделение в
   `explorer.ts` есть, но любое обновление дерева (сохранение, git-статус) сбрасывает
   его на один файл.
5. **Нет блока «открытые редакторы» над деревом.** VS Code показывает его первым,
   и там же видны несохранённые.
6. **Настройки не показывают неправильные значения:** поле с мусором рисуется
   пустым вместо «ожидалось число».
7. **Нет файловых ассоциаций** (`files.associations`): расширение без языка
   остаётся без подсветки, хотя сервер для языка может быть.

## Часть 3. Проводник

1. **Сортировка.** Папки и файлы одним списком вперемешку (`a/`, `b.ts`, `c/`) —
   все редакторы держат папки сверху. В проекте на сотню файлов глаз перестаёт
   находить папки.
2. **Скрытые файлы только глобально.** Нужны исключения: `.git` всегда; по маске
   (`*.log`, `dist`); отдельно — показывать или скрывать начинающиеся с точки.
3. **Нет «показать в проводнике»** (`Reveal in File Explorer`) из вкладки и
   редактора, хотя обратное действие есть.
4. **Перетаскивание не описано правилом.** Перенос в папку должен спрашивать при
   несохранённых правках и переносить файл вместе с историей.
5. **Нет сравнения двух файлов из дерева.** `diff-view` и `folder-compare-modal`
   есть, но зовутся только из SCM.
6. **Цепочки папок без файлов** (`a/b/c`) не сворачиваются в одну строку — там, где
   экономится половина высоты дерева.
7. **Проверить:** создание и переименование с недопустимыми именами (`a:b`, `/`,
   пустое) и отклик на больших каталогах (`node_modules`) — не воспроизводил.

## Часть 5. Чат

1. **План теряется при перезапуске.** `ChatPlanPayload` живёт только в ленте
   (`chat-plan.ts`); `chat-persistence.ts` сохраняет `goal`, `reads`, `trace`, но не
   план. Ценность todo-панели именно в живости: закрыл окно — на чём остановились,
   не видно.
2. **`hidePlan` зовётся не в тот момент:** `chat-stream.ts:192` (в начале ответа) и
   `:405` (`finally`) — план гаснет на **каждом** ответе, а не когда модель сама его
   сменила.
3. **Сжатие посреди прогона режет по «ходу», а не по парам
   `assistant(tool_calls) → tool`** (`MIDRUN_KEEP_TURNS` в `service.ts`). Разрез,
   попадающий между ними, ломает протокол у строгих провайдеров (Anthropic). Резать
   только в точках, где нет висящих `tool_calls`.
4. **Нет `#`-упоминаний.** VS Code даёт `#file`, `#selection`, `#problems`,
   `#codebase`, `#web`. У нас есть приложение файлов, но не `#problems` (ошибки
   проекта в контекст) и не `#web`.
5. **Контекст не виден списком:** сколько токенов заняло что — нужно перед
   отправкой (как «Context» в VS Code).
6. **Ответ не делает кликабельными пути к файлам** и номера строк.
7. **Нет истории планов по беседе:** что уже сделано и когда.

## Часть 6. Подсказки (completions, hover, signature)

Здесь всё — «проверить»: код не читал, опираюсь на пункты спецификации, где чаще
всего спотыкаются клиенты.

1. **`additionalTextEdits`** из `completionItem` — автоимпорт: вставляется ли
   `import` вместе с вставкой.
2. **`commitCharacters`** — при вводе `.` или `(` подсказка должна приниматься, а
   не вставлять текст как есть.
3. **`isIncomplete`** — при нём повторный запрос обязателен, иначе список
   устаревает.
4. **`InsertReplaceEdit` и сниппеты** (`insertTextFormat=2`, `$0`) — правильно ли
   едет курсор внутри сниппета.
5. **`signatureHelp`** — активный параметр при вводе запятой.
6. **`selectionRange`** — расширение выделения по `Shift+Alt+→`.

## Порядок

1. Уведомления LSP (часть 1, п. 1–4) — точные данные, малые правки, видны сразу.
2. Дефекты чата (часть 5, п. 1–3) — у каждого проверяемый тест.
3. Сортировка проводника и скрытые файлы (часть 3, п. 1–2).
4. Подсказки: сначала «проверить» из части 6 — там же и дефекты найдутся.
5. Подсистемы: sticky scroll, MRU-списки, `#`-упоминания.

Ни один пункт не считается сделанным без теста и без `check:static`. Пункты с
пометкой «Проверить» сначала доводятся до воспроизведения, и только потом правятся —
или вычёркиваются, если дефекта нет.
