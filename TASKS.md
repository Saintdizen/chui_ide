## Довести до идеала: IDE · проводник · редактор · чат

Источник задач: документация VS Code (`code.visualstudio.com/docs/...`, берётся как
`.md`: `editing/codebasics`, `editing/editingevolved`, `editing/getting-started/
tips-and-tricks`, `chat/copilot-chat-context`) и известные поведения редакторов.
Каждый пункт — не «хотелось бы для галочки», а разрыв с тем, к чему человек
привык. Где пункт падает не на красоте, а на ошибке — помечено **дефект**.

### Ловушка окружения (не забывать)

Веб-поиск в этой сборке отвечает 404, а `code.visualstudio.com` из `web` — «нет
связи». Документация читается только через `terminal`: `curl -sSL <url>.md`.
Страницы отдают `.md`, если дописать суффикс; HTML отдаёт только шапку (SPA).

### Часть 1. IDE целиком

1. **Дефект: статус-бар врёт про LSP.** Счётчик поднятых серверов берётся из
   `runtimes.size` до того, как сервер ответил на `initialize`. Если сервер упал на
   старте, плашка ещё несколько секунд показывает «1 сервер», а переходы уже не
   работают. Нужно считать только `initialized`.
2. **Командная палитра без недавних.** VS Code (`tips-and-tricks`) ставит сверху
   `Ctrl+P Quick Open` и `Ctrl+Shift+P`: первым делом по списку **недавно
   использованных** команд, потом всех. У нас регистр — алфавитный; человек,
   работающий в двух командах, каждый раз ищет их заново.
3. **Нет `Ctrl+Tab` / `Ctrl+Shift+Tab`** по **порядку использования**, а не по
   порядку вкладок. VS Code отдельно держит MRU-список редакторов. Нужен список
   недавних **файлов** (рядом с недавними командами), переживающий закрытие.
4. **Состояние окна не восстанавливается точно.** Раскладка панелей пишется в
   настройки, а скролл и позиция курсора каждого файла — нет. После перезапуска файл
   открывается на первой строке. Нужен файл рабочей области
   (`workspaceState`-подобный): скролл, курсор, свёрнутые папки, активная вкладка.
5. **Множественный выбор в дереве не переживает перерисовку.** Выделить несколько
   файлов и позвать действие над всеми — обычный жест (у нас в `explorer.ts`
   выделение есть), но после любого обновления дерева (сохранение, git-статус)
   выделение сбрасывается на один файл.
6. **Нет обзора «открытые редакторы» над деревом.** VS Code показывает его
   первым блоком и там же живут «несохранённые» (точка на иконке). .
7. **Настройки не показывают неправильные значения.** `settings-modal` рисует
   то, что лежит в файле, и молчит, если поле не разобралось: человек видит
   пустое поле вместо «ожидалось число, пришло `abc`».

### Часть 2. Проводник

1. **Дефект: сортировка.** Папки и файлы идут одним списком вперемешку —
   `a/`, `b.ts`, `c/`. VS Code всегда держит папки сверху. Это не вкусовщина:
   в проекте с сотней файлов глаз перестаёт находить папки в середине.
2. **Скрытые файлы только глобально.** Переключатель прячет всё или ничего.
   Нужны исключения: `.git` — всегда; `.env` — настраиваемо; исключение по
   маске (`*.log`, `dist`).
3. **Нет «показать в проводнике» из вкладки и из редактора** (`Reveal in File
   Explorer`), хотя обратное действие есть.
4. **Перетаскивание файлов не описано как правило.** Перенос в папку должен
   спрашивать, если файл открыт с несохранёнными правками, и переносить его
   вместе с его историей.
5. **Нет сравнения двух файлов из дерева.** `folder-compare-modal` и
   `diff-view` есть, а зовутся только из SCM; из проводника — никак.
6. **Вложенность папок из одних папок** (`a/b/c` без файлов) не сворачивается в
   `a/b/c` одной строкой — а это то, где VS Code экономит половину высоты дерева.

### Часть 3. Редактор

1. **Дефект: `conceal` не как в VS Code.** Как бы ни выглядела правка, свернуть
   пару `{…}` и оставить пустую строку — значит сломать подсветку следующей
   строки. Проверить на многострочных литералах и шаблонных строках.
2. **Нет закреплённых строк (sticky scroll).** При прокрутке длинной функции имя
   функции должно остаться сверху. Требуется для `editor.` любой длины — это
   самый частый «где я».
3. **Раскраска скобок по уровням** (VS Code `editingevolved` → Bracket Pair
   Colorization) — не сделана. Сейчас все скобки одного цвета, ошибку в
   вложенности не видно.
4. **Inlay hints.** VS Code по умолчанию **включает** подсказки типов
   (`editor.inlayHints.enabled`, `editingevolved`). У нас запроса `inlayHint`
   нет вовсе — TypeScript/Rust не показывают выведенные типы.
5. **Меню контекста не зависит от места.** По правому клику в строке
   `import` и в обычной строке одно и тоже меню; нет `Go to Definition`,
   `Peek`, `Rename Symbol` для слова под курсором.
6. **Переключение комментария блоком** (`Shift+Alt+A`) отсутствует — только
   построчно.
7. **Превью движения по ошибкам** (`F8`): переход к следующей ошибке есть, но
   курсор прыгает без контекста — нет строки-предпросмотра в статус-баре.

### Часть 4. Чат

1. **Дефект: план теряется при перезапуске.** `ChatPlanPayload` живёт только в
   ленте (`chat-plan.ts`), в файл беседы не пишется (`chat-persistence.ts`
   сохраняет `goal`, `reads`, `trace` — но не план). Закрыл окно посреди работы —
   на чём остановились, не видно. Главное неудобство с `todo`-панелями
   (`docs/agents`, в VS Code — Todo List): их ценность именно в живости.
2. **`hidePlan` называется дважды и в неверные моменты** (`chat-stream.ts:192`
   и `:405`): план гасится на **каждом** новом ответе, а не тогда, когда модель
   сменила его самим действием. После перезапуска беседы видно пусто даже при
   сохранённом плане.
3. **Сжатие посреди прогона режет по «ходу», а не по паре
   `assistant(tool_calls) → tool`** (`MIDRUN_KEEP_TURNS` в `service.ts`). Ход —
   сообщение пользователя вместе с хвостом, но ветка инструментов может быть
   длиннее: разрез посреди пар ломает протокол у провайдеров строгой
   валидации (Anthropic). Нужно резать только между ходами, где нет висящих
   `tool_calls`.
4. **Нет «#-упоминаний» как класса.** VS Code (`copilot-chat-context`) даёт
   `#file`, `#selection`, `#problems`, `#codebase`, `#web`. У нас есть
   `@file` в composer'е, но нет `#problems` (ошибки в контексте) и `#web`.
5. **Контекст не виден как список.** Модель получает приложенные файлы, но
   человек не видит итог: сколько токенов заняло что. Нужна панель
   «контекст» перед отправкой (как «Context» в VS Code) — перечень источников с
   размером.
6. **Ответ не пересказывает ссылки на файлы.** В ответе `src/ui/chat.ts:12`
   не превращается в переход. VS Code делает кликабельными путь и номер строки.
7. **Нет истории планов по беседе.** После 3 шагов плана хочется видеть, что
   уже сделано и когда, а не только текущий чек-лист.

### Порядок

Сначала пункты с пометкой **дефект** — их можно закрыть точечно и проверить
тестом. Потом то, что требует новой подсистемы (sticky scroll, inlay hints,
MRU-списки). Ни один пункт не считается сделанным без теста и без
`check:static`.
