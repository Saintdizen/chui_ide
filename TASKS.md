Только открытые задачи. Сделанное живёт в README, тестах и в истории файла
(`git log --follow -p TASKS.md`).

Правило: пункт попадает сюда либо с воспроизведением, либо со ссылкой на строку
кода, либо с пометкой «проверить». Выдуманных дефектов здесь быть не должно.

живёт в `lsp-features.ts`.

## Часть 22. Свод по четырём областям: сверка эталона с кодом

### 22.1. IDE и оболочка

1. **Заголовок вида с `…`** (`ux-views`): каждый вид (Проводник, Поиск, Git,
   Ассистент, Проблемы) — заголовок + действия + `…` с полным списком.
   Сейчас шапки собираются по месту. Проверка: набор действий в `…` не
   зависит от вида, у всех видов он есть.
2. **Палитра показывает всё, что в реестре.** 190+ команд в реестре, в
   палитре и меню видно заметно меньше. Аудит: для каждой команды из
   `src/renderer/core/*commands*.ts` — видна ли она в палитре; невидимая —
   либо в палитру, либо маркер `hidden` с причиной.
3. **Справочник сочетаний генерится из реестра** (`ux-command-palette`):
   README и окно настроек берут его оттуда, а не пишут руками — иначе всё
   расходится (см. «Связки» ниже).
4. **Уведомления: одно действие + не показывать снова** (`ux-notifications`).
   `notice-registry` есть; нет отложенного повтора, `aria-live` для долгой
   работы и ограничения потока (N в очереди, остальное — счётчик).
5. **Строка состояния — живая** (`ux-status-bar`): язык, кодировка, EOL,
   отступы, LSP — по активному редактору; клик по каждому — быстрый выбор.
6. **Быстрые выборы — один механизм** (`ux-quick-picks`): `Ctrl+Shift+O`,
   `Ctrl+T`, `Alt+F10`, палитра, фильтр дерева — нечёткость, стрелки,
   `Ctrl+Enter` (в фоне), `Escape` с возвратом фокуса.
7. **Контекстное меню — группы и подменю** (`ux-context-menus`): только
   уместное здесь, группы, длинное — в подменю, пункты с сочетанием. Пройти
   дерево, редактор, вкладки, беседу, терминал, док.
8. **Макет на крайних значениях** (`custom-layout`): мин. ширина, вид у края,
   док справа, перезапуск — матрица, а не пара случаев.
9. **Всё без мыши** (`a11y`, APG): панель → док → уведомление → журнал →
   палитра → настройки → дерево → беседа → поиск. APG-шаблоны *перечитать
   перед* этим пунктом, а не по памяти.

### 22.2. Проводник

10. **Фильтр дерева — не только `includes`** (`core/tree-filter.ts`,
    `ui/explorer.ts`, Ctrl+F в дереве): у VS Code в строке фильтра `?` —
    один символ, `*` — любой, пробел — разделитель слов, папка видна по
    детям. `tree-filter.ts` знает только подстроку. Тест: каждая форма из
    примеров, плюс свёрнутая папка.
11. **Фильтр + вложенность** (`file-nesting.ts` + `tree-filter.ts`):
    фильтр не прячет спутники вложенного файла, связи не теряются, когда
    родитель отфильтрован.
12. **Режим проверки: правка без открытия** — новый файл, переименование,
    удаление с указателем пути (`Enter` — открыть, `Ctrl+Enter` — оставить
    в дереве). В `explorer.ts` перехватов дерева на это нет.
13. **`explorer.compactFolders`** — склейка одиночных цепочек папок
    (`src/core/Foo.ts` → `src/core/` одной строкой). В `file-nesting.ts`
    есть `FolderChain`, но это не настройка и не покрывает корневые цепочки;
    нужно переключателем и в матрицу порядка.
14. **Скрыть/показать исключённые** (`Files: Exclude`): строка «N файлов
    исключено» в хвосте дерева, клик — показать/скрыть.
15. **Множественный выбор** `Shift+↑/↓`/`Ctrl+Click`: сводные удалить,
    перетащить, копировать — один диалог, одно действие.
16. **Создать/переименовать/удалить/перетащить — один путь** (сейчас три
    разных в `explorer-commands.ts`, `path-commands.ts`, `ui/explorer.ts`):
    одна проверка занятости, одно подтверждение, `updateImportsOnRename`.
17. **Пустые места и отказы ФС** (`ux-views`, Views Welcome): пустой
    проект/папка/корень — разные тексты; `EACCES`/`ENOENT`/`EBUSY` — три
    разных сообщения, ни одного «ошибка».

### 22.3. Редактор

18. **Нормализация юникода и порядок вставки** (`edit-basics`): текст и
    курсоры — в порядке курсоров; `Ctrl+Z` возвращает туда же. В
    `editor-controller.ts` нормализация есть, порядок не покрыт тестом.
19. **Хвостовые пробелы и форматирование** (`trimTrailing` живёт в
    `core/file-write.ts`, а не в действиях редактора): команды обрезки хвостов,
    формат при вставке и формат при наборе — каждая одним `Ctrl+Z`.
20. **Связанные участки — правка** (`linkedEditing` в `editor-view.ts`
    только подсвечивает): второй тег меняется вслед за первым.
21. **Орфография и словарь** (`core/spellcheck.ts`): слово, добавленное в
    словарь, гаснет сразу; добавление отменяется; словарь в проект и в человека.
22. **Состояние настройки не спорит с командой:** тесты на «вкл/выкл»
    `wordWrap`, `minimap`, `sticky` — из окна настроек и из палитры одинаково.

### 22.4. Чат (`chat-overview`, `chat-view`)

23. **Порядок в очереди перетаскивается**, и «отменить всё в очереди» —
    одно действие. В `chat-queue.ts` сейчас только push/снять. Плюс

24. **Вложения множественные, с чипами** (`chat-overview`): несколько

25. **Выбор инструментов и контекста** (`tools-reference`, `workspace-context`):

26. **Управление контекстом:** `/compact`, `/new`, `/fork` — что найдётся

27. **Провенанс ответа:** модель, приложенный контекст, тронутые файлы —

## Часть 18. IDE

Эталон: `userinterface`, `custom-layout`, `a11y`, `keybindings`,
`ux-{notifications,status-bar,panel,command-palette,context-menus,quick-picks,views}`.

### 18.1. Одно правдивое место, где видно состояние

1. **Строка состояния как правило, а не как случай.** Сейчас в ней элементы
   собираются по мере подключения функций, поэтому порядок и состав меняются
   от проекта к проекту. По эталону у неё две стороны и постоянные места:
   слева — файл/ветка/проблемы (щёлк ведёт в соответствующую панель), справа —
   язык, кодировка, тип строк, позиция курсора. Проверка: открыть три проекта
   подряд — одни и те же пункты на одних и тех же местах.
2. **Статус ничего не теряет.** Элемент статуса по эталону: иконка + короткий
   текст + подсказка с подробностью + команда по щелчку. Проверить каждый
   элемент на все четыре свойства; тот, что не кочет команды/подсказки, —
   или доделать, или убрать (молчаливый значок хуже его отсутствия).
3. **Долгие операции видны от и до.** Прогон тестов, установка, git-тяга
   показывают прогресс в строке состояния или в панели — с кнопкой отмены
   там, где отмена возможна. Проверка: отмениться должно там же, где началось.
4. **Подсказка каждому элементу.** Всё, что с иконкой и без подписи
   (кнопки доков, ручки, значки дерева), имеет `title`/тултип и понятное имя
   для диктора. Тест: пройти интерфейс только диктором — не должно быть «кнопка».

### 18.2. Уведомления по правилам, а не по случаю

5. **Три уровня, один журнал.** Эталон: тост (кратко, уходит сам) → журнал
   уведомлений (модалка, вся история с группировкой) → беззвучный приглушённый
   вид. У нас `notice-registry.ts` умеет склейку/приглушение/невиданное, но
   надо сверить каждое место, где рождается ошибка: у каждой должен быть ключ
   `группа:что`, действие и заход в журнал.
6. **Ни одного молчаливого провала.** Все `catch`, которые сейчас только пишут
   в консоль, либо чинятся, либо говорят человеку. Проверка — греп по
   `catch` без `notice|log|throw` и тест на каждую найденную дыру.
7. **Не беспокоить насовсем.** «Не беспокоить» по группе с явным способом
   вернуть (список приглушённых в журнале). Сейчас приглушить можно — включить
   обратно только руками в настройках.

### 18.3. Команды и клавиши без сюрпризов

8. **Смена места сочетания аварийно не ломается.** Сейчас `KeybindingService`
   помнит «перебитое» старое и возвращает его отложенно — но нет способа
   посмотреть конфликты целиком. Добавить «клавиатурный конфликт» в
   `settings-modal`: какая команда победила, почему (порядок `when`/последняя
   правка) и кнопка «снять с пересечения».
9. **Все команды с путём ищутся.** По эталону палитра команд показывает и
   «Файл: переименовать…» (выбор из пути), а не только команды без
   аргументов. Сейчас такие места есть в подменю — они должны быть
   достижимы из `Ctrl+Shift+P` единым поиском (с пустым `args`, которые
   подскажет контекст).
10. **Палитра знает своё.** Группировка по категории, подсказка с сочетанием
    справа, повтор последней команды (`Ctrl+Shift+R`) — все три должны работать
    на всём множестве команд, включая созданные из меню и из расширений.
11. **Каталог горячих клавиш как справочник.** У эталона есть отдельный список
    всех сочетаний с поиском и экспортом. У нас сочетания живут в коде и в
    настройках — нужна сборка одного справочника из реестра команд, чтобы
    README генерировался, а не рос руками.

### 18.4. Окно, макет, рабочее пространство

12. **Док (панель снизу) как у эталона.** Вкладки внутри дока (Терминал, Проблемы,
    Вывод, Отладка) переключаются `Ctrl+Shift+P`-ом? Нет — `Ctrl+Shift+Alt+P`
    не нужно: нужны перемещение вкладки вправо/влево и переключение функции
    дока сочетаниями эталона. Пересмотреть, какие есть в `view.*`, и добить
    недостающие.
13. **Макет проверен на всех размерах.** С широким окном всё ясно; эталон требует
    свернуть/раскрыть без потери размера (это есть — `panel-layout`), но
    не проверено на 1) окне уже минимальной ширины; 2) переезде панели + док в
    правом положении; 3) перезапуске между ними. Написать тест на каждую
    комбинацию, а не только на пару «слева/справа».
14. **Закрытие и восстановление окна.** Горячий выход (незакоммиченные правки +
    несколько вкладок + журнал бесед) должен восстанавливаться целиком после
    `kill -9` и после аварии. Проверить весь список состояния и каждую вещь
    заявить в README.

### 18.5. Доступность и клавиатура

15. **Весь интерфейс без мыши.** Ни один пункт меню, ни одна кнопка, ни один
    тост не должны требовать мыши. Пройти следующие маршруты с выключенной
    мышью: открыть/закрыть/свернуть панель → переключить док → уведомление →
    журнал → палитра → настройки → дерево (полное) → беседа (полное) →
    поиск -> всё.
16. **Focus-ловушки и возврат фокуса.** Диалоги (настройки, быстрый выбор,
    уведомления) по эталону держат фокус внутри и возвращают его на то, что
    было в фокусе до открытия. Проверить каждый диалог.
17. **Проверка без предрассудков.** Всё, что читает диктор, важно: подписи
    `aria-label` не должны совпадать с невидимым текстом, «немые» иконки
    должны получить подпись, живые регионы (`aria-live`) — где долгая работа
    заканчивается. Собрать один смотр `role`/`aria` по всем панелям, а не по
    частям.

## Часть 19. Проводник

Эталон: `userinterface` (Explorer → деление), `ux-views`/`ux-sidebars`,
`ux-context-menus`, `a11y` (treeview/APG), `custom-layout` (Views Welcome),
наш `explorer.ts` + `file-nesting.ts` + `explorer-settings.ts`.

### 19.1. То, что есть, должно быть цельным

1. **Фильтр и вложенность не спорят.** `file-nesting.ts` свёртывает связанные
   файлы, фильтр (Ctrl+F в дереве) потом ещё раз норовит их спрятать.
   Проверка: включить вложенность, набрать `Button` — под родителем
   остаются видимыми и `Button.tsx`, и `Button.test.tsx`, и его дети
   тоже находятся. Сейчас это не покрыто тестом.
2. **Четыре вида правки файла — единый путь.** Создать, переименовать, удалить,
   перетащить: везде проверка занятости, `confirmDelete`, `updateImportsOnRename`
   и сообщение об ошибке. Проверка: тот же файл, три разных пути — одинаково.
3. **Перетаскиванием можно в папку — и только туда, куда можно.** Подсветка
   цели, запрет бросать в файл, самоброс в собственного ребёнка. Если сейчас
   есть только перенос по дереву — нужен и сброс извне (`pathForFile` уже есть):
   один и тот же путь с одним и тем же диалогом.
4. **Нечёткий поиск по дереву — как выбран.** Если фильтр ищет только
   подстроку, искать по совместимости: пробелы — `*`, `?` — один символ,
   папки попадают по детям. Эталон требует именно этого (quick open в
   проводнике и строка быстрого выбора — один механизм, а не два).
5. **Множественный выбор.** Выбрать несколько файлов клавиатурой
   (`Shift+↑/↓`), потом удалить/перетащить/копировать — один раз, а не N
   подтверждений (одно сводное). Сейчас дерево может держать один фокус —
   нужно пересмотреть.

### 19.2. Пустые места и честность

6. **Пустой проект, пустая папка, несуществующий путь — три разных ответа.**
   По эталону Views Welcome: на пустой — как запустить проект (иконка + пара
   пунктов), на пустой папке — ничего, кроме «создать файл», отвалился корень
   — «путь недоступен (был столько-то)» и кнопка «убрать из области».
7. **Отказ файловой системы виден.** Нет прав (EACCES), папка исчезла
   (ENOENT), занято (EBUSY) — три разных сообщения. Сейчас местами одна
   строка «ошибка»; надо пройти все отказы ФС и каждому дать текст.
8. **Чужие корни и смена корня на живом дереве.** Добавили корень снаружи
   рабочей области, убрали корень, переехал `package.json` — дерево и
   настройки по корню всё равно согласованы (`resolveExplorerSettings`).
   Здесь не хватает тестов на *перенос* (не только на слияние).

### 19.3. Взгляд и вкус

9. **Порядок и группировка: всё, что есть в настройках, проверено.**
   `foldersFirst`, `sort`, `groupByType`, `groupByPackage` — любые
   комбинации, вперемешку с вложенностью и скрытыми. Написать матричный тест:
   порядок результатов не должен меняться между запусками и не зависеть от
   скорости чтения ФС (сортировать по ключу, а не по приходу).
10. **Плотность и отступы.** У эталона строки одинаковы по высоте на любой глубине
    (выравнивание иконок по вертикали); свёрнутая папка не скачет по отступу
    при раскрытии. Проверка — замер высот строк и позиции значков на 3-4
    уровнях вложенности.

## Часть 20. Редактор

Эталон: `edit-basics` (полностью), `edit-evolved`, `a11y`,
`default-keybindings`, наши `editor/*` и `core/default-keybindings.ts`.

### 20.1. То, что есть, должно совпадать с эталоном

1. **Порядок вставки и якорей.** После вставки нескольких курсоров вставленный
   текст должен идти в том же порядке, в котором были курсоры. Проверка:
   два курсора, вставить многострочное; отменить — вернуться ровно туда же.
2. **Обрезание хвостовых пробелов — вставка и строка.** `trimTrailing` сейчас
   живёт в `file-write`; по эталону это и действие редактора (по сохранению и
   через команду), и оно не должно трогать строки с разметкой, где пробел значим.
3. **Форматирование вставки/набора.** По эталону: форматирование выделенного
   фрагмента, формата при вставке и формата при наборе — три разных, и все
   отменяются одним `Ctrl+Z`. Сейчас есть `editor.formatSelection`; проверить
   отмену и остальные два.
4. **Связанные участки — не только показ.** `linkedEditing` сейчас показывает
   парные теги; по эталону при правке одного меняется другой. Довести до
   правки или сказать в README, что это только подсветка (но лучше — сделать).
5. **Орфография: решение человека запоминается.** `editor.spellcheck` +
   `editor.addToDictionary` есть; нужно проверить, что слово, добавленное в
   словарь, не подсвечивается сразу (без перезапуска), и что она отменяется.
6. **Справка по редактору из эталона — шпаргалка в продукте.** Под `Ctrl+K`
   в эталоне есть весь список сочетаний; у нас справка нужна хотя бы
   как команда «Всеhotkeys» с генерацией из реестра (см. 18.11).

### 20.2. Файл, вид и сохранность

7. **Гонка двух сохранений.** Сохранить дважды быстро / автосохранение
   пересекается с `Ctrl+S` — на диске должен оказаться последний, а не
   предпоследний текст. Проверка — тест на `file-write` с задержкой.
8. **Файл изменили снаружи.** Правка на диске, пока файл открыт и изменён:
   по эталону — сравнить и предложить загрузить/оставить. Сейчас есть
   (или нет?) — проверить, и если нет, то это главный дефект редактора:
   тихая потеря чужих правок.
9. **Огромные и бинарные файлы.** Ограничение размера (2МБ/16МБ) уже есть;
   добить: бинарный файл → явный отказ с предложением открыть как текст, а
   не «кракозябры»; очень длинная строка (минифицированный `.js`) → без
   подсветки, но с поиском. Тест на каждый порог.
10. **Переводы строк и кодировка.** CRLF/LF — показать в строке состояния,
    при сохранении — не менять молча; битая кодировка — прочитать как
    Windows-1251 и сказать об этом.
11. **Сохранность вкладок и отмены при падении.** Отмена истории — на файл,
    переживает ли она перезапуск? По эталону — да (горячий выход). Вместе с
    18.14 проверить восстановление несохранённых и места вкладок.

### 20.3. Движение и взгляд

12. **Курсор и прокрутка по эталону.** `Ctrl+Home`/`Ctrl+End`, `PageUp/Down против
    вьюпорта`, `Ctrl+↑/↓` — не двигать содержимое, очень длинная строка —
    горизонтальная прокрутка с прижатием к слову, живой длинный файл — без
    дрожания. Альтернативно: прочитать статью через `web` и составить
    контрольный список — потом сверить.
13. **Скрол важнее": автоскролл прекращается при тычке мышью.** У нас
    `autoScroll` есть в беседе; проверить, что в редакторе «тыщу прокруток
    назад» не бросает вниз при вставке от агента.
14. **Мультикурсор как у эталона целиком.** Ctrl+D / Ctrl+Shift+L / Ctrl+Alt+↑↓ / Alt+Click /
    Tab в режиме мультикурсора / Shift+Alt+I. Команды есть — написать
    единый тест всех сочетаний из `default-keybindings` + работа с выделением
    из эталона.

## Часть 21. Чат

Эталон: `chat-overview`, `chat-view`, `inline-chat`, `copilot-chat-context`,
`raw/session-history`, `ux-notifications`, `a11y` (dialog/listbox),
наш `ui/chat*.ts`, `main/ai/*`, `shared/*`.

### 21.1. Ввод и постановка задачи

1. **История отправленного как в терминале.** ↑/↓ по прошлым задачам,
   `Ctrl+Enter` — отправить, `Shift+Enter` — строка, `Alt+Enter` — в текущий
   прогон (есть — `interject`). Проверить всю клавиатуру композера одним тестом.
2. **Ссылки на контекст** (`#файл`, `@` сущность): по эталону упомянутый
   файл прикрепляется к задаче, а не просто подсвечивается в тексте. Открыть
   вопрос: у нас вложения есть (`chat-attachments`), а разбор `#`/`@` —
   проверить и доделать.
3. **Вопрос вместо догадки.** Если задача двусмысленна, агент сначала
   спрашивает (с вариантами, выбор с клавиатуры), а не гадает. Проверить,
   что спрашивание видно в ленте, остаётся в журнале, и ответ на него
   попадает в следующий шаг прогона.
4. **Очередь и передача.** Очередь очередей уже есть (`chat-queue`), но
   порядок не правится: по эталону можно переставить/удалить/отправить
   сразу. Добавить перестановку (мышь + Alt+↑↓) и «отправить сейчас» из очереди.

### 21.2. Лента как документ

5. **Группировка шагов инструментов** — есть (`chat-tools`); добить: свёрнутая
   группа говорит статус «ссейчас работает: правлю такой-то файл» (это
   `busyHint`), а после завершения — итог (сколько файлов, сколько правок).
6. **Закреплённый запрос и золовие.** По эталону текущий запрос закреплён
   сверху ленты, пока листаешь ответ. Сейчас такого нет — сделать sticky-шапку.
7. **Поиск по беседе** — есть (`chat-find-bar`); по эталону вход в поиск
   из ленты не должен уводить курсор в редактор. Проверить свойство
   «нашел — вернулся на то же место» вживую.
8. **Ссылки и упоминания в ответе.** Клик по файлу/строке в ответе аgentа
   открывает их на месте (это главное обещание), а `Ctrl+click` — сбоку.
   Проверить все три вида ссылок (файл, файл:строка, символ) и вложения.
9. **Коллапс, отмена, повтор.** Отменить прогон, отменить один шаг,
   перезапустить с сохранением контекста — эти три по эталону разделены.
   Пройти руками, записать, сверить с `chat*` в код.
10. **Одна и та же правка дважды не приходит.** Адаптер (поток) может повторить
    событие после переподключения. Проверить идемпотентность всех событий
    стрима (`chat-stream`), а не только текста.

### 21.3. Не потерять работу

11. **Журнал бесед: вход, живой поиск, переименование, удаление** — есть
    (`chat-session`), но открыть в панели или вкладке должно быть выбором
    человека. Проверить, что перезапуск не теряет ни одну.
12. **Прикреплённая задача и провенанс.** У каждого ответа: кто (модель),
    какой контекст приложен, какие инструменты трогали файлы. По эталону
    это читаемо из ленты (как контрольная отметка), а не из лога. Проверить
    существующее и закрыть.
13. **Чекпоинты** (`chat-checkpoints`) — есть, но проверить, что он
    делает checkpoints по каждому шагу, а не только перед задачей; и что из
    него видно, что именно откатывается.

Всё остальное считается отложенным: ниже — только то, с чего начинаем и в

## Как это закрывается

Пункт считается закрытым, когда есть:

- **воспроизведение** — шаги, которые до правки давали неверное поведение
  (скриншот, запись, или падающий тест; для «проверить» — сначала именно он);
- **тест** — логика в `tests/`, поведение в `tests/dom/` рядом с соседями;
- **`npm run typecheck` и `npm run check:static`** без новых замечаний;
- **README** — если поведение видно человеку, абзац там, а не только в коммите.

Отдельно: идеальный интерфейс проверяется клавиатурой и диктором, а не только
мышью. Поэтому в каждой части есть пункт про `role`/`aria` и пункт про
путь без мыши — они не «на потом», а часть определения «работает».
