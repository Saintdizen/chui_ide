# Задачи chui_ide

Довести до идеала пять областей: **Оболочка IDE**, **Проводник**, **Редактор**,
**Чат**, **LSP и подсказки**. В файле — только открытые задачи: сделанное
переехало в README и в `git log --follow -p TASKS.md`, здесь его нет.

Пункты пронумерованы сквозно (1..N) — на номер ссылаемся в коммитах.
Внутри каждой области они идут группами от простого к сложному. У каждого —
источник: по нему пункт сверен. Свод по пяти областям собран из корпуса
`.log/` (VS Code, Zed, JetBrains, Sublime, Neovim, Microsoft Writing Style),
сверен по коду.

## Область 1. Оболочка IDE

### Горячие клавиши и команды

1. **Горячие клавиши открываемы.** Каждое действие в меню и в подсказке
   показывает своё сочетание; сочетание в подсказке кликабельно и ведёт
   в настройки клавиш. Источник: Zed `development/ui-checklist`
   (shortcuts discoverable), JetBrains `action-system`.

2. **Конфликт клавиш виден целиком.** `KeybindingService` умеет отложенное
   перебивание, но не говорит, какая команда победила и почему. Нужен экран
   конфликтов и кнопка «снять с пересечения».
   Источник: JetBrains `action-system` (Keymaps), VS Code `default-keys`.

3. **Справочник сочетаний — из одного реестра.** Сейчас три источника:
   `MENU_COMBOS`, `DEFAULT_KEYBINDINGS` и `keybinding:` в `define`. Меню,
   окно настроек и справка должны генериться из них, а не дублировать.
   Источник: JetBrains `action-system` (одно действие — одно описание).

4. **Палитра — всё, что в реестре.** Для каждой команды из
   `src/renderer/core/*commands*.ts` проверить видимость в палитре;
   невидимая — либо в палитру, либо маркер `hidden` с причиной. Плюс
   группировка по категории и повтор последней.
   Источник: VS Code `ux-command-palette`, Zed `command-palette`.

5. **Палитра — режимы `>` `@` `#`.** `Ctrl+P` открывает файлы, `>` — команды,
   `@` — символы текущего файла, `#` — поиск по проекту. Сейчас палитра
   файлов и команд раздельные. Свести к одному префиксному вводу.
   Источник: VS Code `ux-quick-picks`, `ux-command-palette`.

6. **Палитра — нечёткий поиск с подсветкой букв.** Сейчас поиск по подстроке.
   Zed и VS Code сортируют по «жадному» совпадению (буквы по порядку, бонус за
   начало слова и camelCase) и подсвечивают найденные буквы. Основа —
   `matchScore` из `editor/complete/fuzzy.ts`, чтобы правила были одни.
   Источник: VS Code `ux-command-palette`, Zed `command-palette`.

7. **Выбор из списка — один механизм.** `Ctrl+Shift+O`, `Ctrl+T`, `Alt+F10`,
   палитра, фильтр дерева — сейчас разная нечёткость в четырёх местах. Один
   виджет с хостом-поставщиком; стрелки, `Enter` и `Ctrl+Enter` (рядом/в фоне),
   `Escape` с возвратом фокуса, сочетания в подвале.
   Источник: Zed `command-palette`, JetBrains `popups`, VS Code `ux-quick-picks`.

8. **Быстрое переключение файлов — по недавним.** Quick pick поднимает недавно
   открытые наверх при пустом вводе, а `Ctrl+Tab` — история посещений, а не
   порядок вкладок. `shared/recent-commands.ts` есть — проверить, что он влияет
   на порядок, а не только хранится.
   Источник: VS Code `ux-quick-picks`, Zed `tab-switcher`.

### Уведомления, меню, пустые состояния

9. **Уведомление указывает, что изменилось.** Кнопка «Показать» ведёт туда, где
   проблема (файл, место, вид), а не просто закрывает тост.
   Источник: VS Code `ux-notifications`, JetBrains `notification-balloons`.

10. **Уведомление не отбирает ввод.** Тост над полем ввода не перехватывает
    щелчок и не сдвигает макет; живёт долго, пока не прочтут.
    Источник: JetBrains `notification-types`, VS Code `ux-notifications`.

11. **Отмена — одна кнопка, а не диалог.** Действие с последствием (удаление,
    переименование, закрытие всех вкладок) даёт «Отменить» в уведомлении и в
    журнале, а не модальное подтверждение перед каждым шагом.
    Источник: VS Code `ux-notifications`, Zed `development/ui-checklist`.

12. **Контекстное меню: группы и подменю.** Только уместное здесь, длинное —
    в подменю, пункты с сочетанием, разделители по смыслу. Пройти дерево,
    редактор, вкладки, беседу, терминал, док.
    Источник: VS Code `ux-context-menus`, JetBrains `popups`.

13. **Пустые состояния объясняют себя.** «Нет совпадений», «Файл не найден —
    создать?» — текст и действие, а не пустая панель. Проверить все списки:
    палитра, поиск по проекту, символы, проблемы.
    Источник: JetBrains `lists-and-trees` (Empty state), VS Code `ux-views`.

### Строка состояния и макет

14. **Строка состояния — из живого состояния и кликабельна.** Язык, кодировка,
    EOL, отступы, LSP — по активному редактору; клик по каждому — выбор (язык,
    кодировка, EOL, «перейти к строке»), ни одного только для чтения.
    Источник: JetBrains `status-bar-widgets`, VS Code `ux-status-bar`.

15. **Макет на крайних значениях.** Окно уже минимальной ширины, вид у края,
    док справа — после перезапуска всё читаемо, ничего не наезжает.
    Источник: Zed `development/ui-checklist` (Responsiveness), VS Code
    `custom-layout`.

16. **Раскладка помнит точный размер панелей.** Ширина/высота каждой панели
    переживает перезапуск и не «сбрасывается» при закрытии/открытии окна.
    Источник: JetBrains `tool-window`, VS Code `custom-layout`.

17. **Горячий выход и `kill -9`.** Незакоммиченные правки, вкладки,
    развёрнутость дерева, журнал беседы — восстановление целиком по одному
    признаку: приложение ведёт журнал до записи на диск.
    Источник: VS Code `custom-layout` (hot exit), Neovim `editing.txt`.

### Без мыши и доступность

18. **Всё без мыши.** Маршруты: панель → док → уведомление → журнал → палитра →
    настройки → дерево → беседа → поиск. Ни одного шага с мышью.
    Источник: Zed `development/ui-checklist` (usable without a mouse),
    VS Code `ux-accessibility`, JetBrains `lists-and-trees`.

19. **`role` и `aria` по шаблонам APG.** `treeview`, `tabs`, `dialog-modal`,
    `listbox`: фокус внутри диалога, возврат фокуса, живые регионы, стрелки в
    списках. Источник: VS Code `ux-accessibility`, Zed
    `development/ui-checklist` (Accessibility).

20. **Текст интерфейса по одному своду.** Кнопка — глагол, сообщение называет
    причину и что делать, ошибка не обвиняет человека, без жаргона.
    Источник: Microsoft `ms-writing-style`, JetBrains
    `how-to-write-guidelines`.

## Область 2. Проводник

### Фильтр и поиск по дереву

21. **Фильтр дерева — не только `includes`.** `matchesName` в
    `core/tree-filter.ts` знает одну подстроку. Нужно `?` (один символ),
    `*` (любая строка), пробел как разделитель слов и папка, видимая по детям.
    Источник: JetBrains `lists-and-trees` (Speed Search: wildcards, слова в
    любом порядке), VS Code `ux-sidebars` (find в дереве).

22. **Поиск по дереву подсвечивает совпадения.** Typeahead принимает `*` и `?`
    и подсвечивает найденные буквы внутри имён, а не только отбирает строки.
    Источник: JetBrains `lists-and-trees` (Speed Search, подсветка).

23. **Фильтр не рвёт вложенность.** `file-nesting.ts` и `tree-filter.ts` живут
    отдельно: фильтр прячет родителя — спутники вложенного файла теряются.
    Источник: VS Code `explorer` (nested files + find).

24. **Фильтр «показать скрытые» и «только изменённые».** Скрытые (точка в
    начале) и `files.exclude`, а также фильтр по git-статусу прямо в
    проводнике; скрытое можно показать, а не только спрятать.
    Источник: VS Code `explorer`, `settings`.

### Клавиши и навигация

25. **Дерево: полный набор клавиш.** `↑/↓/←/→`, `Home/End`, `PageUp/Down`,
    `Enter` на папке (раскрыть, а не открыть), `Ctrl+Enter` на файле,
    `Shift+↑/↓` — выделение диапазона, буквенный переход по первой букве.
    Источник: JetBrains `lists-and-trees` (Keyboard), Zed `project-panel`.

26. **Активная строка бледнеет, когда фокус ушёл.** Иначе два дерева (или
    дерево и палитра) показывают две «выбранные» строки и непонятно, куда
    уйдёт `Enter`. Источник: Zed `development/ui-checklist` (focus indicators),
    JetBrains `lists-and-trees`.

27. **Sticky-заголовок пути при прокрутке дерева.** Zed и JetBrains держат
    сверху путь к текущей папке, пока дерево прокручено. Редактор умеет
    (`sticky scroll`), дерево — нет; один и тот же чистый модуль пути.
    Источник: Zed `project-panel`, JetBrains `lists-and-trees`.

### Показ и сортировка

28. **Строка-исключение.** «N файлов исключено» в хвосте дерева, клик —
    показать/скрыть, причина исключения видна без правки настроек.
    Источник: VS Code `ux-views` (collapsed items), JetBrains
    `lists-and-trees` (пустое состояние объясняет причину).

29. **Пустое место говорит, что делать.** Пустой проект, пустая папка,
    пропавший корень — три разных текста и три разных действия (создать файл,
    выбрать папку, заново открыть).
    Источник: JetBrains `lists-and-trees` (Empty state), Zed
    `development/ui-checklist` (unhappy path).

30. **`explorer.compactFolders`.** Склейка одиночных цепочек папок одной
    строкой (`src/main/ai`); переключатель и поведение при фильтре и
    вложенности. Источник: VS Code `settings` (explorer.compactFolders).

31. **Порядок и группировка — матрица.** `foldersFirst`, `sort`, `groupByType`,
    `groupByPackage`, вложенность, скрытые: все комбинации и независимость от
    скорости чтения ФС. Источник: JetBrains `lists-and-trees` (сортировка и
    группировка), VS Code `settings`.

### Файловые операции

32. **Перетаскивание одинаково снаружи и изнутри.** `pathForFile` есть —
    проверить: бросок в файл и в собственного ребёнка запрещён с текстом,
    копирование/перемещение спрашивается всегда, иконка показывает результат
    до броска. Источник: JetBrains `lists-and-trees` (Drag and Drop),
    Zed `project-panel`.

33. **Инлайн-переименование с валидацией.** Занятое имя, недопустимые символы,
    пробелы в конце (как в Windows) — сейчас проверяется только занятость.
    Источник: VS Code `explorer`, JetBrains `lists-and-trees`.

34. **«Отменить» для файловых операций.** Удаление идёт в корзину (хорошо), а
    отмены нет: «Вернуть» в тосте после move/rename/delete.
    Источник: VS Code `ux-notifications`, Zed `development/ui-checklist`.

35. **Несколько корней проекта.** VS Code workspaces, JetBrains Content Roots.
    Сейчас один корень. Оценить объём; если дорого — отложенное решение с
    обоснованием, а не молчание.
    Источник: VS Code `custom-layout`, JetBrains `tool-window`.

## Область 3. Редактор

### Отмена и история

36. **Точка последнего изменения.** Восстановленный буфер помечает место, до
    которого правки уже были — повторное открытие не отматывает в начало.
    Источник: Neovim `undo.txt`.

37. **Отмена по шагам, а не одним куском.** Две подряд вставки от агента — два
    `Ctrl+Z`; правка несколькими курсорами — один шаг, но не склеивается с
    соседними. Источник: VS Code `edit-evolved`, Zed `editing-code`.

### Большие файлы и молчаливые пределы

38. **Долгая операция даёт признак жизни.** Открытие 50 МБ, поиск по 20 тыс.
    файлов, форматирование: строка прогресса и возможность отменить, а не
    «окно задумалось». Источник: Zed `development/ui-checklist` (Performance),
    JetBrains `progress-indicators`.

39. **Порог подсветки виден.** Файл без подсветки из-за размера говорит
    почему; есть кнопка «включить всё равно» с предупреждением.
    Источник: VS Code `edit-evolved` (large file optimizations).

40. **Длинная строка не вешает редактор.** Несколько мегабайт в одной строке —
    прокрутка и курсор отзывчивы; горизонтальная прокрутка прижимается к слову.
    Источник: Zed `development/ui-checklist` (large files).

### Навигация внутри файла

41. **Переключатель вкладок по недавним.** `Ctrl+Tab` листает по порядку
    открытия, а не по недавнему использованию; удержание и повторное нажатие
    не циклит. Источник: Zed `tab-switcher`. Файлы: `ui/tabs.ts`.

42. **Вкладка-просмотр.** Одиночный клик в дереве открывает файл во вкладке,
    которая заменяется следующим одиночным кликом, — рабочий набор не
    засоряется. Источник: VS Code `custom-layout` (preview editors).

43. **Скролл-позиция переживает перезапуск.** После перезапуска файл
    открывается на той же строке (и держит видимость при переключении вкладок).
    Источник: VS Code `custom-layout`, JetBrains `tool-window`.

44. **Переход к строке — `Ctrl+G` с автодополнением.** Поле принимает
    `файл:строка` и набирает имена файлов, как Sublime и VS Code.
    Источник: VS Code `edit-evolved` (goto line), Sublime.

### Правка кода

45. **Сниппеты с табуляцией.** `shared/code-snippets.ts` есть — проверить
    переходы `Tab`/`Shift+Tab` по местам подстановки, выход за границу
    сниппета, отмену одним `Ctrl+Z`.
    Источник: Zed `snippets`, VS Code `edit-evolved`.

46. **Форматирование сводится к одному пути.** Сейчас форматирует тот, кто
    первым ответил; нужен выбор из нескольких форматтеров и поведение
    «сохранить и отформатировать» одним действием.
    Источник: Zed `configuring-languages` (Formatting & Linting), VS Code
    `edit-evolved`.

47. **Overview ruler (полоса меток справа).** VS Code и Zed рисуют на правом
    краю метки ошибок, поиска, изменений git. Миникарта есть, полосы меток —
    нет. Отдельный узкий слой, клик прокручивает к метке.
    Источник: VS Code `edit-evolved`, Zed `development/ui-checklist`.

48. **Зум шрифта редактора** (`Ctrl+=`/`Ctrl+-`) с сохранением в настройках.
    В VS Code это `editor.fontSize` плюс временный зум жестом.
    Источник: VS Code `settings`.

49. **«Мягкая» линейка при переносе строк.** `wordWrap` + направляющие для
    перенесённых строк. Мелочь, сильно влияет на читаемость длинных строк.
    Источник: Zed `development/ui-checklist`, VS Code `settings`.

50. **Подсветка парных скобок и направляющие отступов.** Проверить, что обе
    включены по умолчанию, как у конкурентов, а не опцией.
    Источник: VS Code `settings`, JetBrains.

51. **Одна настройка — один результат.** Одна и та же настройка, меняемая из
    окна настроек, из палитры и из меню, даёт один результат, и он виден в
    строке состояния. Источник: Zed `development/ui-checklist` (Consistency).

## Область 4. Чат

### Лента и прогон

52. **Шаги прогона можно прокрутить и раскрыть.** В ленте свёрнутая группа
    показывает, что делает агент, раскрытая — весь путь: правка, результат,
    откат. Источник: Zed `ai/agent-panel`, VS Code `chat-overview`.

53. **Компактный режим — «свернуть всё, кроме ответа».** В длинных прогонах
    лента становится стеной. Общий переключатель свернуть/развернуть уже
    свёрнутые группы инструментов одним движением.
    Источник: VS Code `chat-overview`, Zed `ai/agent-panel`.

54. **Повтор — не дубль.** Событие стрима (`ChatStreamEvent`: `delta`,
    `reasoning`, `tool_start`, `tool_result`, `plan`, `goal`, `paused`, `step`,
    `interject`) при повторе после переподключения не дублирует текст, шаг,
    карточку подтверждения — тест на каждый вид.
    Источник: JetBrains `progress-indicators` (идемпотентность), VS Code
    `chat-overview`.

55. **Завершение прогона в одном месте.** Если прогон упал или прерван, в ленте
    видно почему и что осталось сделанным (файлы, коммиты, откат) — без чтения
    лога. Источник: Zed `ai/agent-panel`, `ai/threads`.

56. **Ошибка провайдера и «Повторить».** Ошибка провайдера/модели не выглядит
    как зависание: понятное сообщение и кнопка «Повторить» без потери вопроса.
    Источник: Zed `ai/agents`, VS Code `chat-overview` (unhappy path).

57. **Переход к диффу из сообщения агента.** Пометка «изменено файлов» с
    переходом к диффу прямо из сообщения; сверить с текущим списком файлов.
    Источник: VS Code `chat-overview`, Zed `ai/agent-panel`.

58. **Экспорт диалога** (Markdown / JSON) — как `Chat: Export Chat...` в VS Code.
    Источник: VS Code `chat-overview`.

### Клавиатура ленты

59. **Клавиатура ленты.** `↑` в пустом композере — вернуть прошлый вопрос,
    `PageUp/Down`, `Home/End` в ленте, `Esc` — фокус обратно в композер.
    Сверить с `shared/run-keys.ts` и `chat.ts`.
    Источник: VS Code `default-keys`, JetBrains `lists-and-trees`.

### Контекст и разрешения

60. **Выбор контекста набирается в поле и виден до отправки.** `#имя`
    вставляет чип, чип можно убрать до отправки и после; без тегов контекст
    берётся по правилам, а не целиком. Сейчас в меню есть только `#` —
    навигация, чипов контекста нет.

## Область 5. LSP и подсказки

Сердце LSP-клиента (`src/main/lsp/lsp.ts`) объявляет и умеет почти весь
протокол: definition, references, hover, signatureHelp, completion + resolve,
codeAction, codeLens, inlayHint, inlineCompletion, documentSymbol,
workspace symbol, selectionRange, foldingRange, formatting/range/onType,
rename + prepareRename, diagnostics (push и pull), semanticTokens
(full/range), typeDefinition, implementation, declaration. Задачи ниже — про
то, чего не хватает вокруг: настройки, подача в редакторе, устойчивость,
смена серверов.

### Настройки серверов и жизненный цикл

68. **Настройки LSP — из четырёх ключей в полноценный набор.** Сейчас есть
    только `lsp.enabled`, `lsp.detect`, `lsp.open`, `lsp.trace`. Нужно:
    per-язык выбор сервера, `lsp.<lang>.command`/`args`/`env`/`initOptions`,
    `lsp.<lang>.extraFolders`, приоритет и «отключить сервер». Окно настроек —
    с полем команды и кнопкой «проверить».
    Источник: VS Code `settings`, Zed `configuring-languages`
    (Language Servers).

69. **Перезапуск и остановка сервера по кнопке.** Из строки состояния и из
    палитры: «Restart Language Server», «Stop», «Show Output». После правки
    команды — перезапуск без рестарта приложения.
    Источник: VS Code `default-keys` (LSP-команды), Zed
    `configuring-languages`.

70. **Статус сервера виден в строке состояния.** Клик по сегменту LSP
    показывает: какой сервер, состояние (запуск/готов/ошибка/пауза), версию,
    корень; здесь же «перезапустить» и «открыть журнал».
    Источник: JetBrains `status-bar-widgets`, VS Code `ux-status-bar`.

71. **Журнал сервера читаем внутри приложения.** Отдельная панель «Output → LSP»
    с потоками message/trace/log и фильтром по серверу; уровень пишется в
    `lsp.trace`. Сообщения `window/showMessage` попадают в уведомления с
    кликабельной ссылкой. Источник: VS Code `ux-notifications`,
    JetBrains `notification-balloons`.

### Подсказки и всплывающие окна

72. **Ховер не мигает и не крадёт фокус.** Задержка появления настраивается,
    окно держится, пока читают, переносится, не перекрывает курсор; `Ctrl`
    в ховере — как в VS Code — раскрывает больше.
    Источник: VS Code `edit-evolved` (hover), JetBrains `popups`.

73. **Автодополнение: причины, регистр, порядок.** В списке подсказок виден вид
    элемента (метод, поле, сниппет, модуль), документирующее окно справа,
    подсветка совпавших букв. Учитывать `sortText`/`filterText`/`preselect`,
    `commitCharacters`, `isIncomplete` (допересылка по мере ввода). Правила
    нечёткости — одни на проект (`editor/complete/fuzzy.ts`), включая
    регистронезависимость и бонус за начало слова.
    Источник: VS Code `edit-evolved` (IntelliSense), Zed `editing-code`.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла и переезжает в README и в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
- Сквозная нумерация (1..N) сохраняется: новый пункт получает следующий номер
  в конце своей области; при переносе между областями номер обновляется по
  позиции, а не переиспользуется.
- Сначала чинить то, что ломает работу (потеря работы, зависание, слепой
  сервер), потом польза, последней — косметика.
