# TASKS

Путь к «идеалу» по эталонным IDE (IntelliJ IDEA, VS Code, плюс что берём у Sublime/Zed).
Шесть срезов, нумерация сквозная, без повторов между срезами.

Источники (проверенные, живыми памятками): JetBrains Help — Project tool window, Using code
editor, Editor gutter, Work with code in editor, Local History, Intention actions, Inlay hints,
Agents in IDE; VS Code Docs — codebasics, editingevolved, intellisense, refactoring,
tips-and-tricks, copilot-chat-context. Каждый пункт ниже говорит, что у нас есть сейчас и чего нет —
по сверке с кодом, а не по памяти.

## 1. Оболочка — рамка вокруг всего

1. **Вкладки и группы вкладок.** Есть открытые редакторы и разбиение экрана; нет разбиения
   на группы с перетаскиванием вкладки между ними, закрепления группы и «все вкладки одного проекта в окно». У IDEA есть Split screen, у VS Code — редакторские группы с сохранением раскладки в рабочей области.
2. **Рабочие пространства (layouts).** Раскладка панелей не сохраняется в именованный пресет
   (VS Code Workbench / IDEA Layouts), нельзя вернуть «как было до перетаскивания».
3. **Панели — в любом месте.** Панель умеет прилипать по краям; нет «плавающая панель» и
   перестановки панели в другую сторону одним пунктом (IDEA View | Appearance | Floating mode).
4. **Zen/распахнутый редактор.** Максимизация панели есть; нет режима «всё скрыто, остался
   только текст» с выходом по Esc (VS Code Zen Mode, IDEA Distraction Free).
5. **Заметки к файлу и проекту.** `mind` — заметки агента; у человека нет своих заметок к
   файлу, которые видны в проводнике и переживают перезапуск.
6. **Строка состояния говорит больше.** Есть язык, кодировка, позиция; нет «профиля
    форматирования», «кросс-линии», «пустого места на клик — отключить линзы» одним щелчком (у VS Code это пункты строки состояния).
7. **Тепловая карта правок в мини-карте.** Мини-карта и правки-метки есть; нет показа
    «где сейчас сидят несохранённые правки агента» поверх всей карты.
8. **Пересадка горячих клавиш.** Карта клавиш наша; нет импорта VS Code keybindings.json и
    профиля IDEA, чтобы пересевший человек не терял пальцы.

## 2. Проводник

9. **Действия в любом узле.** В меню файла есть переименовать, удалить, копировать путь; у
   папки нет «Открыть терминал здесь», «Скопировать путь», «Найти в этой папке», «Свернуть все потомки» (IDEA: контекст проекта — полный набор).
10. **Поиск по проводнику набором (Speed Search).** Начни печатать поверх дерева — у IDEA
    дерево фильтруется по префиксу и Enter выбирает; у нас такого нет (поиск файлов — отдельной панелью).
11. **Перетаскивание с переписыванием импортов.** `workspace.updateImports` и настройка
    `updateImportsOnRename` есть — перетаскивание ими не пользуется: пункт — довести
    перетаскивание и переименование до одних ворот, undo — одной отменой.
12. **Фильтр дерева переживает переоткрытие.** Исключения читаются, но фильтр-набор в
    дереве не запоминается между запусками (IDEA: File nesting / VS Code: Explorer filter state).
13. **Свёрнутое дерево не схлопывается при обновлении корня и переключении проекта.**
    `restoreExpanded` есть и сессия его сохраняет; обновление корня (внешний git, смена
    ветки) сбрасывает раскрытие — пункт: перечитывать и восстановить.
14. **Файловые операции глазами модели.** У человека есть переименование и удаление; у агента — нет `file move/rename/delete` отдельным действием с ручным подтверждением, он правит содержимое.
15. **Ссылки и импорты — в меню файла.** Нет «Найти все ссылки на файл» и «Показать зависимости»:
    у IDEA это Find Usages, у VS Code — References view.

## 3. Редактор

16. **Живые шаблоны.** Вставка сниппетов и postfix есть (`editor/complete/postfix.ts`); нет
    своих живых шаблонов с переменными и обходом табуляцией (IDEA Live Templates).
17. **История буфера обмена.** `shared/paste-clean.ts` чистит вставку; нет журнала вставок
    (IDEA Ctrl+Shift+V) и «вставить без форматирования» отдельной командой.
18. **Local History — история файла без git.** Есть undo/redo и `history-modal`; нет снимков
    файла по времени с diff и откатом к «как было час назад» (IDEA Local History).
19. **Свернуть всё, кроме выбранного.** Свёртка и «свернуть всё» есть; нет «свернуть все, кроме сложенных по выделению» (IDEA Code | Folding).
20. **Свои вхождения слова.** `documentHighlights` спрашивается у сервера и рисуется; нет
    своей подсветки слова под кареткой, когда сервер молчит (VS Code Editor: Occurrences Highlight).
21. **«Показать невидимое» на кнопке.** Подсветка пробелов и переводов строк есть в настройках; нет
    переключателя в статусбаре и запоминания (VS Code `editor.renderWhitespace`).
22. **Сравнение с диском и с буфером.** Сравнение двух файлов и выделений есть (`core/compare-commands.ts`); нет «сравнить с сохранённым» и «сравнить с буфером» (VS Code: Compare with Saved).
23. **Выделение по шаблону структуры.** Smart selection по `selectionRanges` есть; нет «выделить всё тело функции разом» из свёртки и «выделить всё вхождение символа» (IDEA: Extend Selection / Select All Occurrences).
24. **Перевод строки при сохранении.** Есть концовка строки в настройках; нет
    конвертации CRLF/LF по файлу из строки состояния и авто-подхвата по проекту (.editorconfig).
25. **Поиск с параметрами — по регэкспу с подсветкой групп.** Замена по regex есть и группы
    именованные есть; нет «поиск в выделении» и «заменить все» с показом счётчика по группам.
26. **Search Editor.** Поиск по файлам отдаёт список мест; нет отдельного документа-выдачи,
    где результат можно править и пересохранять (VS Code Search Editor).

## 4. Чат (агент)

27. **Очередь промптов.** Отправка во время прогона есть (`ui/chat-queue.ts`); нет видимой
    очереди с порядком, удалением и «вставить в текущий прогон» (IDEA: Prompt queueing).
28. **Контекст-пикер явным списком.** Прикрепление файлов и выделения есть; нет одного списка
    «файлы, папки, коммиты, экран, навыки» с поиском и недавними (IDEA attach context).
29. **Правка очереди инструментов до отправки.** Подтверждение есть; нет «увидеть очередной
    вызов инструмента и поправить аргументы» до выполнения (IDEA: Edit before send).
30. **Сводка расхода панелью.** Сводка за день и разбивка по моделям есть (`shared/spend.ts`);
    нет панели «расход по дням и моделям» с графиком (IDEA Agents: cost management).
31. **Плёнка прогона.** Журнал шагов есть (`run-inspector`, `run-log`); нет непрерывной ленты
    «что агент видел и делал» с прыжком из шага в файл и обратно.
32. **Отмена по куску.** Стоп гасит весь прогон; нет «отменить этот вызов инструмента», не
    трогая остальные (IDEA: stop single action).
33. **Ссылки в ответе.** `#file` и `@файл` по имени есть; нет автодополнения путей в
    композере по `#` (VS Code `#-mentions`) и вставки выделения одним нажатием.

## 5. LSP и подсказки

34. **Подсказка о параметрах при входе в скобки.** `signatureHelp` подключён и вызывается
    по `(` и `,`; нет подсветки текущего параметра и перелистывания перегрузок стрелками (VS Code `editor.parameterHints`).
35. **Задержка наведения отдельной настройкой и «Ctrl — сразу».** `editor.hoverDelayMs` есть; нет
    «держи Ctrl — показать немедленно» и отключения подсказок для определенных языков.
36. **Быстрые исправления списком.** `codeAction` подключён; нет панели «что можно исправить здесь»
    с описанием последствий до применения (IDEA Intention Actions, VS Code Code Actions on Save).
37. **Инлайн-хинты настраиваются.** `lsp-inlay-hints.ts` есть; нет переключателя «типы/параметры/
    возвращаемые» из строки состояния и настройки по языку.
38. **Семантика поверх грамматики с откатом.** `semanticTokens` подключены; нужен явный
    приоритет и слой отката на грамматику, когда сервер молчит или упал (иначе файл «серый»).
39. **Свои подсказки поверх серверных.** `ui/tooltip.ts` обслуживает агента; нет словаря проекта
    (имена, сокращения) поверх серверного hover (VS Code: свой provider выше по приоритету).
40. **Орфография сервером проекта.** Есть свой словарь (`main/spell`); нет использования LSP-сервера
    орфографии и общих словарей с проектом (например, cSpell).
41. **Диагностики всего проекта с переходом.** `project-diagnostics.ts` есть; нет сводки
    «сколько ошибок и где» с переходом из сводки (IDEA Problems view, VS Code Problems).
42. **«Кто меня зовёт» и «иерархия».** `lsp-call-hierarchy` и `lsp-type-hierarchy` есть; нет
    панели с деревом и навигацией внутри (IDEA Call Hierarchy / Type Hierarchy).
43. **Сниппеты сервера с обходом табуляцией.** `completionItem/snippet` приходит; нет обхода
    плейсхолдеров табом внутри файла (VS Code snippet mode).

## 6. Инструменты агента и их экономия

Сейчас в наборе 19 инструментов (`shared/tools.ts`); есть пресеты, счётчики шагов и
`scripts/chunk-cost.ts`. Пункты — только о том, чего в этих замерах нет.

44. **Счётчик «цена одного успешного действия».** `step-counts` считает шаги и отказы по
    причинам; нет метрики «сколько токенов и шагов стоил один коммит/правка» — без неё
    экономия недоказуема. Пункт: отчёт `scripts/action-cost.ts` и порог в тесте.
45. **Бюджет шагов по типам задач.** `chat-budget` есть; нет потолка шагов по сложности задачи
    (короткий вопрос — 1 шаг, рефакторинг — до N) с остановкой и честным отчётом, что не успели.
46. **Сокращать схему по ходу прогона.** Пресеты дают один набор на прогон; нет «убрать
    инструмент после N бесплодных вызовов» и «включить редкий по запросу» (уже сделано для
    `task` и `skill` как ростер — распространить правило на остальные редкие).
47. **Склейка повторных чтений.** `reads` помнит прочитанное внутри хода; нет «этот файл не
    менялся, диапазон тот же — вернуть кэш и не платить». Пункт: хэш (путь, диапазон, версия) в `read`.
48. **Дешёвый первый шаг.** «Просто спросил» уже идёт пресетом «Основа»; нет замера, сколько
    токенов уходит **до** первого вызова инструмента, и порога на этот префикс.
49. **Ростер вместо схем для редких.** `terminal` развели действиями, `task` и `skill` — ростером;
    нет правила «ромбовидные схемы только у частых» и сторожа, который ловит нарушение.
50. **Авто-сжатие вывода инструмента под задачу.** `output-budget` и спилл есть; нет режима
    «вернуть только запрошенные поля», когда модель просит одно, а инструмент отдаёт всё.
51. **Цена в подтверждении.** Тост подтверждения показывает действие; нет цены «примерно столько
    токенов» до нажатия — человек должен видеть, что покупает.
52. **Один вызов вместо нескольких.** `tool-router` есть; нет «сгруппировать соседние чтения в
    один вызов» (несколько `read` заранее) по шаблону вопроса.

## Правила работы со списком

1. Перед работой над пунктом — сверка с кодом. Половина пунктов прошлых раундов уже была
   сделана; закрывать «на глаз» дороже, чем проверить.
2. Закрытый пункт и породивший его код — один коммит; TASKS правится в том же коммите.
3. Пункт, оказавшийся готовым, вычеркивается в тот же миг — без пометки «оказалось готовым».
4. Замер — часть работы: экономия без числа перед и после не считается сделанной.
