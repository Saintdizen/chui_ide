## Структура (долгая правка, отдельной сессией)

Вне класса уже всё, что проверяется отдельно (`workspace-context.ts`,
`src/shared/read-coverage.ts`, `git/exec.ts`, `git/forge.ts`, `git/bisect.ts`).
Без повода не затевать: выигрыш здесь только в читаемости, скорость и поведение те же.

- [ ] **`src/main/git/git.ts` — 2 010 строк, 114 методов.** Распил идёт по одному
       узлу за сессию, методика та же, что на `agent-tools.ts`: grep частоты
       `this.X(` по блоку, брать узел с МАЛОЙ зависимостью от состояния класса.
       Вынесено так: `exec.ts` (запуск git и forge), `forge.ts` (413 строк — задачи,
       конвейеры, уведомления; класс зовёт его через `ForgeContext` из четырёх
       методов: `root`, `repositoryRoot`, `remotes`, `refresh`), `bisect.ts` (90
       строк; `BisectContext` из трёх: `root`, `refresh`, `gitPath`). Остальные
       блоги так не отрезаются — у них 25–36 вызовов `this.repositoryRoot`/
       `this.requireRoot` на блок, то есть каждый тянет состояние класса. Дальше
       только вынос `GitService` целиком на составные сущности (watcher,
       index/status, ветки, worktree, подмодули, личность и ключи) с явными
       зависимостями.
