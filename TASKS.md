# TASKS

Открытые дела по трём срезам: Проводник, Редактор, LSP и подсказки.
Нумерация сквозная и не переиспользуется.

## 1. Проводник

1. **Действие — на любом узле.** Меню файла есть, но у папки нет одним списком
   «Открыть в терминале здесь», «Скопировать путь», «Найти в этой папке»; у корня
   нет «Обновить». У VS Code контекстное меню узла — полный набор, у нас — часть.
2. **Перетаскивание с переносом импортов.** Файл перетаскивается, но правка импортов
   после переноса (у VS Code это расширение, у JetBrains — Move refactoring) не выполняется.
   Пункт: перетащил `.ts` в другую папку — относительные импорты переписаны, undo — одной отменой.
3. **Фильтр дерева переживает переоткрытие.** Исключения проекта читаются
   (README, «Правила проекта и исключения»), но фильтр в дереве не запоминается.
4. **Поиск по проводнику.** Начни печатать поверх дерева — у VS Code это фильтр-набор,
    а Enter уходит в поиск по файлам. У нас такого совмещения нет.
5. **Свёрнутое дерево не схлопывается при обновлении корня.** Состояние раскрытия есть,
    но при обновлении корня дерево схлопывается — у JetBrains и VS Code сохраняется.

## 2. Редактор

6. **Липкая строка области видимости.** `sticky` встречается только в свёртке; у VS Code
    и JetBrains при прокрутке сверху висит текущая функция/класс. Пункт: строка-заголовок
    области, клик — переход к её началу.
7. **Хлебные крошки над файлом.** Их нет (упоминание `breadcrumbs` в дереве — про проводник).
    У VS Code и JetBrains они показывают путь внутри файла и дают прыгать по уровням.
8. **Сворачивание «всё кроме этого».** Из трёх подпунктов свёртки был один — осталось
    «свернуть всё, кроме выбранного» и «свернуть подобранное по выделению».
9. **История правок файла.** Есть undo/redo, но нет Local History поверх сохранений:
    «что было в этом файле час назад», без git. У JetBrains это отдельная панель.
10. **Подсветка вхождений символа под кареткой.** `documentHighlight` у сервера спрашивается,
    но своя подсветка слова на месте в редакторе не включается — VS Code делает оба уровня.
    Пункт: своя подсветка плюс серверная поверх, разные цвета для чтения и записи.
11. **Выделение — по несколько сразу и по столбцу.** Мультикурсор есть, прямоугольного
    выделения (column selection, Alt+drag) нет; у JetBrains и Sublime есть.
12. **Вставка с историей буфера обмена.** Есть очистка вставки (`shared/paste-clean.ts`),
    нет журнала вставок (JetBrains: Ctrl+Shift+V) и «вставить без форматирования»
    отдельной командой.
13. **Шаблоны живого текста.** Есть вставка сниппетов и дополнение, но нет пользовательских
    живых шаблонов с переменными и обходом табуляцией (JetBrains Live Templates).
14. **Postfix-дополнение.** `if.` → `if (…)`, `.var` → переменная. У JetBrains это отдельный
    механизм поверх обычного дополнения; у нас нет.
15. **«Показать невидимое» переключается.** Пробелы, табуляция, переводы строк — команда
    есть местами; нужен переключатель в статусбаре и сохранение выбора.
16. **Сравнение с буфером обмена и с сохранённым.** Сравнение двух файлов и выделений есть;
    «сравнить с буфером» и «сравнить с диском» (у VS Code — в контексте вкладки) нет.

## 3. LSP и подсказки

17. **Подсказка параметра — в вызове.** `signatureHelp` подключён, но не показывается, когда
    каретка внутри аргументов (у VS Code и JetBrains — автоматически, с подсветкой текущего
    параметра). Нужно: автопоказ при входе в скобки, подсветка параметра.
18. **Подсказка при наведении — на своей задержке.** `textDocument/hover` есть в `lsp.ts`
    и `lsp-features.ts`; нет настройки задержки и «держать Ctrl — показать сразу» (VS Code).
19. **Свои подсказки поверх серверных.** `ui/tooltip.ts` обслуживает подсказки агента;
    перекрытия подсказок редактора своим словарём (слова проекта, сокращения) нет.
20. **Код-экшены по подсветке.** `codeAction` есть, но нет панели «быстрые исправления для
    этой диагностики» списком с описанием последствий (JetBrains Intention Actions).
21. **Инлайн-хинты настраиваются.** `lsp-inlay-hints.ts` есть; нет переключателя
    «типы / параметры / возвращаемые» через статусбар.
22. **Семантическая подсветка — поверх грамматики, а не вместо.** `semanticTokens` подключены;
    нужен слой приоритетов и откат на грамматику, когда сервер молчит (иначе файл «сереет»).
23. **Проверка орфографии — по серверу проекта.** Есть свой словарь (`main/spell`); нет
    использования LSP-сервера орфографии, если проект его объявляет.
24. **Диагностики — по проекту, не по файлу.** `project-diagnostics.ts` есть; нет сводки
    «сколько ошибок во всём проекте и где» с переходом из сводки.
