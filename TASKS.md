## Часть 1. Редактор

### Отмена и история

1. **Отмена переживает закрытие файла.** Закрыл вкладку (не приложение) и
   открыл снова — `Ctrl+Z` должен вернуть прежние правки. Сейчас история
   отмены живёт в контроллере и гибнет вместе с редактором.
   Источник: Neovim `undo.txt` (`:h undo-persistence`), VS Code
   `editingevolved`. Файлы: `editor/core/*undo*`, `ui/tabs.ts`.

2. **Точка последнего изменения.** Восстановленный буфер помечает место, до
   которого правки уже были — повторное открытие не отматывает в самое
   начало. Источник: Neovim `undo.txt`.

3. **Отмена по шагам, а не одним куском.** Две подряд вставки от агента — два
   `Ctrl+Z`, а не один; правка несколькими курсорами — один шаг, но не
   склеивается с соседними. Источник: VS Code `editingevolved`, Zed
   `editing-code`.

### Большие файлы и молчаливые пределы

4. **Долгая операция даёт признак жизни.** Открытие 50 МБ, поиск по 20 тыс.
   файлов, форматирование: строка прогресса и возможность отменить, а не
   «окно задумалось». Источник: Zed `development/ui-checklist` (Performance),
   JetBrains `progress-indicators`. Файлы: `editor/view/*`, `ui/search.ts`.

5. **Порог подсветки виден.** Файл без подсветки из-за размера говорит
   почему; есть кнопка «включить всё равно» с предупреждением. Источник:
   VS Code `editingevolved` (large file optimizations).

6. **Длинная строка не вешает редактор.** Несколько мегабайт в одной строке —
   прокрутка и курсор отзывчивы; горизонтальная прокрутка прижимается к слову.
   Источник: Zed `development/ui-checklist` (large files).

### Навигация внутри файла

7. **Структура документа вторым способом.** `Ctrl+Shift+O` открывает список
   символов, но нет постоянной панели структуры для текущего файла.
   Источник: Zed `outline-panel` (постоянное дерево символов, работает и в
   мультибуфере). Файлы: `ui/outline.ts` есть — нет места в раскладке.

8. **Иерархия вызовов: в обе стороны и с переносом корня.**
   `core/call-hierarchy.ts` есть; сверить с эталоном: переключение
   направления на лету, углубление выбором ребёнка, возврат к родителю,
   показ сочетаний в подвале, тот же список в контекстном меню редактора.
   Источник: Zed `finding-navigating` (Call Hierarchy).

9. **Переключатель вкладок по недавним.** `Ctrl+Tab` листает по порядку
   открытия, а не по недавнему использованию; удержание и повторное нажатие
   не циклит. Источник: Zed `tab-switcher`. Файлы: `ui/tabs.ts`.

10. **Вкладка-просмотр.** Одиночный клик в дереве открывает файл во вкладке,
    которая заменяется следующим одиночным кликом, — рабочий набор не
    засоряется. Источник: VS Code `custom-layout` (preview editors).

### Правка кода

11. **Сниппеты с табуляцией.** `shared/code-snippets.ts` есть — проверить
    переходы `Tab`/`Shift+Tab` по местам подстановки, выход за границу
    сниппета, отмену одним `Ctrl+Z`. Источник: Zed `snippets`,
    VS Code `editingevolved`.

12. **Быстрая правка рядом с ошибкой.** `shared/lsp-code-actions.ts` есть —
    нужна подача в редакторе: подчёркивание, лампочка, `Ctrl+.`, применение
    и повторное применение той же правки. Источник: Zed `diagnostics`,
    VS Code `editingevolved` (lightbulb, quick fix).

13. **`formatOnType` — либо работает, либо его нет в настройках.** В эталоне
    настройка есть, у нас ключа нет совсем; `formatOnPaste` работает. Либо
    реализовать и отменить одним `Ctrl+Z`, либо не обещать.
    Источник: VS Code `settings`, Zed `configuring-languages`.

14. **Форматирование сводится к одному пути.** Сейчас форматирует тот, кто
    первым ответил; нужен выбор из нескольких форматтеров и поведение
    «сохранить и отформатировать» одним действием. Источник: Zed
    `configuring-languages` (Formatting & Linting), VS Code `editingevolved`.

### Настройка не спорит с командой

15. **Одна настройка — один результат.** Если одна и та же настройка меняется
    из окна настроек, из палитры и из меню — результат один и тот же, и он
    виден в строке состояния. Источник: Zed `development/ui-checklist`
    (Consistency).

## Часть 2. Проводник

16. **Фильтр дерева — не только `includes`.** `matchesName` в
    `core/tree-filter.ts` знает одну подстроку. Нужно `?` (один символ),
    `*` (любая строка), пробел как разделитель слов и папка, видимая по
    детям. Источник: JetBrains `lists-and-trees` (Speed Search: wildcards,
    словаря в разных порядках), VS Code `ux-sidebars` (find в дереве).

17. **Фильтр не рвёт вложенность.** `file-nesting.ts` и `tree-filter.ts`
    живут отдельно: фильтр прячет родителя — спутники вложенного файла
    теряются. Источник: VS Code `explorer` (nested files + find).

18. **Дерево: полный набор клавиш.** Сверить с эталоном `↑/↓/←/→`,
    `Home/End`, `PageUp/Down`, `Enter` на папке (раскрыть, а не открыть),
    `Ctrl+Enter` на файле. Источник: JetBrains `lists-and-trees`
    (Keyboard: полная навигация без мыши), Zed `project-panel`.

19. **Строка-исключение.** «N файлов исключено» в хвосте дерева, клик —
    показать/скрыть, причина исключения видна без правки настроек.
    Источник: VS Code `ux-views` (collapsed items, настройки вида),
    JetBrains `lists-and-trees` (пустое состояние объясняет причину).

20. **Пустое место говорит, что делать.** Пустой проект, пустая папка,
    пропавший корень — три разных текста и три разных действия (создать
    файл, выбрать папку, заново открыть). Источник: JetBrains
    `lists-and-trees` (Empty state), Zed `development/ui-checklist`
    (unhappy path).

21. **`explorer.compactFolders`.** Склейка одиночных цепочек папок одной
    строкой; переключатель и поведение при фильтре и вложенности.
    Источник: VS Code `settings` (explorer.compactFolders).

22. **Порядок и группировка — матрица.** `foldersFirst`, `sort`,
    `groupByType`, `groupByPackage`, вложенность, скрытые: все комбинации
    и независимость от скорости чтения ФС. Источник: JetBrains
    `lists-and-trees` (сортировка и группировка), VS Code `settings`.

23. **Перетаскивание — одинаковое снаружи и изнутри.** `pathForFile` есть —
    проверить: бросок в файл и в собственного ребёнка запрещён с текстом,
    копирование/перемещение спрашивается всегда, иконка показывает
    результат до броска. Источник: JetBrains `lists-and-trees`
    (Drag and Drop: допустимые цели, копия/перемещение), Zed `project-panel`.

24. **Активная строка бледнеет, когда фокус ушёл.** Иначе два дерева
    (или дерево и палитра) показывают две «выбранные» строки и не понятно,
    куда уйдёт `Enter`. Источник: Zed `development/ui-checklist`
    (focus indicators), JetBrains `lists-and-trees`.

## Часть 3. Оболочка IDE

25. **Горячие клавиши открываемы.** Каждое действие в меню и в подсказке
    показывает своё сочетание; сочетание в подсказке кликабельно и ведёт
    в настройки клавиш. Источник: Zed `development/ui-checklist`
    (shortcuts discoverable), JetBrains `action-system`.

26. **Конфликт клавиш виден целиком.** `KeybindingService` умеет отложенное
    перебивание, но не говорит, какая команда победила и почему. Нужен
    экран конфликтов и кнопка «снять с пересечения». Источник:
    JetBrains `action-system` (Keymaps, конфликты), VS Code `keybindings`.

27. **Справочник сочетаний — из реестра.** Сейчас три источника: `MENU_COMBOS`,
    `DEFAULT_KEYBINDINGS` и `keybinding:` в `define`. Оттуда должны
    генериться меню, окно настроек и справка. Источник: JetBrains
    `action-system` (одно действие — одно описание), однозвучность с VS Code
    `default-keys`.

28. **Палитра — всё, что в реестре.** Для каждой команды из
    `src/renderer/core/*commands*.ts` проверить видимость в палитре;
    невидимая — либо в палитру, либо маркер `hidden` с причиной. Плюс
    группировка по категории и повтор последней. Источник: VS Code
    `ux-command-palette`, Zed `command-palette`.

29. **Выбор из списка — один механизм.** `Ctrl+Shift+O`, `Ctrl+T`, `Alt+F10`,
    палитра, фильтр дерева — сейчас разная нечёткость в четырёх местах.
    Один виджет с хостом-поставщиком; стрелки, `Enter` и `Ctrl+Enter`
    (рядом/в фоне), `Escape` с возвратом фокуса, сочетания в подвале.
    Источник: Zed `command-palette` (вторичное подтверждение),
    JetBrains `popups` , VS Code `ux-quick-picks`.

30. **Уведомление указывает, что изменилось.** Кнопка «Показать» ведёт
    туда, где проблема (файл, место, вид), а не просто закрывает тост.
    Источник: VS Code `ux-notifications`, JetBrains `notification-balloons`.

31. **Уведомление не отбирает ввод.** Тост над полем ввода не перехватывает
    щелчок и не сдвигает макет; живёт долго, пока не прочтут.
    Источник: JetBrains `notification-types` (toolwindow vs balloon),
    VS Code `ux-notifications`.

32. **Отмена — одна кнопка, а не диалог.** Действие с последствием
    (удаление, переименование, закрытие всех вкладок) даёт «Отменить» в
    уведомлении и в журнале, а не модальное подтверждение перед каждым шагом.
    Источник: VS Code `ux-notifications`, Zed `development/ui-checklist`
    (undo/redo действий).

33. **Контекстное меню: группы и подменю.** Только уместное здесь,
    длинное — в подменю, пункты с сочетанием, разделители по смыслу.
    Пройти дерево, редактор, вкладки, беседу, терминал, док. Источник:
    VS Code `ux-context-menus`, JetBrains `popups`.

34. **Строка состояния — из живого состояния.** Язык, кодировка, EOL,
    отступы, LSP — по активному редактору; клик по каждому — выбор
    (язык, кодировка, EOL), ни одного только для чтения. Источник:
    JetBrains `status-bar-widgets`, VS Code `ux-status-bar`.

35. **Макет на крайних значениях.** Окно уже минимальной ширины, вид у края,
    док справа — после перезапуска всё читаемо, ничего не наезжает.
    Источник: Zed `development/ui-checklist` (Responsiveness:
    narrow panes, short panes), VS Code `custom-layout`.

36. **Горячий выход и `kill -9`.** Незакоммиченные правки, вкладки,
    развёрнутость дерева, журнал беседы — восстановление целиком по
    одному признаку: приложение ведёт журнал до записи на диск.
    Источник: VS Code `custom-layout` (hot exit), Neovim `editing.txt`
    (`:mksession`).

37. **Всё без мыши.** Маршруты: панель → док → уведомление → журнал →
    палитра → настройки → дерево → беседа → поиск. Ни одного шага с мышью.
    Источник: Zed `development/ui-checklist` (usable without a mouse),
    VS Code `a11y`, JetBrains `lists-and-trees`.

38. **`role` и `aria` по шаблонам APG.** `treeview`, `tabs`, `dialog-modal`,
    `listbox`: фокус внутри диалога, возврат фокуса, живые регионы, стрелки
    в списках. Источник: VS Code `ux-accessibility`, Zed
    `development/ui-checklist` (Accessibility).

39. **Текст интерфейса по одному своду.** Кнопка — глагол, сообщение
    называет причину и что делать, ошибка не обвиняет человека, никакого
    жаргона. Источник: Microsoft `ms-writing-style`,
    JetBrains `how-to-write-guidelines`.

## Часть 4. Чат

40. **Параллельная задача — отдельное место работы.** Запустил вторую задачу,
    пока идёт первая, — две беседы работают одновременно и не путают
    контекст. Сейчас прогон один. Источник: Zed `ai/parallel-agents`
    (изоляция через worktree), VS Code `chat-overview` (agent sessions).
    Связано с задачей «субагенты».

41. **Ветка работы видна из чата.** Если задача идёт в изолированной
    ветке/каталоге, это написано в шапке задачи, и есть кнопка «применить
    к рабочему дереву». Источник: Zed `ai/parallel-agents`,
    `shared/git-worktrees.ts` уже есть.

42. **Разрешение инструмента — не бинарное.** По команде: разрешить один
    раз, на этот файл, на этот каталог, навсегда; список разрешённого
    виден и редактируется. Сейчас есть согласование карточки и правила,
    но нет гранулярности «только для этого пути». Источник: Zed
    `ai/tool-permissions`, VS Code `trust`.

43. **Шаги прогона можно прокрутить и раскрыть.** В ленте свёрнутая
    группа показывает, что делает агент, раскрытая — весь путь: правка,
    результат, откат. Сверить подачу с эталоном пошагового вида.
    Источник: Zed `ai/agent-panel`, VS Code `chat-overview`.

44. **Выбор контекста набирается в поле и виден до отправки.** `#имя`
    вставляет чип, чип можно убрать до отправки и после; без тегов
    контекст берётся по правилам, а не целиком. Сейчас в меню есть толь­ко
    `#` — навигация, чипов контекста нет. Источник: VS Code
    `copilot-context`, Zed `ai/agent-panel` (mentions).

45. **Сжатие истории показывает, что выброшено.** `/compact`, `/new`,
    `/fork` — каждое действие говорит, что попало в сводку.
    Источник: VS Code `copilot-context` (context window), Zed `ai/agents`.

46. **Инструкции проекта подхватываются и видны.** Файл инструкций проекта
    читается, в ленте видно, что он применён, при правке — перечитывается.
    Источник: VS Code `custom-instructions`, `cloud-instr` (у нас есть
    `main/ai/project-memory.ts` — сверить).

47. **Повтор — не дубль.** Событие стрима (`ChatStreamEvent`: `delta`,
    `reasoning`, `tool_start`, `tool_result`, `plan`, `goal`, `paused`,
    `step`, `interject`) при повторе после переподключения не дублирует ни
    текст, ни шаг, ни карточку подтверждения — тест на каждый вид.
    Источник: JetBrains `progress-indicators` (идемпотентность),
    VS Code `chat-overview`.

48. **Беседа и завершение прогона в одном месте.** Если прогон упал или
    прерван, в ленте видно почему и что осталось сделанным (файлы, коммиты,
    откат) — без чтения лога. Источник: Zed `ai/agent-panel`,
    `ai/threads`.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла и переезжает в README и в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
