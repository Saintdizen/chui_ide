# Задачи chui_ide

Пять областей: **Оболочка IDE**, **Проводник**, **Редактор**, **Чат**, **LSP и
подсказки**. Здесь — только открытые задачи: сделанное живёт в
`git log --follow -p TASKS.md`, а то, что оно умеет, — в README.

Номера сквозные (1..N) — на них ссылаемся в коммитах; пропуски в нумерации —
закрытые пункты. У каждого пункта назван источник, по которому он сверен:
страницы лежат в `.log/docs-2026-11-04/` (VS Code) и
`.log/docs-rivals-2026-11-04/` (Zed, JetBrains, Microsoft Writing Style,
Neovim).

Сверка 2026-11-06: Zed `Project Panel`, `Editing Code`, `Completions`,
`Diagnostics` (zed.dev/docs), LSP 3.17 spec, JetBrains `AI Assistant`.
Каждый пункт — дыра в НАШЕМ коде: сверено с `src/main/lsp/lsp.ts`,
`src/renderer/ui/*`, `src/renderer/editor/**`.

## Область 1. Оболочка IDE

### Доводка до зрелости

18. **Раскладка помнит себя.** Размеры, видимость и места стыков панелей
    восстанавливаются между запусками; закрытая панель остаётся закрытой, а
    «разложить по умолчанию» есть отдельной командой. Оболочка перестаёт
    начинать каждый запуск с чистого листа.
    Источник: VS Code `Custom Layout`, Zed `Workspace`.
19. **Палитра возвращает фокус на место.** После команды из палитры фокус
    возвращается туда, откуда её позвали, а не теряется в теле окна; `Esc`
    возвращает к исходному выделению, а не сбрасывает его.
    Источник: Zed `dispatch`, JetBrains `Quick Search`.
20. **Уведомление не исчезает из-под глаз.** Пока на подсказку смотрят мышью,
    отсчёт остановлен; у отказа есть «Куда смотреть» и «Повторить», а в списке
    уведомлений остаются и прочитанные — до перезапуска окна.
    Источник: VS Code `Notifications`, JetBrains `Notifications`.
21. **Статусная строка — вход в причину, а не картинка.** Каждый её элемент —
    кнопка: язык ведёт к выбору сервера, ветка — к изменениям, кодировка — к
    сохранению; указатель и `aria-label` называют действие заранее.
    Источник: VS Code `Status Bar`, Zed `Status Bar`.

## Область 2. Проводник

22. **Сворачивание не теряет место.** Свёрнутая папка помнит позицию при
    перерисовке и переименовании, а разворот не прокручивает список к началу:
    состояние дерева живёт отдельно от его отрисовки.
    Источник: VS Code `explorer`, Zed `Project Panel`.
23. **Перетаскивание говорит, куда упадёт.** Над строкой — линия вставки, над
    папкой — подсветка цели; неверная цель называет причину («нельзя папку в
    себя»), `Esc` отменяет перенос. Человек не должен узнавать о промахе
    после падения операции.
    Источник: VS Code `Drag and Drop`, JetBrains `Drag And Drop`.
24. **Несколько корней — равные.** Пакеты, шаблоны и примеры открываются
    рядом с основным без перезагрузки окна, а подпись пути — от своего корня,
    а не от первого в списке.
    Источник: VS Code `Multi-root Workspaces`, JetBrains `Attach Directory`.
25. **Фильтр дерева и «только изменённые».** Над деревом — поле «найти файл
    здесь» и переключатель «только изменённые»: оба работают по уже
    загруженному дереву и не перечитывают диск на каждый символ.
    Источник: VS Code `Explorer filter`, Zed `Project Panel`.

## Область 3. Редактор

26. **Строки сверху закрепляются.** Заголовок текущей функции/класса и
    объявление блока остаются видимыми при прокрутке (по данным языкового
    сервера), каждый — ссылкой к своему месту: длинный файл перестаёт терять
    контекст.
    Источник: VS Code `Sticky Scroll`, JetBrains `Breadcrumbs`.
27. **Найти и заменить умеет многое.** Многострочный запрос, история запросов
    (стрелки в поле), «только в выделении», замена с предпросмотром до
    подтверждения и сводка «3 из 148».
    Источник: VS Code `Find and Replace`, Zed `Search`.
28. **Правка одного — видна во всех.** Результат поиска раскрывается списком
    всех вхождений, и правка в любом месте списка правит все сразу, а не по
    файлу за раз.
    Источник: Zed `Multibuffer Editing`, JetBrains `Search Everywhere`.
29. **Длинные строки и отступы честные.** Мягкий перенос, направляющие
    отступов, табуляция по языку с уважением `.editorconfig` — всё
    переключается из статуса и живёт после перезапуска.
    Источник: VS Code `editor.*`, JetBrains `Code Style`.
30. **Сравнение не молчит.** Края сравнения скроллятся вместе, изменённые
    блоки связаны линией, стрелка переносит блок целиком; при конфликте —
    обе стороны с подписью «моя/чужая».
    Источник: VS Code `Diff Editor`, JetBrains `Merge Tool`.

## Область 4. Чат

31. **Ссылка на файл — сразу дело.** Имя файла в ответе открывается, а
    `файл:12` — сразу на строку 12; путь кликается одинаково в тексте, в
    списке правок и в плане.
    Источник: JetBrains `AI Assistant`, Cursor `@file:line`.
32. **Контекст виден и проверяем.** Над полем ввода — список того, что уйдёт
    в запрос (файлы, выделение, ошибки, терминал), с размером и кнопкой
    «убрать»: человек знает, что модель видит, до отправки.
    Источник: Cursor `@-context`, JetBrains `AI Context`.
33. **Своя задача — свой прогон.** Параллельная беседа работает в своём
    месте (ветка, рабочий каталог), остановка одной не трогает другую, а
    конфликт мест называется до старта, а не после него.
    Источник: Cursor `Parallel Agents`, Zed `Agent Panel`.
34. **Долгий ответ не подвешивает ввод.** Можно печатать следующее, пока идёт
    ответ, и ставить в очередь; `Стоп` останавливает и печать, и запущенные
    инструменты; «Повторить» даёт тот же запрос без набора.
    Источник: VS Code `Chat`, JetBrains `AI Chat`.
35. **Изменения от модели — списком и по одному.** Все правки прогона
    собраны в одном месте, каждая с «принять/отклонить» и сравнением, а
    отмена решения возвращает файл как был.
    Источник: Cursor `Review changes`, Zed `Agent: review edits`.

## Область 5. LSP и подсказки

36. **Сервер сам просит обновить пометки.** Подписка на
    `workspace/diagnostic/refresh`: правка настроек или файла вне редактора
    пересчитывает ошибки, а не ждёт следующего сохранения.
    Источник: LSP 3.17 `diagnostic/refresh`, VS Code `Diagnostic Provider`.
37. **Форматирование на лету.** `textDocument/onTypeFormatting`: закрыл
    скобку, поставил `;` — отступ и склейка проявляются сразу, если сервер
    это умеет, без ручного «форматировать документ».
    Источник: LSP 3.17 `onTypeFormatting`, JetBrains `Reformat on the fly`.
38. **Список серверов — с состоянием и умениями.** Видно не только
    «запущен/упал», но и что сервер умеет (подсказки, пометки, формат) и где
    его лог; при открытии файла незнакомого языка человек получает
    предложение поставить сервер.
    Источник: VS Code `language servers`, Neovim `:LspInfo`.
39. **Многосерверность не даёт слепого пятна.** Когда подсказки дают два
    сервера, объединение идёт без дублей, а у пометки виден источник (какой
    сервер сказал); выключение одного не убирает второго.
    Источник: Neovim `vim.lsp`, VS Code `Diagnostic source`.
40. **Подсказки не мешают печатать.** Пока набираешь, список не перебивает
    уже видимый и не дёргается под курсором: фильтрация — по введённому, при
    открытой скобке — подсказки по аргументам, `Tab`/`Enter` вставляют без
    лишнего символа, а подсказка без вставки отменяется одной клавишей.
    Источник: LSP 3.17 `completion`, JetBrains `Completion`, Zed
    `Completions`.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла; его история — в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
- Сквозная нумерация (1..N) сохраняется: новый пункт получает следующий номер
  в конце своей области; при переносе между областями номер обновляется по
  позиции, а не переиспользуется.
- Сначала чинить то, что ломает работу (потеря работы, зависание, слепой
  сервер), потом польза, последней — косметика.
