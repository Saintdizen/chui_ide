## Чат: вывод и отображение сообщений

План модернизации ленты. Порядок — как нумерованы пункты. Пункты 107–109
дают видимый эффект и не меняют протокол; 110–115 — по мере надобности.
Каждый пункт закрывается вместе с тестом, чтобы не кормить долг из №106.

### Как сейчас

- `renderer/ui/chat.ts` (~3400 строк) — монолит: лента, вкладки, поиск,
  экспорт, инспектор, действия. Рисование истории — `renderHistory`
  (с ~1302): сообщение — DOM-узел `div.msg.msg-<role>` с `div.msg-body`,
  разметка — `markdown.renderInto`.
- Модель сообщения уже существует: `ChatMessage` в `shared/api/ai.ts`
  (id, role, content, toolCalls, toolCallId, images). Плоская: текст и вызовы
  инструментов лежат рядом полями, а не частями; reasoning в `ChatMessage`
  нет — он живёт только в потоке.
- `chat-stream.ts` — `createStreamRunner`: склеивает стрим в текущий ход,
  `markdown.renderInto` дописывает текст, `scrollToEnd` держит низ.
- `chat-tools.ts` — карточки вызовов: `TOOL_LABELS`/`TOOL_ICONS`/
  `TOOL_ACTION_LABELS`, `MAX_REASONING_CHARS = 20_000`, reasoning в `<details>`.
- `chat-markdown.ts` — свой markdown, `createMarkdownRenderer({ openPath })`;
  стили — `renderer/styles/chat.css` (`.msg`, `.msg-body`, `.msg-error`,
  `.msg-activity`).
- `renderHistory` уже обрезает длинную сессию по ходам (`VISIBLE_TURNS = 20`,
  кнопка «развернуть»), но скрытые ходы всё равно строятся в DOM: обрезка
  визуальная, не по узлам.
- Поиск по сессии есть: `findMarks`/`revealFindMatch` ходят по живым узлам
  через `TreeWalker`. Действия на ответе есть: `attachAssistantActions`
  (копировать, повторить, обратная связь).
- Виртуализации ленты нет: все сообщения сессии живут в DOM до перерисовки.
- Доступности нет: ни `role="log"`, ни `aria-live` на ленте.
