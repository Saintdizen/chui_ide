## Структура (долгая правка, отдельной сессией)

Вне класса уже всё, что проверяется отдельно (`workspace-context.ts`,
`src/shared/read-coverage.ts`, `git/exec.ts`, `git/forge.ts`, `git/bisect.ts`,
`git/inspect.ts`, `git/status.ts`, `git/repository-watcher.ts`, `git/args.ts`, `git/diff-text.ts`, `git/apply.ts`, `git/locate.ts`, `git/file-text.ts`, `git/network.ts`, `git/stash.ts`, `git/worktree.ts`, `git/lfs.ts`, `git/sparse.ts`, `git/ssh-keys.ts`, `git/rebase.ts`, `git/submodules.ts`, `git/contexts.ts`, `git/git-context-source.ts`, `git/index-staging.ts`, `../tool.ts`).
Без повода не затевать: выигрыш здесь только в читаемости, скорость и поведение те же.

- [ ] **`src/main/git/git.ts` — 1 280 строк.** Распил идёт по одному узлу за
       сессию, методика та же, что на `agent-tools.ts`: grep частоты `this.X(` по
       блоку, брать узел с МАЛОЙ зависимостью от состояния класса. Вынесено так:
       `exec.ts` (запуск git и forge), `forge.ts` (413 строк — задачи, конвейеры,
       уведомления; `ForgeContext` из четырёх методов: `root`, `repositoryRoot`,
       `remotes`, `refresh`), `bisect.ts` (90 строк; `BisectContext` из трёх:
       `root`, `refresh`, `gitPath`), `inspect.ts` (61 строка — `headText`,
       `revert`, `reset`; `InspectContext` из трёх: `repositoryRoot`, `requireRoot`,
       `refresh`), `status.ts` (140 строк — разбор porcelain=v2, `repositoryMetaDir`,
       `writeLocalConfig`; ровно ноль обращений к состоянию класса, поэтому резалось
       без контекста вовсе).
       **Узел кончился, и это замерено.** Оставшиеся блоги (watcher, index/status,
       ветки, worktree, подмодули, личность и ключи) имеют 25–36 вызовов
       `this.repositoryRoot`/`this.requireRoot` на блок — это не узел с малой
       зависимостью, а сам класс. Дальше только вынос `GitService` целиком на
       составные сущности с явными зависимостями, то есть одна длинная правка на
       весь файл. По объёму она тоже ничего не даст: `inspect.ts` сократил git.ts
       на 0 строк (2010 → 2011) — выигрыш был в том, что правила легли в одно
       место, а не растворились в двух тысячах строк.

Повод — прогон CI дольше 2 минут (Windows-шаг «Тесты» сейчас ≈1м28с).

- [ ] **`tests/git-service.test.ts` — 6.1с, потолок замерен.** Ревизия сцен
       сделана: пять читающих сцен переведены на готовый снимок (`readOnlyRepo`),
       три сцены про `pull` — на один хелпер, у `makeRepos` появился хук
       `afterClone`. Итог — **было 6.14с, стало 6.47с, то есть хуже на 5%**
       (3 прогона до и после, сумма времени сцен по JSON-отчёту). Причина
       названа, а не угадана: `readOnlyRepo` делает КОПИЮ снимка (`clone
       --no-hardlinks`) ради изоляции, и копия стоит дороже того `init`+`clone`,
       которую заменяет. Трогать `readOnlyRepo` без нужды нельзя — он держит
       изоляцию сцен друг от друга. Режется только число сцен: 22 из 63 меняют
       состояние, 41 читают, и дублей по набору вызовов нет — каждая проверяет
       свой метод. Дальше только смысл тестов, не настройка.
