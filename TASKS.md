Список открытых дел. Пять срезов — Оболочка (IDE), Проводник, Редактор, Чат (агент),
LSP и подсказки. Внутри среза сначала дыры (пункты со сквозной нумерацией), потом
раздел «Проверено и найдено готовым — НЕ пункт»: то, что просит перечень любой
зрелой IDE, у нас уже есть. Сделанное отсюда снимается.

Источники сверки (собраны 07.11): JetBrains IDEA — `using-code-editor`, `editor-gutter`,
`intention-actions`, `local-history`, `search-everywhere`, `multiple-cursors-and-selection-ranges`,
`file-structure`; Zed — `editing-code`, `llms.txt`; VS Code — codebasics, editingevolved,
refactoring, intellisense, ai-powered-suggestions; плюс обзоры Sublime Text, Cursor,
Windsurf и Copilot. Сверка шла по коду: `grep` и чтение модуля, а не по памяти.

## 2. Проводник

### Открыто

7. **Действие — на любом узле.** Меню файла есть, но у папки нет одним списком
   «Открыть в терминале здесь», «Скопировать путь», «Найти в этой папке»; у корня
   нет «Обновить». У VS Code контекстное меню узла — полный набор, у нас — часть.
8. **Перетаскивание с переносом импортов.** Файл перетаскивается, но правка импортов
   после переноса (у VS Code это расширение, у JetBrains — Move refactoring) не выполняется.
   Пункт: перетащил `.ts` в другую папку — относительные импорты переписаны, undo — одной отменой.
9. **Фильтр дерева переживает переоткрытие.** Исключения проекта читаются
   (README, «Правила проекта и исключения»), но фильтр в дереве не запоминается.
10. **Поиск по проводнику.** Начни печатать поверх дерева — у VS Code это фильтр-набор,
    а Enter уходит в поиск по файлам. У нас такого совмещения нет.
11. **Свёрнутое дерево не схлопывается при обновлении корня.** Состояние раскрытия есть,
    но при обновлении корня дерево схлопывается — у JetBrains и VS Code сохраняется.

### Проверено и найдено готовым — НЕ пункт

- Дерево с ленивой загрузкой, иконки по типу и имени, отметки состояния git на узлах.
- Создание, переименование, удаление, копирование пути, «Открыть с помощью».
- Внешние изменения на диске видны (перечитывание файла, сторож изменений).
- Несколько корней, выход за корень с подтверждением, удалённые файлы через модалку.
- Группировка по типу, «показать скрытые», размеры и число файлов в папке.

## 3. Редактор

### Открыто

12. **Липкая строка области видимости.** `sticky` встречается только в свёртке; у VS Code
    и JetBrains при прокрутке сверху висит текущая функция/класс. Пункт: строка-заголовок
    области, клик — переход к её началу.
13. **Хлебные крошки над файлом.** Их нет (упоминание `breadcrumbs` в дереве — про проводник).
    У VS Code и JetBrains они показывают путь внутри файла и дают прыгать по уровням.
14. **Сворачивание «всё кроме этого».** Из трёх подпунктов свёртки был один — осталось
    «свернуть всё, кроме выбранного» и «свернуть подобранное по выделению».
15. **История правок файла.** Есть undo/redo, но нет Local History поверх сохранений:
    «что было в этом файле час назад», без git. У JetBrains это отдельная панель.
16. **Подсветка вхождений символа под кареткой.** `documentHighlight` у сервера спрашивается,
    но своя подсветка слова на месте в редакторе не включается — VS Code делает оба уровня.
    Пункт: своя подсветка плюс серверная поверх, разные цвета для чтения и записи.
17. **Выделение — по несколько сразу и по столбцу.** Мультикурсор есть, прямоугольного
    выделения (column selection, Alt+drag) нет; у JetBrains и Sublime есть.
18. **Вставка с историей буфера обмена.** Есть очистка вставки (`shared/paste-clean.ts`),
    нет журнала вставок (JetBrains: Ctrl+Shift+V) и «вставить без форматирования»
    отдельной командой.
19. **Шаблоны живого текста.** Есть вставка сниппетов и дополнение, но нет пользовательских
    живых шаблонов с переменными и обходом табуляцией (JetBrains Live Templates).
20. **Postfix-дополнение.** `if.` → `if (…)`, `.var` → переменная. У JetBrains это отдельный
    механизм поверх обычного дополнения; у нас нет.
21. **«Показать невидимое» переключается.** Пробелы, табуляция, переводы строк — команда
    есть местами; нужен переключатель в статусбаре и сохранение выбора.
22. **Сравнение с буфером обмена и с сохранённым.** Сравнение двух файлов и выделений есть;
    «сравнить с буфером» и «сравнить с диском» (у VS Code — в контексте вкладки) нет.

### Проверено и найдено готовым — НЕ пункт

- Правка одного — видна во всех (п.27 прошлого списка), многобуфер.
- Свёртка по уровню, блоки от сервера, свёртка из gutter, сторож свёрнутого.
- Правая колонка-обзор с метками ошибок и правок.
- Поиск с историей, замена в файле и по проекту, регулярные выражения, проверка regex.
- Сравнение двух файлов, с сохранённым в git, структурный поиск и замена.
- Мультикурсор, дополнение пар знаков, умный Enter, комментарии строчные и блочные, обёртка.
- Перемещение и дублирование строк, отступы, форматирование по серверу и по правилам проекта.
- Внутренние ссылки и переход по ним, цвета в файле, инлайн-значения отладчика.
- Настройки редактора: таб/пробелы, ширина, перевод строки, кодировка, автосохранение,

    кэша как намеренное свойство.
26. **Спилл-файлы большого вывода — под юнит и с уборкой.** `read` и `terminal` отдают через
    файл в `ai-spill/`; нужен тест на порог, на чтение диапазоном и на уборку старых

27. **Журнал шагов переживает перезапуск.** `session.trace` живёт в памяти чата; после

28. **Стоимость по модели и по дню.** `usageCost` считается по нити; нет сводки «сколько за

## Правила работы со списком

- Пункт закрывается тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на `tests/helpers/mini-dom.ts`.
- Перед пунктом — `grep`; после закрытия — снять его отсюда и дописать в
  список «найдено готовым», если по пути нашлось готовое.
- Ссылка на источник — в коммите и в журнале, а не в голове.
- Номера сквозные (1–36) и не переиспользуются: новый пункт получает номер
  следующим за последним.
