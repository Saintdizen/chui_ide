# Задачи chui_ide

Пять областей: **Оболочка IDE**, **Проводник**, **Редактор**, **Чат**, **LSP и
подсказки**. Здесь — только открытые задачи: сделанное живёт в
`git log --follow -p TASKS.md`, а то, что оно умеет, — в README.

Номера сквозные (1..N) — на них ссылаемся в коммитах; пропуски в нумерации —
закрытые пункты. У каждого пункта назван источник, по которому он сверен:
страницы лежат в `.log/docs-2026-11-04/` (VS Code) и
`.log/docs-rivals-2026-11-04/` (Zed, JetBrains, Microsoft Writing Style,
Neovim).

## Область 1. Оболочка IDE

### Без мыши и доступность

15. ~~**Всё без мыши.**~~ **ЗАКРЫТО** (коммит следом): три дыры было,
    все в одном месте — после открытия панели фокус оставался где был.
    (1) нижняя панель: `showAndFocus` вместо `show` для команд `Вид`;
    (2) дерево было недостижимо совсем (`tabindex=-1`, двери нет) — теперь
    `explorer.focus` на `Ctrl+Shift+E` и `focus()` в дереве;
    (3) у «Структуры» не было клавиши — `Ctrl+Shift+U` (`O`, `K`, `M` заняты).
    Вкладки дока — `role=tablist` с одним обходом Tab и стрелками по кругу.
    Тест `маршрут без мыши` в `command-descriptors` сторожит двери всех точек.
    Источник: Zed `development/ui-checklist` (usable without a mouse),
    VS Code `ux-accessibility`, JetBrains `lists-and-trees`.

16. **`role` и `aria` по шаблонам APG.** `treeview`, `tabs`, `dialog-modal`,
    `listbox`: фокус внутри диалога, возврат фокуса, живые регионы, стрелки в
    списках. Источник: VS Code `ux-accessibility`, Zed
    `development/ui-checklist` (Accessibility).

17. **Текст интерфейса по одному своду.** Кнопка — глагол, сообщение называет
    причину и что делать, ошибка не обвиняет человека, без жаргона.
    Источник: Microsoft `ms-writing-style`, JetBrains
    `how-to-write-guidelines`.

## Область 2. Проводник

### Фильтр и поиск по дереву

18. ~~**Фильтр «показать скрытые» и «только изменённые».**~~ **ЗАКРЫТО**
    (коммит 95bca8c): команда `explorer.toggleHidden` + пункт в контекстном
    меню пустого места (прятал не дерево, а настройка — значит, и показывать
    оттуда же); режим `onlyChanged` — кнопка-режим в шапке панели с
    `aria-pressed`, отбор в `matrixSections` (`changeOf` + `onlyChanged`).
    Папки режим не прячет: git о папках молчит, и судить их по себе — значит
    спрятать работу вместе с веткой.

### Клавиши и навигация

19. **Дерево: полный набор клавиш.** `↑/↓/←/→`, `Home/End`, `PageUp/Down`,
    `Enter` на папке (раскрыть, а не открыть), `Ctrl+Enter` на файле,
    `Shift+↑/↓` — выделение диапазона, буквенный переход по первой букве.
    Источник: JetBrains `lists-and-trees` (Keyboard), Zed `project-panel`.

20. ~~**Активная строка бледнеет, когда фокус ушёл.**~~ **ЗАКРЫТО** (коммит
    следом за п.19): класс `is-unfocused` на строках, пока `focusin/focusout`
    дерева говорят, что фокус не в нём; в `chrome.css` потухшая строка гаснет
    до `text_color_secondary` без фона, а наведение мышью её опять зажигает.
    Перерисовка — только окна строк, не всей панели.

### Клавиши и навигация — громкие точки входа

- `Enter` уже открывает файл, `Space` — смотрит без вкладки. Стоит ли
    разрешить `Ctrl+Enter` открывать вбок (split)? Пока не заведено.
- Буквенный переход по первой букве работает однажды и не показывает,
    что именно набрано. Отдельного окна с набором ещё нет.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла; его история — в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
- Сквозная нумерация (1..N) сохраняется: новый пункт получает следующий номер
  в конце своей области; при переносе между областями номер обновляется по
  позиции, а не переиспользуется.
- Сначала чинить то, что ломает работу (потеря работы, зависание, слепой
  сервер), потом польза, последней — косметика.
