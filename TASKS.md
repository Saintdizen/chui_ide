# Задачи chui_ide

Пять областей: **Оболочка IDE**, **Проводник**, **Редактор**, **Чат**, **LSP и
подсказки**. Здесь — только открытые задачи: сделанное переехало в README и в
`git log --follow -p TASKS.md`.

Номера сквозные (1..N) — на них ссылаемся в коммитах; пропуски в нумерации —
закрытые пункты. У каждого пункта назван источник, по которому он сверен:
страницы лежат в `.log/docs-2026-11-04/` (VS Code) и
`.log/docs-rivals-2026-11-04/` (Zed, JetBrains, Microsoft Writing Style,
Neovim).

---

## Область 1. Оболочка IDE

### Горячие клавиши и команды

1. **Горячие клавиши открываемы.** Каждое действие в меню и в подсказке
   показывает своё сочетание; сочетание в подсказке кликабельно и ведёт
   в настройки клавиш. Источник: Zed `development/ui-checklist`
   (shortcuts discoverable), JetBrains `action-system`.

2. **Конфликт клавиш виден целиком.** `KeybindingService` умеет отложенное
   перебивание, но не говорит, какая команда победила и почему. Нужен экран
   конфликтов и кнопка «снять с пересечения».
   Источник: JetBrains `action-system` (Keymaps), VS Code `default-keys`.

### Уведомления, меню, пустые состояния

8. **Отмена — одна кнопка, а не диалог.** Действие с последствием (удаление,
    переименование, закрытие всех вкладок) даёт «Отменить» в уведомлении и в
    журнале, а не модальное подтверждение перед каждым шагом.
    Источник: VS Code `ux-notifications`, Zed `development/ui-checklist`.

9. **Контекстное меню: группы и подменю.** Только уместное здесь, длинное —
    в подменю, пункты с сочетанием, разделители по смыслу. Пройти дерево,
    редактор, вкладки, беседу, терминал, док.
    Источник: VS Code `ux-context-menus`, JetBrains `popups`.

10. **Пустые состояния объясняют себя.** «Нет совпадений», «Файл не найден —
    создать?» — текст и действие, а не пустая панель. Проверить все списки:
    палитра, поиск по проекту, символы, проблемы.
    Источник: JetBrains `lists-and-trees` (Empty state), VS Code `ux-views`.

### Строка состояния и макет

11. **Строка состояния — из живого состояния и кликабельна.** Язык, кодировка,
    EOL, отступы, LSP — по активному редактору; клик по каждому — выбор (язык,
    кодировка, EOL, «перейти к строке»), ни одного только для чтения.
    Источник: JetBrains `status-bar-widgets`, VS Code `ux-status-bar`.

12. **Макет на крайних значениях.** Окно уже минимальной ширины, вид у края,
    док справа — после перезапуска всё читаемо, ничего не наезжает.
    Источник: Zed `development/ui-checklist` (Responsiveness), VS Code
    `custom-layout`.

13. **Раскладка помнит точный размер панелей.** Ширина/высота каждой панели
    переживает перезапуск и не «сбрасывается» при закрытии/открытии окна.
    Источник: JetBrains `tool-window`, VS Code `custom-layout`.

14. **Горячий выход и `kill -9`.** Незакоммиченные правки, вкладки,
    развёрнутость дерева, журнал беседы — восстановление целиком по одному
    признаку: приложение ведёт журнал до записи на диск.
    Источник: VS Code `custom-layout` (hot exit), Neovim `editing.txt`.

### Без мыши и доступность

15. **Всё без мыши.** Маршруты: панель → док → уведомление → журнал → палитра →
    настройки → дерево → беседа → поиск. Ни одного шага с мышью.
    Источник: Zed `development/ui-checklist` (usable without a mouse),
    VS Code `ux-accessibility`, JetBrains `lists-and-trees`.

16. **`role` и `aria` по шаблонам APG.** `treeview`, `tabs`, `dialog-modal`,
    `listbox`: фокус внутри диалога, возврат фокуса, живые регионы, стрелки в
    списках. Источник: VS Code `ux-accessibility`, Zed
    `development/ui-checklist` (Accessibility).

17. **Текст интерфейса по одному своду.** Кнопка — глагол, сообщение называет
    причину и что делать, ошибка не обвиняет человека, без жаргона.
    Источник: Microsoft `ms-writing-style`, JetBrains
    `how-to-write-guidelines`.

## Область 2. Проводник

### Фильтр и поиск по дереву

18. **Фильтр «показать скрытые» и «только изменённые».** Скрытые (точка в
    начале) и `files.exclude`, а также фильтр по git-статусу прямо в
    проводнике; скрытое можно показать, а не только спрятать.
    Источник: VS Code `explorer`, `settings`.

### Клавиши и навигация

19. **Дерево: полный набор клавиш.** `↑/↓/←/→`, `Home/End`, `PageUp/Down`,
    `Enter` на папке (раскрыть, а не открыть), `Ctrl+Enter` на файле,
    `Shift+↑/↓` — выделение диапазона, буквенный переход по первой букве.
    Источник: JetBrains `lists-and-trees` (Keyboard), Zed `project-panel`.

20. **Активная строка бледнеет, когда фокус ушёл.** Иначе два дерева (или
    дерево и палитра) показывают две «выбранные» строки и непонятно, куда
    уйдёт `Enter`. Источник: Zed `development/ui-checklist` (focus indicators),
    JetBrains `lists-and-trees`.

21. **Sticky-заголовок пути при прокрутке дерева.** Zed и JetBrains держат
    сверху путь к текущей папке, пока дерево прокручено. Редактор умеет
    (`sticky scroll`), дерево — нет; один и тот же чистый модуль пути.
    Источник: Zed `project-panel`, JetBrains `lists-and-trees`.

### Показ и сортировка

22. **Строка-исключение.** «N файлов исключено» в хвосте дерева, клик —
    показать/скрыть, причина исключения видна без правки настроек.
    Источник: VS Code `ux-views` (collapsed items), JetBrains
    `lists-and-trees` (пустое состояние объясняет причину).

23. **Пустое место говорит, что делать.** Пустой проект, пустая папка,
    пропавший корень — три разных текста и три разных действия (создать файл,
    выбрать папку, заново открыть).
    Источник: JetBrains `lists-and-trees` (Empty state), Zed
    `development/ui-checklist` (unhappy path).

24. **`explorer.compactFolders`.** Склейка одиночных цепочек папок одной
    строкой (`src/main/ai`); переключатель и поведение при фильтре и
    вложенности. Источник: VS Code `settings` (explorer.compactFolders).

25. **Порядок и группировка — матрица.** `foldersFirst`, `sort`, `groupByType`,
    `groupByPackage`, вложенность, скрытые: все комбинации и независимость от
    скорости чтения ФС. Источник: JetBrains `lists-and-trees` (сортировка и
    группировка), VS Code `settings`.

### Файловые операции

26. **Перетаскивание одинаково снаружи и изнутри.** `pathForFile` есть —
    проверить: бросок в файл и в собственного ребёнка запрещён с текстом,
    копирование/перемещение спрашивается всегда, иконка показывает результат
    до броска. Источник: JetBrains `lists-and-trees` (Drag and Drop),
    Zed `project-panel`.

27. **Несколько корней проекта.** VS Code workspaces, JetBrains Content Roots.
    Сейчас один корень. Оценить объём; если дорого — отложенное решение с
    обоснованием, а не молчание.
    Источник: VS Code `custom-layout`, JetBrains `tool-window`.

## Область 3. Редактор

### Отмена и история

28. **Точка последнего изменения.** Восстановленный буфер помечает место, до
    которого правки уже были — повторное открытие не отматывает в начало.
    Источник: Neovim `undo.txt`.

29. **Отмена по шагам, а не одним куском.** Две подряд вставки от агента — два
    `Ctrl+Z`; правка несколькими курсорами — один шаг, но не склеивается с
    соседними. Источник: VS Code `edit-evolved`, Zed `editing-code`.

### Большие файлы и молчаливые пределы

30. **Долгая операция даёт признак жизни.** Открытие 50 МБ, поиск по 20 тыс.
    файлов, форматирование: строка прогресса и возможность отменить, а не
    «окно задумалось». Источник: Zed `development/ui-checklist` (Performance),
    JetBrains `progress-indicators`.

## Область 4. Чат

### Параллельная работа

31. **У параллельной задачи свой рабочий каталог — сама.** Две беседы идут
    одновременно, но правят один каталог: мы предупреждаем и предлагаем увести
    задачу в ветку руками. Надо, чтобы вторая задача уходила в свой worktree без
    человека — тогда диффы не смешаются. Источник: Zed `ai/parallel-agents`.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла и переезжает в README и в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
- Сквозная нумерация (1..N) сохраняется: новый пункт получает следующий номер
  в конце своей области; при переносе между областями номер обновляется по
  позиции, а не переиспользуется.
- Сначала чинить то, что ломает работу (потеря работы, зависание, слепой
  сервер), потом польза, последней — косметика.
