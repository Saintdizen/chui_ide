## Правила

1. Перед пунктом — сверка с кодом.
2. Код и удаление пункта — один коммит.
3. Готовое удаляется сразу, без пометок.
4. Экономия без числа до и после не считается сделанной.
5. Пункт, оказавшийся готовым при сверке, удаляется тем же коммитом.

  за объём истории: полный prompt пересчитывается каждый шаг, кэш
  скидывает лишь его цену.
- Выводы инструментов дешёвые: read 17.3 М симв / 7 289 вызовов, terminal
  12.1 М / 12 913 (p50 531, p99 4 067, max 4 095 — границы обрезки не
  достигаются никогда), edit 3.3 М / 3 491.
- Шаг в среднем отдаёт 464 тк прироста истории, а первый шаг уже 34 630
  тк: стартовая история — сборка беседы, память проекта, схемы, замер

- Длинное — норма: медиана прогона agent 44 шага, 336 из 692 длиннее 45.
  Prompt на длинных прогонах растёт 37 243 → 54 684 тк к шагам 46-60:

79. terminal: обрезка головы (24 000 + 36 000) до потолка ответа — СДЕЛАНО,
    но экономии не дало: ни один вызов в 12 913 не дошёл до 6 000
    символов (max 4 095), граница не срабатывала. Теперь
    `HEAD_CHARS`+`TAIL_CHARS` = 18 000 и подача `headChars` в RunOptions;
    строка в замере — служит защитой, а не источником выигрыша.
    Осталось настоящее: повторный run той же команды в одном прогоне
    отдаёт «без изменений с шага N» вместо полного вывода. Число:
    символов на вызов в классе terminal.
80. edit — СДЕЛАНО, ждёт числа. Улика была не в эхе тела, а в
    односторонности: `condenseAppliedCalls` звался только на сообщение
    последнего хода, поэтому тело правки ходов 2 и старше оставалось
    целиком. Теперь `condenseHistoryCalls` проходит всю историю
    (идемпотентно, префикс не двигается). Замер по журналу: 2763 из 3491
    вызова `edit` >= 200 симв, 3.3 М символов — вот их теперь и не
    пересылаем. Осталось: процент свёрнутых тел по следующему журналу.
