# Что предстоит

Только открытые задачи. Сделанное живёт в README, тестах и в истории файла
(`git log --follow -p TASKS.md`).

Правило: пункт попадает сюда либо с воспроизведением, либо со ссылкой на строку
кода, либо с пометкой «проверить». Выдуманных дефектов здесь быть не должно.

Метод протокола ищется по всему `src`, а не в одном транспорте: клиентская половина
живёт в `lsp-features.ts`.

## Окружение

`web` даёт 404, `fetch` на `code.visualstudio.com` — «нет связи». Документация —
через `terminal`: `curl -sSL <url>.md` (HTML — SPA, отдаёт одну шапку).

## План

Порядок работы, сверху вниз. Без теста и `check:static` пункт не закрыт; «проверить»
сначала доводится до воспроизведения — или вычёркивается.

Сверка с документацией VS Code (`.log/vscode-docs-ideas-2026-11-02.md`, 328 статей)
дала части 7–12.

Второй проход (03.11) — не по документации, а по эталонам поведения: руководства
VS Code по интерфейсу (views, sidebars, notifications, quick picks, panel,
context menus, status bar, command palette), `custom-layout`, `accessibility`,
`chat-overview`/`chat-view`, плюс шаблоны WAI-ARIA APG (treeview, tabs, dialog,
listbox). Что было скачано — в «Источниках» в конце. Оттуда — части 13–15: три
места, где «работает» и «работает как эталон» — разные вещи.

Правило проверки в этих частях жёстче, чем в остальных: «не нашёл грепом» — не
довод об отсутствии. Пункт с пометкой «проверить» сначала доводится до
воспроизведения (скриншот, запись шагов, падающий тест), и только потом либо
чинится, либо вычёркивается.

Дешёвые прицепки, без порядка: всё, что в частях 13–14 помечено «проверить», — это
не задачи, а долг по проверке; каждый пункт дешевле закрыть до того, как браться
за следующий крупный кусок.

## Часть 13. Оболочка IDE

Эталон: UX-руководства VS Code + `custom-layout` + `accessibility`.

1. **Палитра команд — центр, а не место для редких команд.** В VS Code палитра открывается
   по центру сверху и показывает сначала недавнее, потом совпадения по словам запроса.
   Проверить: `palette.ts`, `quick-open.ts`, `core/quick-open-rank.ts` — недавнее
   учитывается при пустом запросе? «Пробел = И по словам» или подстрока? Что выше —
   недавнее или точное совпадение?
2. **Возврат фокуса — везде, а не только в модалках.** Модалки перехватывают Tab,
   закрываются по Escape и возвращают фокус (проверено). Осталось у попапов без
   модалки — палитра, `quick-open.ts`, `popup-menu.ts`, `lazy-popover.ts`,
   `context-menu.ts`: **вернуть фокус элементу, который их открыл**. Без этого
   мышь обязательна — а это уже дефект.
3. **Tab внутри модалки не уводит наружу.** По `accessibility` («tab trapping»): Tab
   ходит по кругу внутри модалки, Shift+Tab — назад, Escape — закрыть. Проверить
   `ui/modal.ts` на всех, кто его использует (их десятки — от `settings-modal.ts`
   до `rebase-modal.ts`); один экран с дырой — и «идеально» не будет.
4. **Масштаб: две ручки, а не одна.** `Ctrl`+колесо есть (`editor-input.ts` →
   `editor.fontSize`, тест `editor-wheel-zoom`). Осталось: `Ctrl`+`+`/`-`/`0` (ноль — сброс)
   и проверка, что уровень интерфейса (`ui-scale`) переживает перезапуск.
5. **Уведомления: один канал на одно событие.** `ui/toast.ts` + `ui/notifications-modal.ts`:
   одна и та же беда не должна всплывать и тостом, и в статус-баре, и в панели
   «Проблемы». Нужен общий реестр: уведомление имеет ключ, повтор поднимает старое,
   «не беспокоить» глушит группу, история живёт в модалке.
6. **Уважение к `prefers-reduced-motion` — везде.** Сейчас есть в `editor/view/editor-view.ts`,
   `theme.css`, `chrome.css`, `editor.css`. Проверить анимации вне этого списка:
   выезд панели (`ui/dock.ts`), попапы (`lazy-popover.ts`), тосты, стрим чата.
7. **Фокус виден на любом фоне.** Ни одна тема (включая High Contrast, если она есть
   в `theme-service`) не должна оставлять элемент без различимой обводки фокуса.
   Проверить: обойти Tab-ом всю оболочку, сфотографировать каждый шаг.
8. **Плотность и края панелей.** По `custom-layout`: панель перетаскивается между
   позициями, «свернуть всё», двойной щелчок по границе — сброс к умолчанию.
   У нас — `core/panel-layout.ts`, `ui/dock.ts`; проверить сохранение в сессии и
   поведение при схлопывании окна до минимума.
9. **Статус-бар как отражение, а не свалка.** По эталону элемент статус-бара —
   ссылка на действие. Проверить `ui/statusbar.ts`: каждый слот кликабелен и
   открывает то, о чём говорит; длинные пути и имена не разъезжают соседей
   (усечение с середины, полный путь — в подсказке).

10. **Выход из дзена по `Esc`.** Сам режим есть и работает (`view.zen`, `Alt+Z`,
    меню, панели/док/миникарта прячутся и возвращаются). По `custom-layout` из VS Code
    дзен закрывается `Esc` дважды — у нас только повторная команда (проверить). Второй
    `Esc` не должен выбивать из редактора: сначала ест модалка/попап/находка, потом
    дзен, и только потом обычный `Esc` редактора.

    СДЕЛАНО: `Esc` в дзене выходит (`bindInContext` — сочетание с условием `when()`,
    спрашивается раньше умолчаний). Очередь соблюдена: `handle` начинается с
    `if (event.defaultPrevented) return` — модалки и поиск ловят `Escape` в фазе
    ПЕРЕХВАТА и потому оказываются раньше, а съеденное нажатие не достаётся никому.
    Побочно исправлено: раньше `Esc`, съеденный окном, всё равно проваливался в
    умолчания — то есть закрывал окно И снимал мультикурсор заодно.
    ОСТАЛОСЬ: «дважды» — у нас закрывается одним нажатием. Это отличие от VS Code,
    а не поломка; менять — только если решим повторить их привычку.
11. **Один список горячих клавиш, из которого всё можно найти.** `core/keybindings.ts`
    + `core/default-keybindings.ts` — 60 строк на все команды; по `default-keybindings`
    VS Code ищет и по команде, и по клавише. Нужна таблица в настройках с поиском обоих
    видов и честным «конфликт: та же клавиша занята».

## Часть 14. Проводник

Эталон: WAI-ARIA APG (`treeview`) + UX-руководство `views` + поведение проводника VS Code.

1. **Дерево должно быть деревом и для скринридера.** Grep по `explorer.ts`:
   `role: 'tree'` нет ни разу (файл размечает только `tabindex: '-1'`). По APG нужны
   `role="tree"/"treeitem"`, `aria-level`, `aria-expanded`, `aria-selected`,
   `aria-setsize`/`aria-posinset` для больших списков. Нынешнее дерево для незрячего —
   куча div-ов без смысла.
2. **Клавиатура по APG целиком.** Проверить наличие и поведение: `↑`/`↓` (без
   раскрытия), `→` (раскрыть / внутрь), `←` (свернуть / к родителю),
   `Home`/`End`, `PageUp`/`PageDown`, `*` (раскрыть соседей), типизированный
   поиск по имени (`type-ahead`). Виртуализация в `core/tree-window.ts` не должна
   ломать «до конца списка» — сейчас неизвестно (проверить).
3. **Выделение и массовые действия.** `core/tree-selection.ts` знает Ctrl-точечное
   и Shift-диапазон. Дальше должно работать над ВСЕМ выделением, а не над первым:
   удалить, скопировать путь, переместить, перетащить. Проверить каждый пункт меню
   на выделении из трёх файлов.
4. **Копировать путь и относительный путь.** Grep `copyPath|copyRelativePath` — пусто
   в обоих рендерерах; по `context-menus` это первый по частоте пункт в проводнике.
   Добавить оба, с учётом корня первого проекта (у нас мультикорень — `workspace-model.ts`).
5. **Перетаскивание наружу и внутрь.** `dataTransfer` найден только в
   `image-view.ts`, `rebase-modal.ts`, `chat.ts`. Нужно: тянуть файл из дерева
   в терминал/на рабочий стол (путь текстом) и принимать файлы из ОС в папку
   (с подтверждением на перезапись).
6. **Склейка папок-цепочек.** `core/folder-chain.ts` есть — проверить крайние случаи:
   цепочка с закреплённым ребёнком (`tree-pins.ts`), цепочка с фильтром
   (`tree-filter.ts`), `a/b/c` при полностью раскрытой середине.
7. **Сортировка: папки вперёд, числа по-людски.** `core/tree-sort.ts` — проверить,
   что `file10` идёт после `file9` (natural sort, не по коду символа) и что
   регистр не решает порядок; фильтр не должен молча разворачивать всё дерево.
8. **Файловые ошибки говорят человеческим языком.** `core/file-notices.ts`,
   `core/file-actions.ts`: нет прав, файл занят, слишком длинное имя, папка
   исчезла между чтением и записью — на каждый случай свой текст и понятный
   выход, а не `EACCES`.
9. **Удаление отменяемо или честно неотменяемо.** `moveToTrash` кладёт в системную
   корзину — это хорошо. Нужно: сказать это в тосте («в корзину, вернуть оттуда»)
   и не обещать откат `Ctrl+Z` там, где его нет.
10. **Большие папки: цифры, а не ощущения.** Замерить открытие 50 000 файлов
    в одной папке: время до первого экрана, память, отзывчивость прокрутки.
    `tree-window.ts` — есть; потолок/ленивое чтение — проверить.
11. **«Где я сейчас».** Открыл файл из истории/поиска — дерево должно его
    подсветить и проскроллить к нему (autoReveal). Проверить с файлом, лежащим
    в свёрнутой ветке пятью уровнями глубже.

## Как это закрывается

Пункт считается закрытым, когда есть:

- **воспроизведение** — шаги, которые до правки давали неверное поведение
  (скриншот, запись, или падающий тест; для «проверить» — сначала именно он);
- **тест** — логика в `tests/`, поведение в `tests/dom/` рядом с соседями;
- **`npm run typecheck` и `npm run check:static`** без новых замечаний;
- **README** — если поведение видно человеку, абзац там, а не только в коммите.

Отдельно: идеальный интерфейс проверяется клавиатурой и диктором, а не только
мышью. Поэтому в каждой части есть пункт про `role`/`aria` и пункт про
путь без мыши — они не «на потом», а часть определения «работает».
