# Что предстоит

Только открытые задачи. Сделанное живёт в README, тестах и в истории файла
(`git log --follow -p TASKS.md`).

Правило: пункт попадает сюда либо с воспроизведением, либо со ссылкой на строку
кода, либо с пометкой «проверить». Выдуманных дефектов здесь быть не должно.

Метод протокола ищется по всему `src`, а не в одном транспорте: клиентская половина
живёт в `lsp-features.ts`.

## Окружение

`web` даёт 404, `fetch` на `code.visualstudio.com` — «нет связи». Документация —
через `terminal`: `curl -sSL <url>.md` (HTML — SPA, отдаёт одну шапку).

## План

Порядок работы, сверху вниз. Без теста и `check:static` пункт не закрыт; «проверить»
сначала доводится до воспроизведения — или вычёркивается.

Сверка с документацией VS Code (`.log/vscode-docs-ideas-2026-11-02.md`, 328 статей)
дала части 7–12.

Дешёвые прицепки, без порядка: часть 8, п. 2–4 и часть 7.

## Часть 1. LSP

1. **`textDocument/semanticTokens/range`** — подсветка видимого куска вместо всего
   файла; на больших файлах заметно.
2. **`textDocument/semanticTokens/full/delta`** — правка на символ перекрашивает
   весь файл.
3. **`textDocument/willSaveWaitUntil`** — форматирование перед сохранением
   (`editor.formatOnSave`); одного `willSave` мало.
4. **`resolve` у codeAction / codeLens / documentLink / inlayHint.** Сейчас есть
   только у `completionItem` и `workspaceSymbol`; остальные теряют заголовки и
   команды. Звать, если сервер объявил `resolveProvider`.
5. **Pull-диагностика** (`textDocument/diagnostic`, `workspace/diagnostic`). Живём
   на push-модели и так её и объявляем — но на больших проектах push дороже. Нужен
   кэш, `resultId`, отмена.
6. **`didSave` не открытых в редакторе файлов:** сохранение через файловый менеджер
   тоже стоит сообщать серверу.

## Часть 2. IDE

1. **Нет `Ctrl+Tab` по порядку использования.** VS Code держит MRU отдельно от
   порядка вкладок; нужно то же, и переживающее перезапуск.
2. **Состояние окна восстанавливается неточно.** Раскладка панелей пишется, а скролл,
   курсор и свёрнутые папки нет: после перезапуска файл на первой строке.
3. **Множественный выбор в дереве не переживает перерисовку.** Выделение в
   `explorer.ts` есть, но обновление дерева (сохранение, git-статус) сбрасывает его
   на один файл.
4. **Нет блока «открытые редакторы» над деревом.** VS Code показывает его первым,
   и там же видны несохранённые.
5. **Настройки не показывают неправильные значения:** поле с мусором рисуется
   пустым вместо «ожидалось число».
6. **Нет файловых ассоциаций** (`files.associations`): расширение без языка остаётся
   без подсветки, хотя сервер для языка может быть.

## Часть 3. Проводник

1. **Перетаскивание не описано правилом.** Перенос в папку должен спрашивать при
   несохранённых правках и переносить файл вместе с историей.
2. **Нет сравнения двух файлов из дерева.** `diff-view` и `folder-compare-modal`
   есть, но зовутся только из SCM.
3. **Цепочки папок без файлов** (`a/b/c`) не сворачиваются в одну строку.
4. **Проверить:** имена с `a:b`, `/` и пустые, отклик на больших каталогах
   (`node_modules`) — не воспроизводил.

## Часть 4. Редактор

1. **Пункт меню недоступен только «по факту»:** состав меню уже зависит от места
   (`core/editor-menu.ts`: место клика, `hasSelection`, `Go to Definition` / `Peek` /
   `Rename (F2)`). Остаток: `canUndo`/`canRedo` из снимка не читаются — нужен
   серый пункт в `PopupMenuItem`, а поля `enabled` там нет.

## Часть 5. Чат

1. **Сумма контекста без расхода:** меню вложения растёт (#diff, #codebase, #symbols…),
   а бюджет хода — общий на всё.

## Часть 6. Git — по `sourcecontrol/*`

1. **«Принять оба» ломает `+=`:** наложившиеся правки склеиваются как «наше, затем
   их», и `a += 1`/`a += 2` даёт `a += 1a += 2`. Нужен порядок по смыслу, не по стороне.
2. **Пере-слияние:** снял конфликт — файл больше не сливается повторно, смотреть
   результат нечем.

## Часть 7. Агент как среда

1. **Хуки агента** (`agents/reference/hooks-reference`): пользовательская проверка
   поверх `tool-policy.ts`: скрипт решает, пускать ли действие, или дописывает
   результат. Нужны две точки вызова (до/после инструмента) и запуск скрипта из
   проекта. Ценно для «не пускать `rm -rf`, `git push`» — на уровне репозитория.
2. **Заготовки промптов** (`*.prompt.md` с `${input}`): `CONTEXT_COMMANDS` даёт
   данные (`#codebase`, `#diff`), заготовка даёт *задание*. Формат близок к
   `chat-markdown.ts`.
3. **Артефакты прогона:** `agent-present.ts` объявляет файл карточкой в ленте —
   но постоянного места у него нет. Дать артефактам панель рядом с редактором.
4. **Субагенты** (`agents/run/subagents`): вложенный прогон с отдельным контекстом
   и своим набором инструментов. `runTool` один и однопоточный. Цена — токены
   удваиваются, нужен жёсткий лимит глубины. Брать, когда упрётся: «поищи по всему
   проекту и не забивай контекст». Следом — skills (инструкция + скрипты,
   подгружаемые по надобности).
5. **Автоматизации** (`agents/run/automations`): запуск задачи по событию
   (расписание, изменение файла). Почти `jobs.ts`, не приоритет.

## Часть 8. Совместимость с чужими репозиториями

1. **`tasks.json`** (`debugtest/tasks`): `src/main/node/{lint,format,tests}.ts`
   зашиты под наш проект. Чтение `tasks.json` VS Code даёт сборку/линт из
   любого репозитория — и заодно ставит точку роста: описание задач вместо
   захардкоженных функций.
2. **Скриншоты из браузера:** инструмент `browser` есть, снимок страницы — малая
   работа.
3. **Файл сниппетов `*.code-snippets`** (`editing/userdefinedsnippets`): свои
   сниппеты у нас есть полем `editor.snippets` (`settings-modal.ts:1241`). Не хватает
   файла: тогда сниппеты едут с проектом и ревьюятся как код. Формат совместим с
   VS Code: `~/.chui_ide/snippets/*.code-snippets` и `.vscode/*.code-snippets`
   в проекте.
4. **`launch.json`** (`debugtest/debugging-configuration`): конфигурации отладки
   живут в нашем формате — чужой репозиторий своих не принесёт. Чтение `launch.json`
   даёт запуск «как в VS Code» без ручной перенастройки. Начать с одной модели
   конфигурации, наш формат — её частный случай.

| Локализация UI | Механизм прост, но переводить весь интерфейс — работа большая, ценность внешняя |
