# Что предстоит

Только открытые задачи. Сделанное живёт в README, тестах и в истории файла
(`git log --follow -p TASKS.md`).

Правило: пункт попадает сюда либо с воспроизведением, либо со ссылкой на строку
кода, либо с пометкой «проверить». Выдуманных дефектов здесь быть не должно.

Метод протокола ищется по всему `src`, а не в одном транспорте: клиентская половина
живёт в `lsp-features.ts`.

## Окружение

`web` даёт 404, `fetch` на `code.visualstudio.com` — «нет связи». Документация —
через `terminal`: `curl -sSL <url>.md` (HTML — SPA, отдаёт одну шапку).

## План

Порядок работы, сверху вниз. Без теста и `check:static` пункт не закрыт; «проверить»
сначала доводится до воспроизведения — или вычёркивается.

Сверка с документацией VS Code (`.log/vscode-docs-ideas-2026-11-02.md`, 328 статей)
дала части 7–12.

Дешёвые прицепки, без порядка: часть 8, п. 2–4 и часть 7.

## Часть 2. IDE

Закрыто и снято: состояние окна (верх экрана, каретка, свёрнутые папки), множество в дереве,
блок открытых редакторов, числа в настройках, свои языки файлов.

## Часть 7. Агент как среда

1. **Хуки агента** (`agents/reference/hooks-reference`): пользовательская проверка
   поверх `tool-policy.ts`: скрипт решает, пускать ли действие, или дописывает
   результат. Нужны две точки вызова (до/после инструмента) и запуск скрипта из
   проекта. Ценно для «не пускать `rm -rf`, `git push`» — на уровне репозитория.
2. **Заготовки промптов** (`*.prompt.md` с `${input}`): `CONTEXT_COMMANDS` даёт
   данные (`#codebase`, `#diff`), заготовка даёт *задание*. Формат близок к
   `chat-markdown.ts`.
3. **Артефакты прогона:** `agent-present.ts` объявляет файл карточкой в ленте —
   но постоянного места у него нет. Дать артефактам панель рядом с редактором.
4. **Субагенты** (`agents/run/subagents`): вложенный прогон с отдельным контекстом
   и своим набором инструментов. `runTool` один и однопоточный. Цена — токены
   удваиваются, нужен жёсткий лимит глубины. Брать, когда упрётся: «поищи по всему
   проекту и не забивай контекст». Следом — skills (инструкция + скрипты,
   подгружаемые по надобности).
5. **Автоматизации** (`agents/run/automations`): запуск задачи по событию
   (расписание, изменение файла). Почти `jobs.ts`, не приоритет.

## Что отброшено осознанно

Не повторять эти предложения при следующем разборе документации:

| Идея из VS Code | У нас |
|---|---|
| Правила проекта файлом (`AGENTS.md`) | Уже есть — `workspace-context.ts:22`, `INSTRUCTION_FILES` |
| Staging по hunk'ам в gutter | Уже есть — `stageHunk`/`discardHunk` + меню полоски, разворачивание блоков — в попапе изменений чата |
| `tasks.json` как *формат задач* | Отложено в часть 8 (нужен лишь для чужих репо) |
| Skills / custom-agents / prompt-files | Сведено в часть 7, п. 2 и п. 4: отдельно от субагентов не живёт |
| Синхронизация настроек | `.chui_ide` и так переживает перезапуск; между машинами — чужой сервис |
| Профили | Ниже приоритет: воркспейсы уже несут конфиг |
| Локализация UI | Механизм прост, но переводить весь интерфейс — работа большая, ценность внешняя |
| Голос | Нужен внешний STT, проверять отдельно |
