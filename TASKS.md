## Структура (долгая правка, отдельной сессией)

Вне класса уже всё, что проверяется отдельно (`workspace-context.ts`,
`src/shared/read-coverage.ts`, `git/exec.ts`, `git/forge.ts`). Без повода
не затевать: выигрыш здесь только в читаемости, скорость и поведение те же.

- [ ] **`src/main/git/git.ts` — 2 042 строки, 116 методов.** Распил идёт по одному
       узлу за сессию, методика та же, что на `agent-tools.ts`: grep частоты
       `this.X(` по блоку, брать узел с МАЛОЙ зависимостью от состояния класса.
       Сделано так: `exec.ts` (запуск git и forge), `forge.ts` (413 строк — задачи,
       конвейеры, уведомления; класс зовёт его через `ForgeContext` из четырёх
       методов: `root`, `repositoryRoot`, `remotes`, `refresh`). Остальные блоги
       так не отрезаются — у них 25–36 вызовов `this.repositoryRoot`/`this.requireRoot`
       на блок, то есть каждый тянет состояние класса. Дальше только вынос
       `GitService` целиком на составные сущности (watcher, index/status, ветки,
       bisect, worktree, подмодули, личность и ключи) с явными зависимостями.

## Скорость (ждёт повода)

сейчас ≈1м28с). Оставшееся режется только числом сцен в
`tests/git-service.test.ts` (7.2с на Linux, 72.5с на Windows, 63 сцены по 5–15
git-вызовов) — то есть смыслом тестов, а не настройкой.
