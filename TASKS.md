## Правила, добытые ценой (не задачи)

- **Одно окружение на несколько проектов — это конфликт версий, который pip не считает ошибкой.**
  `pip install -r requirements.txt` разрешает только свою графу: `pytest-cov`, поставленный
  пресетом, в ней нет — и pip молча понизил `pluggy` до 0.13.1 (в выводе лишь «resolver does
  not currently take into account all the packages that are installed»), после чего pytest-cov 7
  падал на загрузке `TypeError: __call__() got an unexpected keyword argument 'wrapper'`.
  Поэтому `python.createVenv` по умолчанию **чистое** окружение (`clean: true` в
  `CreateVenvOptions`, `src/main/python/environments.ts` пропускает и пресет, и requirements;
  галочка в `src/renderer/ui/venv-modal.ts`). Ставить пакеты — решение человека, не побочный
  эффект создания venv. Не сделано: `pip check` после установки.

- **Порог покрытия — только там, где тесты доехали.** Глобальный процент
  считается по всем тестам, а часть их на Windows снимается: заглушки
  git/rg/lsp — POSIX-скрипты (`stubSupported = process.platform !== 'win32'`
  в `tests/*.ts` + `tests/ripgrep-stub.ts`; `rg` без расширения и `rg.cmd`
  спавн без оболочки не находит — PATHEXT). Прогон на Windows даёт
  ~80.75/75.06/78.63/83.54 при порогах 81/75/78/84: падают statements и lines.
  Настоящая причина — меньше тестов доехало, а не хуже код.
  Поэтому `npm run check` (с порогами) — только Linux (`runner.os == 'Linux'`
  в `release.yml`), на Windows и macOS — `check:static` + `npm test`.
  Приёмка — по прогонам 40658435010 / 40659787113 / 40660644089: Windows
  падал три тега подряд в шаге «Проверить код», macOS и Linux — нет.
  Настоящее лекарство — заглушки в процессе (`vi.mock`, как у `pip`), а не
  скрипты: тогда тесты пойдут всюду и порог снова можно включить на всех ОС.

- **Без повода не затевать распил ради читаемости.** Выигрыш — только в
  читаемости, скорость и поведение те же.
- **Выродившаяся обёртка — это забытая обёртка, а не «шов на будущее».** Если
  у `private xxxCtx()` тело стало `return this.gitContext()` — удалять, а не
  сужать.
- **Перед выносом метода проверить, не вынесен ли он уже:**
  `grep -rn "export async function ИМЯ" src/main/git/`. В классе может
  остаться стрелка в одну строку.
- **Мерить, ГДЕ лишнее, до того как чинить названный файл.** Пункт может
  называть `contexts.ts`, а виноваты два `extends` на месте.
- **Целый файл — не «дорого», а «дешевле шага»: порог `whole-read` не спускать.**
  Замер по `counts.jsonl` (167 прогонов, 29.10): `whole-read` — 214 вызовов,
  средний 3185 символов, медиана 4019, p90 4062; а лишний шаг — ≈ 7к токенов
  (≈ 28к символов). Значит целое чтение дешевле второго шага примерно в семь раз,
  и `WHOLE_FILE_MAX_LINES = 160` в `src/main/ai/agent-read.ts` заведомо ниже
  точки безразличия: спуск порога добавит шагов больше, чем сэкономит. Повод
  пересмотреть — только новый замер `npm run usage` (`scripts/agent-usage.ts`),
  где p90 `whole-read` подберётся к 28к символов.
- **Потолки вывода инструментов менять только по жалобе модели на обрезку.**
  Шаг 1 сделан, цифры выверены тестом `tool-output-budget.test.ts`.
- **Молчание виджета читается как «всё чисто».** Если проверка не состоялась
  (нет линтера, отказ, повисший процесс), ноль показывать нельзя — вместо
  числа слова «не проверено» и причина в подсказке. Пустой список без
  причины — такая же ложь, как и выдуманная пометка. Вид виджета решает
  чистая функция в `ui/problems-widget.ts`, тест — `problems-widget.test.ts`.
- **На полосе прогресса число — это шаги, а не проценты работы.** Середину
  шага не знает никто: линтер и tsc — один процесс и молчат до конца. Где
  делить нечего (tsc), чисел нет вообще — бежит штрих. Вид решает чистая
  функция `ui/check-progress.ts`, тест — `check-progress.test.ts`.
- **Не знаешь середины — не рисуй процент.** В строке состояния одна общая
  полоса `.status-meter` на три работы: `$/progress` сервера (процент даёт сам
  сервер), чтение проекта (числа — файлы) и проверка проекта (числа — этапы).
  Где числа нет (tsc, сервер молчит) — бегущий штрих, а не 0%.
- **Три полосы рядом читаются как поломка.** Пока виджетов было три, две обычно
  стояли на нуле, дожидаясь своей очереди, — и «читаю проект: 0 из 0» выглядело
  как зависание. Очередь старшинства (сервер → чтение проекта → проверка) и
  выбор вида решает чистый модуль `ui/status-meter.ts`, тест —
  `tests/status-meter.test.ts`. Штамп «0 из 0» не печатается ни при каких
  данных: у `progress.total === 0` в `shared/symbol-index.ts` числа снимаются
  совсем (`symbol-index.test.ts`).
- **Сервер молчит не потому, что нечего сказать, а потому, что его не спросили
  по протоколу.** Диагностика в LSP включается объявлением
  `capabilities.textDocument.publishDiagnostics` в `initialize`:
  `typescript-language-server` без него не публикует ничего — ни для
  открытого файла, ни для обхода. Проверять поведение сервера живым
  процессом, а не по документации: обе стороны держит
  `tests/lsp-diagnostics-sweep.test.ts` (заглушка, как tsserver, публикует
  только при объявленной capability и отвечает на `didClose` пустым
  списком — а обход такое эхо не считает «стало чисто»).
- **Запустил процесс — сумей убить.** Внешний инструмент, которого зовут без
  `AbortSignal`, переживает свой вызов: после «не успели» он держит каталог
  проекта (на Windows — `EBUSY` при уборке temp-папки), греет процессор и
  может писать файлы. Запуск у нас один — `src/main/project/tool-run.ts`, тест —
  `tests/tool-run.test.ts`; новые вызовы — только через него.
- **Пути сравнивать в одном виде.** Внешние инструменты отдают их по-разному
  (eslint — абсолютными, на Windows через `C:/`; biome и ruff — относительными
  через `/`). Склеивать — только через `shared/paths.ts` (`isAbsolutePath`,
  `withSeparator`), иначе путь линтера не совпадёт ни с одним файлом проекта и
  клик по пометке упирается в «файл не найден». Случаи в тесте — из CI на Windows: `tests/project-analysis.test.ts`.

- **`fs.watch` не обещает доставку — тест не вправе требовать одной правки.**
  На macOS (FSEvents) событие для записи через миллисекунды после установки
  наблюдения теряется, на загруженном раннере наблюдение к тому же успевает
  пересоздаваться (`WATCH_RETRY_MS`). Одиночная запись давала «no event in time»
  при здоровом сервисе (CI 27.10). Ждать через `tests/watch-wait.ts`
  (`untilEdit`): перезапись тем же содержимым, пока наблюдатель не ответит.
  Путь один и тот же → `pendingCount` не растёт, проверки остаются строгими,
  а мёртвый наблюдатель по-прежнему валит тест (проверено отключением
  `startWatcher` — падают 5 тестов с «правка не дошла»).

- **Высота всплывашки — по нарисованному прямоугольнику, а не по `scrollHeight`.**
  У списка `scrollHeight` потолком `max-height` не режется: у длинного набора он
  равен высоте ВСЕХ строк (в живой ИДЕ — 1000 при видимых 210). С такой "высотой"
  попап не влезал ни вниз, ни вверх и прижимался к верхнему краю окна — при том что
  якорь был верный, а каретка — посреди экрана (жалоба 28.10). Мера —
  `this.root.getBoundingClientRect().height`, а без раскладки (jsdom) — расчёт по
  строкам: `src/renderer/editor/widgets/suggest-widget.ts`, тест —
  `tests/suggest-widget-position.test.ts`.
- **Попап не на месте — сперва проверить меру, а не якорь.** В том же баге якорь
  совпадал с нарисованной кареткой бит в бит (проверено в живом Chromium:
  `npm run probe:suggestplace`, отчёт — `.chui_ide/probe-suggest-place.txt`).
  Юнит-тесты верят переданному якорю, поэтому "попап уехал" они не видят.

- **Акселератор меню ловит клавишу только пока фокус в нашем документе.**
  Страница встроенного браузера (`WebContentsView`) и открытый диалог забирают
  нажатие себе — палитра команд «то открывается, то нет» (жалоба 28.10). Поэтому
  у одной команды три пути, и лишнего среди них нет: акселератор меню, сочетание в
  `DEFAULT_KEYBINDINGS` (срабатывает там, где меню промолчало: нажатие, съеденное
  меню, до renderer не доходит) и `before-input-event` гостевой страницы
  (`src/main/browser/panel.ts`, там же `event.preventDefault()`, иначе страница
  тоже получит клавишу). Второй способ позвать палитру — двойное нажатие `Shift`
  (`core/double-shift.ts`): считается только «чистое» нажатие, иначе Shift при
  наборе заглавных открывал бы палитру посреди слова, тест —
  `tests/double-shift.test.ts`.

## Правило новое (27.10): `noUncheckedIndexedAccess`

Флаг включён в `tsconfig.json` (было 207 ошибок, стало 0). Разбор нового
`Object is possibly 'undefined'`: если индекс уже проверен выше в том же
теле (`i < arr.length`, `findIndex`/`indexOf` >= 0, группа regex после
`match !== null`) — ставить `!`; если проверки нет или значение бывает
пустым — `?? fallback`. Не писать `a?.b[0]!.c` (biome ловит
`noNonNullAssertedOptionalChain`) — вместо этого `a?.b[0]?.c`.
`exactOptionalPropertyTypes` замерен (67 main + 65 renderer = 132), не включали.
