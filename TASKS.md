# Задачи chui_ide

Пять областей: **Оболочка IDE**, **Проводник**, **Редактор**, **Чат**, **LSP и
подсказки**. Здесь — только открытые задачи: сделанное живёт в
`git log --follow -p TASKS.md`, а то, что оно умеет, — в README.

Номера сквозные (1..N) — на них ссылаемся в коммитах; пропуски в нумерации —
закрытые пункты. У каждого пункта назван источник, по которому он сверен:
страницы лежат в `.log/docs-2026-11-04/` (VS Code) и
`.log/docs-rivals-2026-11-04/` (Zed, JetBrains, Microsoft Writing Style,
Neovim).

Сверка 2026-11-06 (вторая, ужесточённая): сначала смотрел, что в коде
ЕСТЬ, и только потом писал пункт. Первый заход этой не выдержал: из 23
пунктов пять отпали сразу — раскладка (`ui/layout.ts` + `persistLayout`),

## Область 1. Оболочка IDE

19. **Палитра возвращает фокус на место.** После команды из палитры фокус
    возвращается туда, откуда её позвали, а не теряется в теле окна; `Esc`
    возвращает к исходному выделению, а не сбрасывает его.
    Источник: Zed `dispatch`, JetBrains `Quick Search`.
20. **Уведомление не теряет нить.** Пауза при наведении есть, но «Куда
    смотреть», «Повторить» и список прочитанных у нас есть только до
    перезапуска — после него смерть сервера не объяснена. Пункт — про
    список с причиной и действием, а не про паузу.
    Источник: VS Code `Notifications`, JetBrains `Notifications`.
21. **Статусная строка — вход в причину.** Каждый её элемент — кнопка
    (язык → выбор сервера, ветка → изменения, кодировка → сохранение) с
    `aria-label`; проверить каждый и добить те, что остались картинками.
    Источник: VS Code `Status Bar`, Zed `Status Bar`.

## Область 2. Проводник

22. **Сворачивание не теряет место.** Свёрнутая папка помнит позицию при
    перерисовке и переименовании, а разворот не прокручивает список к началу.
    Источник: VS Code `explorer`, Zed `Project Panel`.
23. **Перетаскивание говорит, куда упадёт.** Линия вставки между строками и
    подсветка папки-цели; `Esc` отменяет перенос, неверная цель называет
    причину. Перетаскивание есть, а «куда» человек узнаёт после падения.
    Источник: VS Code `Drag and Drop`, JetBrains `Drag And Drop`.
24. **Несколько корней — равные.** Добавление есть; проверить подпись пути от
    своего корня (а не от первого) и переживание перезагрузки окна.
    Источник: VS Code `Multi-root Workspaces`, JetBrains `Attach Directory`.
25. **Фильтр дерева — с «только изменённые».** Фильтр есть
    (`core/tree-filter.ts`), а переключателя «показывать только изменённые»
    (по данным git) нет: в живом проекте он и есть главный.
    Источник: VS Code `Explorer filter`, Zed `Project Panel`.

## Область 3. Редактор

27. **История поиска и «только в выделении».** Многострочный запрос и regex
    есть, а стрелки вверх/вниз по прошлым запросам и переключателя «в
    выделении» нет.
    Источник: VS Code `Find and Replace`, Zed `Search`.
28. **Правка одного — видна во всех.** Результат поиска раскрывается списком
    всех вхождений, и правка в любом месте списка правит все сразу, а не по
    файлу за раз.
    Источник: Zed `Multibuffer Editing`, JetBrains `Search Everywhere`.
29. **Мягкий перенос и направляющие отступов.** Переключателя мягкого переноса
    и направляющих отступов нет — только `renderWhitespace`; в длинных
    строках горизонтальная прокрутка.
    Источник: VS Code `editor.wordWrap`, `editor.guides`.
30. **Две правки рядом — как в Merge Tool.** Показ конфликтов есть
    (`ui/conflict-view.ts`), а связной прокрутки и переноса блока стрелкой
    в обычном сравнении двух файлов — нет.
    Источник: VS Code `Diff Editor`, JetBrains `Merge Tool`.

## Область 4. Чат

32. **Контекст виден до отправки.** Над полем ввода — список того, что уйдёт
    в запрос (файлы, выделение, ошибки, терминал), с размером и кнопкой
    «убрать». Сейчас видно только после ответа, по счётчику токенов.
    Источник: Cursor `@-context`, JetBrains `AI Context`.
33. **Своя задача — свой прогон.** Параллельная беседа работает в своём месте
    (ветка, рабочий каталог), остановка одной не трогает другую, а конфликт
    мест называется до старта.
    Источник: Cursor `Parallel Agents`, Zed `Agent Panel`.
34. **Стоп гасит и инструменты, а не только печать.** «Повторить» и очередь
    есть; проверить, что нажатие `Стоп` отменяет запущенные команды и
    правки, а не оставляет их сиротами.
    Источник: VS Code `Chat`, JetBrains `AI Chat`.
35. **Изменения от модели — списком и по одному.** Все правки прогона
    собраны в одном месте, каждая с «принять/отклонить» и сравнением, а
    отмена решения возвращает файл как был.
    Источник: Cursor `Review changes`, Zed `Agent: review edits`.

## Область 5. LSP и подсказки

36. **Сервер сам просит обновить пометки.** Подписки на
    `workspace/diagnostic/refresh` НЕТ (`grep refresh main/lsp/lsp.ts` пуст) —
    правка настроек или файла вне редактора не пересчитывает ошибки.
    Источник: LSP 3.17 `diagnostic/refresh`, VS Code `Diagnostic Provider`.
37. **Форматирование на лету.** `textDocument/onTypeFormatting` не
    запрашивается вовсе — отступ проявляется только по команде.
    Источник: LSP 3.17 `onTypeFormatting`, JetBrains `Reformat on the fly`.
38. **Список серверов — с умениями.** `LspStatus.servers` знает язык, версию
    и корень, но не что сервер умеет; при незнакомом языке нет предложения
    поставить сервер.
    Источник: VS Code `language servers`, Neovim `:LspInfo`.
39. **Пометка знает автора.** Диагностика с нескольких серверов сливается
    без источника: в панели не видно, какой сервер сказал.
    Источник: VS Code `Diagnostic source`, Neovim `vim.lsp`.
40. **Подсказки по аргументам.** Подсказки и postfix есть; подсказок по
    аргументам при открытой скобке (как в JetBrains) не хватает — замыкает
    список шумом.
    Источник: LSP 3.17 `completion`, JetBrains `Completion`.
41. **Строки `foldingRange` от сервера.** Свёртка своя по отступам; диапазоны
    от сервера (`textDocument/foldingRange`) не запрашиваются — блоки
    сворачиваются не так, как их видит язык.
    Источник: LSP 3.17 `foldingRange`, VS Code `Folding Provider`.
42. **Цвета от сервера.** `documentColor` не запрашивается: в CSS/конфигах
    нет образцов цвета и выбора — только текст.
    Источник: LSP 3.17 `documentColor`, VS Code `Color Provider`.
43. **Открыть ссылку внутри файла.** `documentLink` получен, но переход по
    ссылке в незнакомую цель (файл, URL) не всегда возможен — проверить и
    добить, чтобы `Ctrl+Click` не молчал.
    Источник: LSP 3.17 `documentLink`, VS Code `Link Provider`.

## Правила работы со списком

- Пункт закрывается только тестом, а не глазами: либо юнит на чистый модуль,
  либо сценарий на существующем стенде.
- Закрытый пункт удаляется из этого файла; его история — в
  `git log --follow -p TASKS.md`.
- Если пункт оказался уже сделанным — он снимается, а не переформулируется
  в «проверить».
- Сквозная нумерация (1..N) сохраняется: новый пункт получает следующий номер
  в конце своей области; при переносе между областями номер обновляется по
  позиции, а не переиспользуется.
- Сначала чинить то, что ломает работу (потеря работы, зависание, слепой
  сервер), потом польза, последней — косметика.
