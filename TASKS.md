на них ссылаются коммиты и память проекта.
Готовое удаляется из списка, а не вычеркивается: здесь только то, что
впереди.

## Правила

1. Перед пунктом — сверка с кодом.
2. Код и удаление пункта — один коммит.
3. Готовое удаляется сразу, без пометок.
4. Экономия без числа до и после не считается сделанной.
5. Пункт, оказавшийся готовым при сверке, удаляется тем же коммитом.

0. Повторный run той же команды в одном прогоне отдаёт «без изменений
   с шагом N» вместо полного вывода. Замер 09.11 упёрся в стену:
   телеметрия хранит только {name, ok, chars, ms, flags} — текст команды
   не пишется, повтора по ним не найти. Чтобы закрыть пункт, нужно СНАЧАЛА
   добавить в запись вызова хэш аргументов (sha1 от args, без самого текста —
   чтобы не писать секреты в журнал), потом перемерить.
   Сама фича сейчас стоит мало: terminal — 37% веса, но p50 = 558 символов,
   и доля именно повторных `run` не доказана. Понижено в приоритете:
   выгода не доказана, цена — поле в журнале.

1. Подсказка ростера сама зовёт второй шаг. `shortRosterLine` вырезает имена
   группы `terminal`/`mcp`, а `toolPresetNote` советует «поля формы — из
   отказа «не задан аргумент»». Значит: вызов без полей → отказ → уточнение =
   два шага на одну команду. Это убыток, а не экономия. Шаги:
   (a) в отказе перечислять поля ФОРМЫ ВСЕГДА, даже если их 12 (~4 токена
   против целого шага);
   (b) из `toolPresetNote` убрать совет «поля — из отказа», заменить на
   «форма — в системном промпте»;
   (c) тест: вызов терминала/ростр-инструмента по имени без полей не даёт
   двухшаговой серии.
   Замер до правки: доля двухшаговых серий `terminal` по counts*.jsonl
   (отказ → уточнение). Сделать ДО правки, иначе нечем доказать выгоду
   (правило 4).

2. Токен-цена контекста не считается. Хвост промпта показывает, сколько
   едет в каждом шаге, но не пишет НИКУДА: ни в телеметрию шага, ни в
   итог прогона. Замер по чатам (~/.config/chui-ide/chats/*.json) доказал,
   что ответы инструментов — 91% истории; без постоянного поля «сколько
   ехало» любая следующая правка экономии мерится постфактум вручную.
   Добавить в trace шага `carried` (токены промпта шага с учётом кеша) и
   в итог прогона — `carriedTotal`. Польза не в экономии, а в приборе.

3. Сокращение истории режет ПО ЗАДНЕЙ, а не по весу. Свёртка старого
   (condenseAppliedCalls, ageStaleResults, minStaleChars) работает по
   чете «размер + возраст», но НЕ ведёт сохраняемую прибыль: 57% вызовов
   короче 900 симв. выходят из окна старения в первом же проходе и больше

   возраста, но остались вызовы, не влезающие ни в одну полосу).
   Проверить: есть ли вызовы, которые раз за разом старше порога, но не
   сворачиваются; если есть — либо в окно по счётчику, либо удалить
   третью ступень как мёртвую (тогда тоже коммитом).

7. Строка ростера может соврать моликом. Найдено при сверке п.1: в

15. Прибор цены хода уводит в ошибку. Счётчик \"цена контекста… 336.5k…

   одного прогона, где я только делал правки в TASKS.md. Значит:
   (a) либо в основу промпта попадает переменная часть (сводка, spill-
   файлы, полные ответы read) — тогда 336k и есть утечка;
   (b) либо сам прибор считает не то, что обещает. Сначала проверить сам
   счётчик (что именно он складывает), потом основу — иначе будем
   экономить на выдуманной цифре. Связано с п.8.

   мента). Правило: после серии правок одного файла — перечитать целиком
   и сверить нумерацию и что ничего не потерялось.
