# Задачи по мотивам DeepSeek Harness

Список того, что из DSH (DeepSeek Harness) осталось сделать в chui_iDE. Не копия их плана,
а наш разбор: что берём, где это живёт у нас и чем проверяется. Сделанное здесь не описано —
оно в README и в истории коммитов.

**Что прочитано** (лендинг + репозиторий + все страницы доков и внутренние ссылки из них):

1. `https://www.deepseek.com/en/harness/` — лендинг: превью, официальные плагины (Agent teams,
   Auto approval review, Scheduled tasks, Voice input, Terminal, Agent loop, Subagents),
   «Creator mode», работа с документами, Developer tools (трасса вызова).
2. `https://github.com/deepseek-ai/deepseek-harness` — MIT, «everything is a plugin» на Cordis,
   `npx @deepseek-ai/dsh web`, профили `web`/`headless`/`sdk`/`acp`, бандлы.
3. `guide/quickstart` и вся ветка Guide: `providers`, `network-proxy`, `public-deployments`,
   `python-sdk`, `github-review`, `schedule`, `mcp-memory`, `plugin-market`.
4. `develop/basic/` (+ `tool`, `config`, `publish`), `develop/framework/*`, `develop/practice/*`,
   `develop/cordis-tutorial/*`.
5. `reference/` — `tool-catalog`, `config-catalog`, `api-gateway`, `agent-lifecycle`,
   `tool-execution-pipeline`, `capability-seams`, `persistence-catalog`, `cookbook/*` и ~50
   страниц `reference/subsystems/*`. К оставшимся пунктам относятся: `session-query` (п. 18),
   `web-server` и `api-gateway` (п. 21), `slots`/`client-modules`/`conversation` (п. 22),
   `typert` (п. 23), `user-questions` и `approval` (голос, п. 16).
6. `docs/architecture.md` и `README.md` из репозитория.

**Как читать.** `P2` — сильные возможности, `P3` — архитектурное и большое. Раньше был и `P1`
(«дешёвое и заметное») — он закрыт целиком, поэтому этого раздела больше нет. Объём: `S` — до
полудня, `M` — день-два, `L` — больше.

## P2 — сильные возможности

### 13. `ralph` — свежий агент на раунд — **M**
Цикл «новый агент без прошлого разговора → ограниченный отчёт → следующий раунд», пока не
готово. Долгая работа не тащит за собой всю переписку: каждый раунд начинается с чистого листа
и получает только отчёт прошлого.

Кирпичи уже есть: `runSubAgent`, цель (`shared/goal.ts`), сценарий (`workflow`) и реестр живых
агентов (`spawn_agent` с почтой и остановкой) — раунд можно раздать `agents.run`, а ветвление
и предел раундов держать в самом сценарии. Отдельный инструмент нужен там, где сценарий не
подходит: предел раундов задаёт человек, а не модель, и он же видит каждый раунд в панели.

- **Где:** `main/ai/service.ts` поверх `runSubAgent`, инструмент в `shared/tools.ts`.
- **Что учесть:** раунд не должен видеть прошлые отчёты целиком — иначе вся затея теряет смысл;
  предел раундов и остановка человеком обрывают цикл целиком, а не один раунд.
- **Проверка:** юнит на предел раундов и на формат отчёта между раундами.

### 15. Вебхук: беседа-ревью по событию GitHub — **M**
Из `guide/github-review`: подписанный эндпоинт; когда PR переходит из черновика в «готов к
ревью», DSH создаёт беседу под рабочей папкой репозитория и запускает read-only ревью.

- **Где:** `main` (локальный HTTP-слушатель на loopback), `main/git` (площадки уже есть),
  `ui/chat.ts` (открыть беседу), настройки.
- **Что учесть:** секрет в заголовке, размер тела, только loopback + проброс извне человеком,
  запуск строго в read-only правах. Слушатель живёт, только пока включён в настройках, а занятый
  порт объясняется словами — иначе «ничего не пришло» будет искать причину в GitHub.
- **Проверка:** юнит на проверку подписи и на «черновик → готов» + проба с локальной отправкой.

### 16. Голосовой ввод в композер — **M**
На лендинге это официальный плагин (`Voice input`). У нас нет ничего (по `src` — ни `voice`,
ни `speech`).

- **Где:** `ui/chat-composer.ts` (значок-кнопка `.icon-btn` в `.composer-toolbar`, подсказка через
  `title` — как у остальных кнопок), запись — media API, распознавание — RPC в main
  (провайдер или локальный whisper).
- **Что учесть:** без разрешения на микрофон — внятный текст; отмена; вставка в текущую позицию,
  а не в конец (человек мог уже начать печатать дальше); без настроенного распознавания кнопка
  не притворяется рабочей.
- **Проверка:** проба `probe:chat` (кнопка есть, отказ объясняется словами), юнит на склейку
  кусков текста.

## P3 — архитектурное и большое

### 18. Индекс бесед (session-query) — **L**
DSH держит SQLite FTS по прошлым сессиям и отвечает «где мы это обсуждали», различая «текущий
контекст», «вытесненный» и «только в журнале». У нас беседы — файлы.

- **Зачем:** поиск по беседам (`session_search`) без индекса хорош до первых сотен бесед; плюс
  `session_trace` — «что было в прогоне» по прошлой беседе.
- **Где:** `main/ai/chat-store.ts`, новый модуль индекса, миграция без потери старых бесед.
- **Что учесть:** индекс — копия, а не хозяин: файл беседы остаётся правдой, и потеря индекса
  должна лечиться пересборкой, а не потерей разговоров.

### 20. Набор инструментов на конкретную беседу — **S–M**
Пресеты наборов сделаны (п. 32): композер, `shared/tool-presets.ts`, подзадача видит тот же
набор. От задуманного осталось одно: набор выбирается общий, из настроек, — а нужен он на
беседу. Тогда «разговор про рефакторинг» и «разговор про релиз» перестают навязывать друг другу
свой набор.

- **Где:** `ChatConversation` (поле набора рядом с прочими её свойствами), `userMessage`.
- **Что учесть:** `sanitizeConversations` обязан переносить новое поле, иначе выбор теряется при
  записи файла — та же грабля, что была с целью работы.

### 21. Headless / ACP: агент без окна — **L**
DSH можно поднять профилем `headless` или `acp` и гонять из чужого кода (есть Python SDK).
У нас всё начинается с окна.

- **Где:** `src/main/index.ts` (аргументы запуска), RPC-слой (`main/ipc`) уже отделён от окна.
- **Зачем:** скрипты, CI, «прогнать задачу по расписанию без GUI».
- **Что учесть:** без окна нет renderer'а, а в нём живут правки, ревью и подтверждения.
  Значит headless-режим — это отдельные права и свой ответ на «агент просит подтверждение»,
  а не просто другой флаг запуска.

### 22. UI-слоты и узлы ленты — **отложено**
Самый интересный для будущего: у DSH клиент — набор слотов (`ctx.slots.register`), а лента — из
типизированных узлов (`ConversationNodeDefinition`). Это и есть фундамент плагинов.

- **Пока отложено** (плагины решено не делать). Но если вернёмся — начинать отсюда, а не с
  «папка с плагинами».

### 23. Типизированный RPC вместо ручного контракта — **L**
У DSH мост Host↔Client генерируется из аннотаций (`@Remote`), у нас — руками: `shared/api.ts`,
`registerIpc`, `scripts/ui-mock.js`, и договор стережёт `tests/ui-mock-contract.test.ts`.
Генерация типов и мок-заглушек из одного описания убрала бы целый класс расхождений.

- **Что учесть:** контракт уже типизирован — не хватает не типов, а ЕДИНОГО описания, из которого
  выйдут и типы, и регистрация, и мок. Начинать с мока (он расходится чаще всего), а не с типов.

## Чего не берём

- **Cordis и «всё есть плагин»** — своя архитектура уже сложилась; переезд на чужой фреймворк
  не окупится.
- **Web UI за реверс-прокси** (`--public-url`, `--trusted-host`) — у нас настольное приложение,
  вынос интерфейса в браузер это отдельный продукт.
- **Plugin manager и рынки плагинов** — сознательно отложены.
- **`str_replace_editor`** — у нас `apply_edit`/`apply_patch`, и они лучше.
- **`pwsh` отдельным инструментом** — у нас терминал и `run_terminal`; PowerShell приедет сам,
  если понадобится, как вид оболочки.
- **`stagehand_*`** — у нас свой браузер с вкладкой, выбором элемента и масштабом.

## Порядок, который предлагаю

1. **Вебхук GitHub (п. 15)** — заметнее всего в работе: ревью приходит само, а не «когда
   вспомнил». Дешёвый по кирпичам: площадки git уже есть, HTTP-слушатель нужен новый.
2. **Голос (п. 16)** — вторая по заметности, но зависит от распознавания: сначала решить, чьё
   оно (провайдер в main или локальный whisper), иначе кнопка появится раньше, чем заработает.
3. **`ralph` (п. 13)** — кирпичи все на месте, но польза видна только на долгой работе; делать,
   когда такая работа появится.
4. **Набор на беседу (п. 20)** — самое дешёвое из оставшегося, чинится в один заход.
5. **Индекс бесед (п. 18)** — нужен, когда бесед станет много; сейчас поиск без индекса
   справляется.
6. **Headless (п. 21)** и **типизированный RPC (п. 23)** — крупное и не про сегодняшнюю работу.
7. **UI-слоты (п. 22)** — только если вернёмся к плагинам.

## Правила для нового инструмента

Каждый новый инструмент проходит один и тот же путь: схема в `src/shared/tools.ts` → исполнение
в `src/main/ai/agent-tools.ts` → решение о правах (`READ_ONLY_TOOLS`, `PLAN_MODE_TOOLS`,
`isDangerousCommand`) → тест → раздел в пробе. Новый RPC — ещё и в `scripts/ui-mock.js`,
иначе покраснеет `tests/ui-mock-contract.test.ts`. Если инструмент отдаёт модели что-то кроме
текста (картинку, вложение) — это `ToolOutcome.images` и отдельное сообщение прогона; тогда
его надо ещё и запретить внутри `run_code` (`DENIED_IN_PROGRAM`), иначе программа получит
текст про картинку, которой модель не видит. А новое поле в беседе (`ChatConversation`) обязан
переносить `sanitizeConversations` — иначе оно теряется при записи файла.
