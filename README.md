# chui_iDE

Редактор кода для Python и Node.js с встроенным ассистентом. Настольное приложение для Windows,
Linux и macOS.

Раскладка в духе современных IDE, свой редактор и свой терминал, привычная палитра подсветки,
поиск и замена по проекту, работа с git и площадками GitHub и GitLab, отладчик
для Python и JavaScript, языковые подсказки, просмотр картинок и предпросмотр Markdown,
встроенный браузер и ассистент, который читает проект, правит файлы, запускает команды,
ищет в интернете и работает с браузером.

Разделы ниже описывают, что приложение умеет и как этим пользоваться.

## Начало работы

**Стартовое окно.** При запуске открывается окно с тремя действиями — «Открыть проект»,
«Склонировать проект» и «Создать проект», — списком недавних проектов и заглушкой, если история
пуста. Клонирование и создание идут с показом хода работы прямо в этом окне, а папку на диске
выбираете вы.

**Создать проект.** Выбираете имя, тип и папку, где ему появиться, — и приложение заводит папку
с файлами-заготовками: точкой входа, README и набором игнорируемых путей. Типы: Python, Node.js
и пустой проект. Имя — это имя папки, поэтому проверяется сразу: разделители пути, знаки вроде
«:» и «*» и зарезервированные системой имена (вроде CON) не примутся, а причина будет видна
под полем. Занятую папку приложение не трогает — поступит с ней так же, как при клонировании:
скажет, что папка уже есть.

**Закрыть проект.** Вернуться к списку проектов можно из меню Файл → «Закрыть проект».
Окно редактора закрывается, а на его месте открывается стартовое — с недавними проектами.
Если остались несохранённые файлы, приложение спросит, что с ними делать, — так же, как
при обычном закрытии окна.

**Открыть проект сразу.** Проект можно задать аргументом — приложение откроет его мимо стартового
окна:

```sh
chui_iDE ~/projects/api    # проект в аргументе
chui_iDE                   # стартовое окно со списком проектов
```

Служебные переключатели впереди не мешают (`chui_iDE --no-sandbox ~/proj`). Если путь указан,
а папки по нему нет, об этом напишут в консоль. Второй запуск с путём открывает проект в уже
работающем окне; на macOS работает и `open -a chui_iDE ~/proj`.

**Несколько папок в одном окне.** Кроме основной папки можно добавить ещё («Добавить папку
в рабочую область»): каждый корень идёт в дереве верхней строкой, клик делает папку активной,
правый клик — «сделать активной» и «убрать из рабочей области». Активный корень задаёт, что
видят поиск, git и запуск, когда файл не назван явно. Правила исключения и пометки git у каждого
корня свои. Панель «Изменения» показывает сводку по всем папкам сразу (ветка, расхождение
с удалённой, число правок), а «Забрать изменения во всех папках» обновляет все корни разом —
папка без репозитория остальным не мешает. Список корней переживает перезапуск.

**Установка на macOS.** Скачайте файл под свой процессор: `arm64` — для Apple Silicon
(M1 и новее), `x64` — для Intel. Узнать свой можно в меню яблока → «Об этом Mac».
Откройте образ и перетащите приложение в «Программы».

При первом запуске система спросит разрешение: приложение подписано самим проектом,
а не сертификатом Apple. Нажмите на значок правой кнопкой и выберите «Открыть», а если
система не предлагает такого выбора — «Всё равно открыть» в «Настройках» →
«Конфиденциальность и безопасность». Это нужно один раз, дальше приложение запускается
как обычно.

Сообщение «файл повреждён, переместите в Корзину» к скачанному файлу больше не относится:
оно появлялось у сборок без подписи, и такие сборки исправлены. Если оно всё же вышло,
скачайте файл из последнего выпуска — в нём подпись есть.

## Интерфейс

**Окно.** Системной шапки нет — рамку рисует приложение: кнопка «☰» открывает меню, кнопка
запуска, действия и кнопки окна. Окно тянется за шапку и растягивается за края. На macOS остаются
системные «светофоры», своих кнопок свернуть/развернуть/закрыть там нет. Горячие клавиши,
которых приложение не видит (масштаб, полный экран), держит системное меню и они работают.

**Раскладка.** Панели — «острова» со скруглёнными углами: панели и редактор темнее фона окна,
поэтому швы между ними читаются светлыми линиями, а зазоры работают сплиттерами. В шапке
слева — меню и работа с содержимым: сохранить всё, поиск, открыть страницу; в центре — имя
открытого файла и кнопка запуска; справа — переключатели раскладки (боковая панель, нижняя
панель, разделить редактор), ассистент и кнопки окна. Палитра команд и настройки в шапку
не вынесены: первая живёт на `Ctrl+Shift+P` и в меню «Вид», вторые — на `Ctrl+,` и в меню «Файл».

**Вкладки и строка состояния.** Активная вкладка выделена светлой подложкой — она
приподнята над полосой, а не залита цветом; путь к файлу показывают
хлебные крошки. Полоса вкладок прокручивается колесом по горизонтали. Строка состояния:
путь к файлу, `строка:столбец`, окончания строк, кодировка, отступ, язык, ветка git
и число правок, а у проектов на Python — виджет окружения, у Node — чип версии Node, у языковых
серверов — чип активного сервера. Клик по чипам открывает соответствующие панели.

**Пустой редактор** показывает знак приложения «[i_i]» и подсказки по горячим клавишам: кнопок
нет, всё, что они делали, есть в меню, в палитре команд и в дереве проекта.

**Палитра команд** (`Ctrl+Shift+P`) собирает все действия приложения. Настройки открываются
по `Ctrl+,` — там есть поиск по разделам. Режим дзен (`Alt+Z`) прячет панели, нижний док, строку
состояния и шапку, оставляя только редактор.

## Проект и файлы

**Дерево проекта** показывает файлы и папки; содержимое подгружается по мере раскрытия, набор
раскрытых папок возвращается при следующем открытии проекта. Файл открывается по клику или
двойному (выбор — настройка `explorer.openOnSingleClick`). Значки файлов и папок свои: цвет
и буква говорят о виде файла, у папок отдельные тона для `src`, `tests`, `dist` и других.

**Работа с файлами.** Файлы и папки создаются, переименовываются (вводом прямо в строке дерева)
и удаляются в корзину; те же действия — в контекстном меню строки. Ввод `a/b/c.txt` создаёт всю
цепочку папок. Перетаскивание переносит файл или целую выделенную группу; с `Ctrl` (на macOS —
`Alt`) — копирует, и копия не перетирает существующее. «Обновить» перечитывает папки, не схлопывая
дерево: раскрытые папки и выделение остаются на месте.

**Выделение.** `Ctrl`/`Cmd`+клик добавляет или снимает строку, `Shift`+клик выделяет диапазон,
`Del` удаляет всю группу одним вопросом.

**Открытие вне приложения.** Из контекстного меню строки: «Открыть в системном проводнике»,
«Открыть внешней программой», «Открыть терминал в папке» (встроенная панель поднимается
в каталоге выбранного) и «Открыть терминал системы» (свой задаётся переменной `$TERMINAL`).
Копирование пути — тоже из меню строки; у группы копируются все пути, по одному на строку.

**Быстрое открытие файла** (`Ctrl+Shift+O`) — список файлов проекта с отбором по подпоследовательности
символов: «qjs» находит `quick-js`. Совпадение в имени файла весит больше, чем в пути.

**Поиск и замена по проекту** (`Ctrl+Shift+F`) — с регулярными выражениями и маской файлов.
Рядом с поиском поле «Чем заменить» и кнопка «Заменить все». Область поиска переключается
на «Открытые вкладки» — тогда поиск идёт по тексту документов в памяти (видно и несохранённые
правки), но замена в этом режиме недоступна.

**Поиск по структуре.** Поиск символа по проекту (`Ctrl+T` — имя класса, функции, переменной),
«Где экспортируется» — файлы, где имя под курсором объявлено экспортом, «Кто наследует тип»
и «От кого наследует тип» — по родителям объявления.

Объявления всех файлов проекта (Python и Node.js) IDE держит собранными зараннее и сохраняет
между запусками. Поэтому поиск по структуре отвечает сразу после открытия проекта, а пока
языковой сервер ещё разбирается или вовсе недоступен — находит по этой же карте.

В карту попадают и установленные зависимости — пакеты `node_modules` и библиотеки окружения
Python (включая общее окружение вне проекта). Их классы и функции находятся так же, но идут в
списке ниже своих и подписаны именем пакета; открываются такие файлы только на чтение.

**Пометки git** в дереве: буква у файла и точка у папки, внутри которой есть правки; в подсказке —
сколько правок внутри. Цветом помечается и весь путь к правке. Несохранённые документы тоже
показываются изменёнными, а удалённые и ещё не закоммиченные файлы остаются зачёркнутой строкой
с буквой `D`. Игнорируемые git файлы показываются приглушённо (настройка `explorer.dimIgnored`).
Пометки обновляются сами, в том числе после чужого коммита из терминала. Добавить файл
в `.gitignore` можно прямо из меню строки.

**Подсветка недавно изменённых.** Файл, тронутый в пределах окна (`explorer.recentChanges`,
по умолчанию сутки), получает точку свежести — это про время правки, а не про правки с коммита.

**Просмотр без открытия** (`Пробел` на выделении или «Просмотр» в меню строки) — копия кода файла
«на месте», вкладок не трогает; стрелками листаются файлы, `Enter` уводит насовсем, `Escape`
закрывает.

**Сравнение файлов и папок.** Два выделенных файла дают «Сравнить», один — «Сравнить с…»
(файл подбирается быстрым открывателем). Две папки дают «Сравнить папки»: окно показывает
различающиеся файлы, а клик по строке открывает их сравнение.

**Локальная история файла** (`file.history`): прежнее содержимое откладывается при каждой
перезаписи и перед удалением; окно показывает версии (время, возраст, размер, причину), даёт
предпросмотр и возврат выбранной. История хранится вне проекта, рядом с беседами.

**Связанные файлы (file nesting).** `Button.module.css` и `Button.test.tsx` сворачиваются
под `Button.tsx`. Правила по умолчанию есть для JS, TS, Python, Go и Ruby, свои задаёт настройка
`explorer.fileNesting`.

**Автосохранение** (настройка `editor.autoSave`): выключено, «через паузу после правки»,
«при переходе к другому файлу», «при потере фокуса окна». Если файл изменён на диске, автосохранение
его не перезаписывает, а сообщает, что пропустило.

**Горячий выход.** Несохранённые правки уходят в сессию проекта и возвращаются при следующем
открытии; файл на диске при этом не трогается, вкладка помечена «не сохранён». Размер и число
таких буферов ограничены. Вернуть файл к версии на диске можно командой «Перечитать с диска» —
она отбрасывает правки в буфере с подтверждением, где перечислено, что потеряется.

**Большие проекты.** Дерево рисует только строки вокруг видимой части, поэтому папка в несколько
тысяч файлов остаётся отзывчивой. Симлинки показываются значком-стрелкой: ссылка на папку
раскрывается, на файл — открывается, битая помечена. В монорепо пакеты можно поднять строками
верхнего уровня (`explorer.groupByPackage`) — `packages/api` показывается как `@demo/api`,
а промежуточный каталог скрывается.

**Группировка и сортировка.** Порядок строк настраивается: имя, тип файла, время изменения,
пометки git. Группировка по назначению (`explorer.groupByType`, выключена по умолчанию) собирает
файлы под полками «Тесты», «Стили», «Документация», «Конфигурация», «Ресурсы», «Исходники».

**Избранное и закрепление.** Постоянные места — отдельным блоком над деревом (настройка
`workspace.favorites`): живут в настройках приложения, переживают смену проекта и могут указывать
на папку вне области. Закреплённые файлы и папки собираются в блоке сверху дерева. Метка файла —
цветной ярлык из подменю «Метка»; закладки на строки живут в редакторе.

**Настройки на каждую папку.** У корня области могут быть свои отличия от общих: что скрыто,
как сортируется, что помечается (окно «Настройки папки…» в меню строки корня).

**Удалённые папки.** Адреса `ssh://`, `wsl://` и `container://`; ходит туда клиент системы — `ssh`,
`wsl`, `docker`. Папки видны блоком «Удалённые папки» в дереве, файл открывается своим окном
с записью. Адрес задаётся настройкой `workspace.remoteRoots` или командой «Подключить удалённую
папку…». Строка папки различает три состояния: «Читаю…», красное «Не удалось прочитать — проверьте
адрес и доступ» и «Папка пуста». По удалённым путям не работают слежение за папкой, пометки git,
индексация и запуск, поэтому такая папка открывается отдельным окном, а не вкладкой.

**Сторонние значки** поверх дерева: правила «маска → подпись и цвет». Набор приносит человек —
файлом (команда «Набор значков дерева из файла…») или настройкой `explorer.badges`.

## Редактор

**Ввод** сам дописывает пары скобок и кавычек, перешагивает через закрывающий знак и снимает
пустую пару целиком. `Ctrl+/` комментирует строки, `Shift+Alt+A` — блоком; `Alt+↑/↓` переносят
строку, `Shift+Alt+↓` копируют её ниже; `Ctrl+Shift+K` удаляет строку, `Ctrl+Shift+J` соединяет
строки. Работают мёртвые клавиши (акценты) и составной ввод иероглифов.

**Подсветка.** Своя подсветка синтаксиса — более двадцати языков: C-подобные (JS, TS, Java, C, C++,
C#, Go, Rust, Kotlin, Swift, PHP, Dart, Scala, Groovy, Lua, Ruby, Perl, R), Python, JSON, YAML,
TOML, Shell, HTML/XML, CSS/SCSS/Less, Markdown, SQL, Makefile, Dockerfile. Цвета — привычная
палитра. Под курсором подсвечиваются все вхождения слова
и парная скобка, а свёрнутый блок и парные теги — связанные участки. Семантическая подсветка
ложится поверх своей: где высказался языковой сервер, его роль важнее.

**Поиск и замена по файлу** (`Ctrl+F` / `Ctrl+H`): подстрока, слово целиком или регулярное
выражение, с учётом регистра или без. Ошибочная регулярка не прерывает работу — она показывается
под полем ввода. Замена всех отменяется целиком одним `Ctrl+Z`. Переход к строке — `Ctrl+G`.

**Автодополнение** подсказывает слова документа и подбирает их по началу, по «горбам» имени
(`gT` → `getTitle`) и с учётом регистра. После точки подсказываются члены объекта, а не слова
файла. Сниппет раскрывается по формату `${1:имя}`: разметка в текст не попадает, а курсор встаёт
на первое место подстановки. Emmet по `Tab` раскрывает сокращения разметки и стилей (`ul>li*3`
→ список, `m10` → `margin: 10px;`), включатель — `editor.emmet`.

**Мультикурсор.** `Ctrl+D` добавляет каретку на следующем вхождении слова, `Ctrl+Shift+L`
выделяет все вхождения сразу, `Ctrl+Alt+↑`/`Ctrl+Alt+↓` ставят каретку по столбцу, `Alt+клик`
добавляет каретку вручную, `Alt+протяжка` — блочное выделение, `Escape` оставляет одну каретку.
Набор, удаление и вставка идут во все каретки и отменяются одним `Ctrl+Z`.

**Свёртка блоков.** У сворачиваемых строк есть значок в жёлобе; `Ctrl+Shift+[` и `Ctrl+Shift+]`
сворачивают и разворачивают блок под курсором, «Свернуть всё» и «Развернуть всё» — в палитре.
Границы берутся у языкового сервера, а без него считаются по отступам.

**Навигация по коду.** `F12` — перейти к определению, `Shift+F12` — все ссылки, `Ctrl+Shift+F12` —
заглянуть в определение (копия кода на месте, не уходя из файла). Хлебные крошки, список символов
файла, иерархии вызовов и типов. Закладки на строки: `Ctrl+Alt+K` ставит и снимает, `Ctrl+Alt+L`
и `Ctrl+Alt+J` листают, `Ctrl+Alt+B` открывает список; закладки помнятся в проекте.

**Рефакторинг.** Переименование символа, организация импортов, авто-импорт при вставке, смена
стиля имени (camelCase ↔ snake_case), сортировка, соединение, дублирование и перестановка строк,
форматирование документа и при сохранении. Быстрые исправления (`Ctrl+.`) — список действий
для места под курсором, в том числе «Извлечь в переменную или функцию» и «Развернуть (inline)».
Обернуть выделение (`Ctrl+Shift+T`) — скобки, кавычки, блочный комментарий, тег. Форматирование
выделения — `Ctrl+K Ctrl+F` (правится только выделенный участок).

**Качество кода.** Ошибки и предупреждения подчёркнуты волной и собраны в панели «Проблемы»;
`F8` и `Shift+F8` ходят по пометкам. Автор строки (blame) и полоски изменений в жёлобе.
Пометки TODO/FIXME подсвечиваются в тексте и собираются в панели «Задачи». Проверка орфографии:
слова не из словаря подчёркиваются зелёной волной, словарь берётся из системы или задаётся
переменной `CHUI_DICTIONARY`, свои слова — настройка `editor.spellWords`, включатель
`editor.spellcheck` (в коде проверяются только комментарии и строки).

**Вид.** Перенос длинных строк (`editor.wordWrap`, по умолчанию выключен), показ невидимых знаков
(`editor.renderWhitespace`: `none` / `trailing` / `all`), миникарта (`editor.minimap`), лигатуры
(`editor.fontLigatures`), направляющие столбцов, своя высота строки, форма и мигание каретки.
Разделение редактора — `Ctrl+\`: две панели в ряд или сетка 2×2, у каждой панели свой курсор
при общем буфере. Вкладки умеют предпросмотр и закрепление.

**Режим Vim** (настройка `editor.vimMode`, выключен) — нормальный, визуальный и визуально-строчный
режимы плюс вставка: движения `h/j/k/l`, `w/b/e`, `0/^/$`, `gg/G`, операторы `d/c/y`
со счётчиками, объекты текста `iw/aw`, регистры `"a`…`"z`, `p`/`P`, `.` повторяет правку.
**Режим Emacs** (настройка `editor.emacsMode`, выключен) — сочетания Ctrl/Alt поверх обычного
ввода: `Ctrl+F/B/N/P`, `Ctrl+A/E`, `Ctrl+K/U`, `Ctrl+Y`, `Ctrl+_` и другие.

**Inline-подсказка** — призрачный текст у каретки, принимается по `Tab`.

## Просмотр файлов

**Картинки.** При открытии изображения показывается отдельное полотно: вписывание в окно, масштаб
кнопками и `Ctrl+колесо`, «1:1», в шапке — формат и размер. Открываются PNG, JPEG, GIF, WebP, BMP,
ICO, AVIF, SVG, APNG, TIFF и HEIC — последние два приложение объясняет заглушкой, потому что
показать их не умеет. Картинка крупнее 32 МБ не открывается.

**Предпросмотр Markdown.** Файл `.md` показывается либо исходником, либо собранным документом;
переключает режимы кнопка в самой вкладке (глаз — смотреть, карандаш — вернуться к правке), тот же
переключатель продублирован кнопкой «Редактировать» в шапке предпросмотра. Разметка обновляется
по правке с небольшой задержкой. Режим помнится по файлу.

**Встроенный браузер.** Страница открывается вкладкой в редакторе: меню «Вид → Открыть страницу…»,
палитра команд или `Ctrl+Shift+B`. Адрес вводится обычной строкой (без схемы — `https`, локальные
адреса — `http`). У каждой вкладки своя история, прокрутка и формы; куки и кэш браузера хранятся
отдельно от окна приложения. Ссылки, которые просят новое окно, открываются вкладкой в той же
полосе. Ссылка из вывода терминала на локальный адрес открывается вкладкой в приложении, а чужой
адрес уходит в системный браузер.

**Страница и ассистент.** По умолчанию ассистент работает в отдельной вкладке со своей сессией.
Кнопка «поделиться» (значок ассистента в шапке вкладки) отдаёт ему доступ к той странице, которую
видите вы, — вместе с входом и куками; доступ снимается той же кнопкой или закрытием вкладки.
Кнопка «Добавить в чат» кладёт в вопрос снимок страницы или её журнал консоли.
Пока ассистент действует на странице, об этом говорит плашка в её шапке и точка на вкладке.

**Масштаб и выбор элемента.** В шапке вкладки есть масштаб страницы — те же кнопки, что у
просмотра изображений: мельче, крупнее, 1:1 и «вписать по ширине»; `Ctrl` с колесом делает
то же самое. Кнопка «выбрать элемент» превращает клик по странице во вложение вопроса: в чат
попадают селектор, стили, разметка и снимок этого элемента, а страница при выборе не нажимается.

**PDF.** Документ `.pdf` из проекта открывается той же вкладкой-страницей: печатать и листать его
умеет встроенный просмотрщик движка, поэтому в полосе у него подпись файла, а в шапке — страницы,
масштаб, скачивание и печать. В адресной строке стоит имя файла, а не адрес: сетевого адреса у
документа нет. Открывается только то, что лежит в проекте и не больше 64 МБ — остальное честно
отказывает словами. Текстом PDF не открывается: в редактор попал бы двоичный файл.

## Терминал

Настоящий терминал (псевдотерминал): несколько сессий с вкладками, свой рабочий каталог, изменение размера
вместе с панелью, завершение процесса, очистка экрана. Шрифт, кегль и лигатуры у него общие
с редактором, поэтому консоль и код выглядят одинаково.

Умеет цвета 16/256/truecolor, широкие и составные знаки, альтернативный экран (`vim`, `htop`),
мышь, выделение и копирование (автоматически при выделении и по `Ctrl+Shift+C`), вставку из буфера
(`Ctrl+V`), поиск по выводу (`Ctrl+F`), гиперссылки (клик открывает локальный адрес вкладкой
в приложении, чужой — в системном браузере) и имя окна от программы — оно показывается подписью
вкладки: в подписи — только имя каталога, полное имя видно на наведении.

При изменении ширины окна содержимое переносится заново: длинная строка ломается на несколько
или собирается в одну, а что не влезло — уходит в историю, а не пропадает.

## Языки и подсказки

Подсказки по коду, переходы к определениям и подчёркивание ошибок даёт языковой сервер —
отдельная программа для конкретного языка. Приложение само следит за тем, когда он нужен,
и запускает его без вашего участия.

**Что поддерживается.** Python, JavaScript и TypeScript, Rust, Go, C и C++, Java, Kotlin, Swift,
C#, Ruby, PHP, Dart, Perl, Lua, Shell, а также JSON, YAML, CSS/SCSS/Less, HTML, XML, SQL, TOML,
Dockerfile и Markdown. У языков, для которых сервера нет, ничего не запускается и сообщение
об ошибке не появляется.

**Откуда берутся серверы.** Часть едет вместе с приложением и работает сразу после установки:
JS/TS, Python (Pyright), JSON, CSS, HTML и YAML — дополнительно ставить ничего не нужно.
Остальные (pylsp, pyright, rust-analyzer, gopls, clangd, jdtls, solargraph, intelephense и другие)
подбираются из окружения проекта или из `PATH`: кнопка «Найти установленные» проверяет и то и другое.
Если подсказки включены, а список серверов пуст, приложение подставит найденные само.

У каждого языка остаётся один сервер. Приоритет: окружение проекта → поставка приложения → `PATH`.
Если названный сервер не поднялся или подолгу не отвечает, берётся следующий по приоритету,
чтобы язык не остался без подсказок из-за одного плохого сервера.

**Что видно в окне.** Чип в строке состояния называет сервер активного языка и откуда он взят.
Клик по чипу открывает список: что запущено, а что не поднялось — с причиной, и кнопки
«Перезапустить» и «Настройки».

**Настройка.** Раздел «Языки (LSP)» в настройках (те же значения в `settings.json`):
`lsp.enabled` — общий тумблер, `lsp.servers` — список серверов вручную, `lsp.trace` — журнал
обмена с серверами для отладки. Там же кнопки «Найти установленные», «Установить сервер (Python)»
(ставит python-lsp-server с линтерами в окружение проекта) и «Перезапустить».

**Что умеет подсказка.** Автодополнение (в том числе по знакам-триггерам языка), наведение
с типом и описанием, переход к определению и ссылки, структура файла, иерархии вызовов и типов,
переименование, быстрые исправления и рефакторинги, подсказка по аргументам вызова, кликабельные
ссылки в `import` и адресах, связанное редактирование парных тегов, значения переменных прямо
в строках при отладке. Ошибки и предупреждения подчёркнуты и собраны в панели «Проблемы»; текст
пометки виден в карточке наведения. Форматирование языковой сервер не делает — его выполняют
ruff, black и prettier.

Записные книжки (ячейки Jupyter) не поддерживаются.

## Запуск, тесты и отладка

**Запуск.** Кнопка запуска стоит в центре шапки и появляется, когда есть что запускать: файл
Python, Node, Shell или задача из `scripts` в `package.json`. Запускается то, чем нужно —
интерпретатор виртуального окружения проекта, а без него `python3`; менеджер пакетов Node
определяется по проекту. Команда набирается в терминале в каталоге проекта: процесс видно,
его можно прервать и посмотреть вывод, вкладка называется по запуску. Перед запуском
несохранённые файлы сохраняются (отключается в настройках).

**Точка входа** отмечена значком ▶ у номера строки: `if __name__ == "__main__":` в Python,
`require.main` в Node. Клик по значку запускает файл так же, как `Ctrl+F5`. В тестовом файле
значок стоит у каждого теста — клик запускает ровно этот тест, а не весь файл.

**Файлы TypeScript** запускаются без предварительной сборки. Если в проекте есть `tsx` или
`ts-node` — запускаются они, иначе файл выполняет сам Node со встроенным стиранием типов.
Более старый Node файлы `.ts` не выполняет, и запуск тогда не предлагается.

**Виртуальные окружения Python** — окно «Python: виртуальные окружения» (меню «Python»
или палитра по слову `venv`): видно уже найденные, главное помечено, тут же создаётся новое —
с выбором версии Python из системы, набором пакетов и зависимостей из `requirements.txt`.

**Пакеты и окружение.** Попап окружения Python показывает, сколько пакетов стоит, сверяет
установленное с `requirements.txt` (сколько зависимостей не хватает и каких) и ставит их одной
кнопкой; то же — командой «Python: установить зависимости». Клик по чипу «Node.js» в строке
состояния показывает версию Node, менеджер пакетов, требуемую версию, поломки (нет `node_modules`,
не хватает зависимостей, нет файла блокировки) и кнопку установки зависимостей.

**Проверка импортов.** Импорты неустановленных библиотек подчёркиваются прямо в редакторе
(`import requests`, `import { z } from 'zod'`); стандартная библиотека Python и встроенные
библиотеки Node не трогаются. Так же помечаются свои файлы, которых нет на диске:
`import { x } from './gone'`. Окружение сменилось или файл открыли заново — проверка повторяется.

**Отладчик** работает для Python и JavaScript: `F5` запускает, `Shift+F5` останавливает,
`F9` ставит точку останова на строке курсора, `F10`/`F11`/`Shift+F11` — шаги. Подключиться можно
и к уже запущенному процессу («Отладка: подключиться к процессу…»). Правый клик по жёлобу открывает
меню точки останова: условие, счётчик попаданий («остановиться на пятом проходе») и точка в журнал —
она печатает сообщение с подстановкой значений вместо останова.

Раздел «Наблюдение» считает свои выражения (`total * 2`, `len(items)`) в контексте выбранного
кадра; выражения можно заготовить заранее. Наведение на имя в остановленном файле показывает
значение и тип. Двойной клик по переменной или наблюдаемому выражению задаёт новое значение.
Панель «Отладка» показывает стек вызовов и переменные выбранного кадра. Параметры запуска
(аргументы, переменные окружения, рабочий каталог), наблюдения и точки останова помнятся
в проекте. Останов по исключению — двумя галочками: необработанные и любые.

## Git и площадки

**Панель «Изменения»** (`Ctrl+Shift+G`) — поле сообщения коммита и два списка: проиндексированные
и остальные правки, у каждой строки кнопка индексации. В однорепозиторных проектах обычно
открывается поповером у кнопки ветки в строке состояния. Файлы помечены буквами и цветом:
`M`, `A`, `D`, `R`, `U`, `!`. Переключение ветки — списком в панели.

**Коммит.** Обычный, только проиндексированное, и исправление последнего (`amend`) — флажком.
Перед коммитом несохранённые буферы записываются (настройка `git.saveBeforeCommit`). Кнопка
со искрой предлагает сообщение коммита по правкам — это один запрос к модели, без беседы
и инструментов; текст ложится в поле, а не коммитится сразу. Кнопка «Соавтор» дописывает строку
`Co-authored-by`. Есть отложенные изменения (stash) своим окном: сохранить, применить, всплыть,
удалить, посмотреть патчем.

**Синхронизация.** Кнопки `fetch`, `pull`, `push` в шапке панели, рядом — расхождение с удалённой
веткой (`↑` уехало, `↓` не подтянуто). Первая отправка ветки сама ставит upstream, принудительная —
через `--force-with-lease`. Режим вливания выбирается в настройках раздела «Git»: как настроено
в git, слияние, перебазирование или только перемотка.

**Сравнение и полоски.** Экран сравнения — рядом или одним столбцом, с ходьбой по блокам
(`Alt+↑`/`Alt+↓`). В сравнении можно оставлять замечания к коду: у строки — замечание, ответы идут
в треде, тред помечается решённым; замечания хранятся в проекте и переживают перезапуск. В жёлобе
редактора полоски показывают добавленные, изменённые и удалённые строки файла, а правый клик
по полоске индексирует, снимает из индекса или откатывает один блок правок.

**История.** Коммиты файла и всего репозитория, различие любого коммита, граф веток, blame,
переход к коммиту, изменившему строку под курсором. У коммита — перенос (`cherry-pick`), откат
(`revert`) и сброс ветки на него. Ветки: список локальных и удалённых, переключение, создание,
переименование и удаление. Теги: создание, список, переход, отправка и удаление. Отмена операций —
журнал ссылок (`reflog`) и «Отменить последний коммит», оставляющий правки в индексе.

**Прочее.** Перестройка истории (interactive rebase) своим окном: каждый коммит можно оставить,
переписать сообщение, остановиться и править, склеить с предыдущим или выбросить, а также
переставить стрелками. Поиск багованного коммита (`git.bisect`) ведёт диалог с git и отмечает
коммиты «Хороший»/«Плохой». Сравнение веток — список различающихся файлов со статусом.
Рабочие каталоги (worktree) — список, открытие любого как проекта, добавление и удаление.
Подмодули помечены в дереве. Разреженный рабочий каталог (sparse checkout) показывает, какие
папки выложены на диск. Большие файлы (Git LFS) — отдельное окно. Личность автора и подпись
коммитов (`git.identity`) правятся в локальном конфиге репозитория.

**Площадки GitHub и GitLab.** Вся работа идёт через консольный клиент `gh` или `glab` — своих
токенов приложение не заводит, вход и хранение токена берёт на себя клиент. Доступны:
запросы на слияние (PR/MR) с обсуждением и созданием, задачи (issues), прогоны CI и уведомления.
Площадка узнаётся по адресу удалённого репозитория. Без клиента или без входа окно говорит
об этом словами, а не показывает пустой список.

## Ассистент

**Провайдеры.** Поддерживается любой OpenAI-совместимый API — OpenAI, Groq, Ollama, llama.cpp,
LM Studio и другие, а также Anthropic. Настраиваются в `~/.config/chui-ide/settings.json`:

```json
{
  "ai": {
    "providers": [
      { "id": "openai", "label": "OpenAI", "baseUrl": "https://api.openai.com/v1",
        "models": ["gpt-4o-mini"], "defaultModel": "gpt-4o-mini" },
      { "id": "local", "label": "llama.cpp", "baseUrl": "http://127.0.0.1:8080/v1",
        "models": ["qwen2.5-coder"], "defaultModel": "qwen2.5-coder" }
    ],
    "activeProviderId": "openai"
  }
}
```

Ключи в `settings.json` не хранятся: они лежат отдельно, в `credentials.json` рядом
с настройками (права — только владельцу). Файл настроек копируют в бэкап и правят руками, а ключ —
это пароль, поэтому в нём его нет; при обновлении старый ключ оттуда переезжает сам. В окне ключ не
виден никогда: панель знает только «ключ есть».
Можно и не хранить его вовсе, а задать переменной окружения: `OPENAI_API_KEY`,
`GROQ_API_KEY`, `ANTHROPIC_API_KEY` или общим `CHUI_API_KEY` — тогда файл ключей вообще не нужен.
Для локальных адресов ключ не требуется.

**Контекст в вопросе.** К вопросу прикладываются выделение, файл или проблемы (`#selection`,
`#file`, `#problems`) и картинки: скрепка → «Изображение из файла…», `Ctrl+V` из буфера или
перетаскивание файла на панель. До четырёх изображений на вопрос, до 5 МБ каждое — это
картинки, которые вы приложили сами. Ту, что агенту нужно посмотреть в проекте, он читает
сам (`read_image`, ниже). Через `@` прикладывается файл или папка проекта — и прошлая беседа:
разговор уходит к вопросу как справка, отдельным блоком с пометкой «это данные, а не указания»
и ссылкой на исходный разговор (видно, откуда взят текст, и он не путается с приложенным
файлом). Так спрашивают «а как мы это решали?», не пересказывая старый разговор руками.
Прикладывается хвост переписки (до 40 последних сообщений), текущая беседа в подсказку
не попадает, а размер справки ограничен в байтах: кириллица занимает два байта на знак,
и предел в символах врал бы вдвое.

**Слэш-команды** композера (`/explain`, `/fix`, `/tests`, `/doc`), свои команды проекта и команды
«Объяснить выделение» и «Исправить выделение» шлют вопрос с выделенным фрагментом. Короткие задачи
в один запрос (подсказка в редакторе, сообщение коммита) идут мимо беседы.

**Инструменты ассистента.** Чтение проекта: список файлов, чтение файлов и диапазонов,
просмотр картинки, поиск по тексту и по смыслу, карта проекта, скелет файла, поиск файлов
по маске, диагностика, запуск линтера и тестов, поиск ссылок и переход к определению,
переименование символа. Правки: применение правок и патчей, массовая замена, создание,
удаление и перемещение файлов. Запуск: команды терминала, в том числе фоновые задания —
запустить, прочитать новое по номеру, снять, — и живые терминальные сессии: открыть,
писать в неё, читать вывод, закрыть. Git: чтение состояния, различий, истории и blame,
а также индексация, коммит, смена ветки, откат, получение и отправка изменений. Ещё: поиск
в интернете и чтение страницы по ссылке (поиск отдаёт выдачу, а страницу агент открывает сам —
текстом, с заголовком и ссылками, по которым идёт дальше), открыть файл в редакторе,
план работы, цель работы, файлы-результаты кнопкой в ленте, вопрос человеку, подзадачи
(несколько независимых разом — идут параллельно), браузер, навыки, память проекта
и поиск по прошлым беседам проекта (что уже обсуждали и решили),
а также ресурсы внешних серверов MCP — каталог адресов и чтение документа по нему.
Отдельно — программа вместо десятка вызовов (`run_code`, о ней ниже).
Ход в интернет — поиск и чтение страниц — включается в настройках (раздел AI)
отдельно: по умолчанию агент в сеть не ходит.

**Прокси.** Если в окружении заданы `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` или `NO_PROXY`,
IDE ходит в сеть через них — этим же путём идут провайдер модели, веб-поиск и чтение страниц.
Локальные адреса прокси не касаются никогда, `NO_PROXY` понимает домены с поддоменами и порт,
а `socks5://` не поддержан: о нём честно сказано в ошибке, а не молча ходим напрямую.

Несколько инструментов отвечают не «что нашлось», а «что спросили», и это сделано нарочно:
`search` показывает не больше десяти совпадений из одного файла (иначе один `package-lock.json`
занимал всю выдачу и казалось, что больше нигде нет); `read_file` у файла длиннее 400 строк
показывает первые 200 и оглавление объявлений, а не первые 60 000 символов вслепую; `run_tests`
принимает файл или имя теста — гонять весь набор после правки одной функции незачем; `git_diff`
без пути показывает весь рабочий diff, а не требует перебирать файлы; а если якорь правки
не нашёлся, ответ называет ближайшую строку, чтобы не читать файл заново.

**Картинка из проекта.** `read_image` показывает модели файл-изображение: скриншот, макет,
схему. `read_file` на картинке откажет — она не текст, а SVG читается именно как текст.
Крупная картинка уменьшается сама (длинная сторона — до 1568 пикселей, вес — до 1,5 МБ):
она едет в каждом следующем запросе беседы, и один скриншот на 6 МБ стоил бы дороже
всего остального контекста. В раскрытой карточке вызова видно сам кадр.

**Режимы работы.** Рядом с полем ввода выбирается, насколько самостоятелен ассистент.
«Вопрос» — просто ответ по тому, что вы написали и приложили: инструментов нет, проект он
не читает. «Агент» — сам смотрит файлы, правит их и запускает команды. «План» — читает
проект и предлагает шаги, ничего не меняя: ни правок, ни команд. Ещё один выбор — усилие
размышления: сколько модель думает перед ответом (от «без размышлений» до `High`). Он имеет
смысл только у моделей, которые умеют думать; остальным он ничего не меняет.

**Набор инструментов.** Схемы инструментов уезжают модели в каждом запросе, и полный набор —
это около одиннадцати тысяч токенов: прогон в восемь шагов платит их восемь раз. Поэтому рядом
с режимом есть выбор набора: «Все инструменты» (как было), «Правка» (чтение, правки, проверки),
«Только чтение» и «Минимум» (найти, прочитать, спросить). «Только чтение» стоит примерно вдвое
дешевле полного, «Минимум» — вчетверо. Выбор действует в режиме «Агент», хранится в настройках и
переживает перезапуск; если модель всё же позовёт инструмент не из набора, он не выполнится,
и ей об этом скажут — вместе с советом попросить у вас другой набор.

**Куда попадают правки и что спрашивается.** Права выбираются рядом с режимом, в трёх
состояниях. «Спрашивать» — правки приходят карточкой в ленте, команды тоже спрашиваются:
это состояние по умолчанию. «Правки» — правки применяются сразу и сразу ложатся на диск,
а команды всё равно спрашиваются: отменить правку есть чем, а `npm install` — нет.
«Полный доступ» — и правки, и команды без вопросов; необратимые команды всё же могут
спросить, если включена страховка (её можно снять в настройках). В «Вопросе» и «Плане»
выбор недоступен: там инструменты либо не работают, либо ничего не меняют.

**Проверка подтверждений моделью.** В режиме «Спрашивать» агент за один ответ запускает
десяток безобидных команд — просмотр, поиск, `git status`, сборку, — и на каждой карточке
начинают нажимать «Выполнить» не читая, а подтверждение, которое нажимают не читая, ничего
не значит. Отдельная настройка «Проверять команды моделью» ставит между ассистентом и вами
второе мнение: безобидные команды выполняются сами, а в ленте остаётся строка «Разрешено
проверкой» с причиной. Сомнительное — то, что меняет файлы, ходит в сеть, трогает историю
git — проверка не разрешает и отдаёт вам вместе со своей причиной: она видна в карточке
подсказкой. Необратимые команды (`rm`, `sudo`, `git push --force`) проверка не трогает
вообще: их решаете вы, даже если модель уверена. Ошибка сети, таймаут и непонятный ответ
тоже означают вопрос человеку, а не молчаливое «разрешаю». Проверяет модель из настройки
`ai.reviewModel` (пусто — активная модель беседы), а сам выключатель — `ai.approvalReview`;
по умолчанию проверка выключена.

Когда правки не применяются сразу, ассистент держит их в буфере: файл на диске остаётся
прежним, вкладка помечена «не сохранён», и запись на диск делает кнопка «Сохранить»
в сводке изменений. При «Правках» и полном доступе карточки нет, а правка сразу ложится
на диск: следующее чтение файла ассистент делает с диска и незаписанный текст не должен
принимать за применённый. Итог каждого вызова говорит прямо, осталась ли правка в буфере.

**Как выглядит лента.** Ход работы виден у каждого вызова: галочка в круге — готово, крест —
ошибка, вращающийся круг — выполняется, а рядом — сколько вызов занял (сборка отличается от
чтения файла одним этим числом). Раскрытая карточка — разбор вызова: с чем инструмент позвали
(аргументы как есть, с отступами) и что он ответил и вернул. Аргументы и результат копируются
значком в заголовке своей части. В шапке группы свёрнутых вызовов — те же значки плюс
счётчики: сколько вызовов, сколько файлов тронуто и сколько упало.

**Цель работы.** Отдельно от плана есть цель — то, что нужно довести до конца, а не
ответить за один ход. Ассистент ставит её сам, когда задача оказалась многошаговой
(«довести сборку до зелёного»), и с этого момента ответ не считается финалом: прогон
продолжает работу сам, не больше трёх раз подряд. Цель видна строкой над полем ввода —
с текстом и значком, которым её можно снять; снятая цель останавливает продолжения сразу.
Закрывает её ассистент, когда работа кончилась, и после этого продолжений тоже нет, даже
если ход был не последним.

Цель живёт в беседе, а не в одном ответе: она уходит модели в каждом следующем вопросе
и переживает перезапуск окна — работа могла остаться незаконченной. Если ассистент трижды
подряд закончил ход, не закрыв цель, дело не в нехватке шага: тогда он останавливается и
говорит, что цель недостижима или требует решения человека.

От плана цель отличается тем, что описывает: план — это шаги одной задачи (и он живёт,
пока идёт ответ), цель — условие «готово» (и она живёт, пока её не закроют).

**Вопрос человеку.** Ассистент может остановиться и спросить: карточка в ленте с полем ввода
и кнопками вариантов, если они есть. Ответ уходит модели результатом вызова, а прогон
продолжается тем же шагом.

**Подзадача.** Отдельный агент со своим контекстом: длинное чтение он делает «на стороне»
и возвращает краткий отчёт — файлы, строки, имена, вывод команд. Правки и команды остаются
за основным ассистентом.

**Память проекта.** Заметки, которые переживают беседу и её сжатие: предпочтения, решения,
«как запускать». Области две — заметки проекта и личные (годные в любом проекте). Хранятся
обычными `.md`-файлами в папке данных приложения, их видно и можно править руками. Потолок —
40 заметок.

**Навыки.** Готовые сценарии работы — «как выпускать версию», «как гонять проверки»,
«как устроен этот проект». От правил проекта они отличаются тем, когда платят за контекст:
правила читаются целиком в каждый запрос, а от навыка ассистент видит только имя и одну
строку описания — тело подгружается, когда задача совпала с описанием. Свои навыки лежат
в проекте, в папке `.chui/skills`, и уезжают вместе с ним в репозиторий; общие для всех
проектов — в `.chui/skills` домашнего каталога; при одинаковом имени выигрывает проектный.
Навык — папка с файлом `SKILL.md` либо одиночный `.md`. Начало файла может быть шапкой
с `name` и `description` в строках `---`; без шапки именем становится имя папки (или файла),
а описанием — первый абзац. В список попадает до 40 навыков.

**Свои команды.** Повторяющийся запрос можно сохранить как команду и вызывать её из меню
композера: `/review`, `/release`, `/release только changelog`. Команда — обычный `.md`-файл
в папке `.chui/commands` проекта (уезжает в репозиторий) или в `.chui/commands` домашнего
каталога (общая для всех проектов); при одинаковом имени выигрывает проектная. Имя команды —
имя файла, описание — строка шапки `---` (без шапки — первый абзац), тело — сам запрос.
Набранный после имени хвост подставляется на место `$ARGUMENTS` (можно писать `$ARG`),
а если такого места в тексте нет — дописывается отдельным абзацем. Подсказка появляется
при наборе `/` вместе со встроенными командами, и свои идут первыми.

**Расписание задач.** Задачу можно поставить на время, и ассистент начнёт её сам —
без вопроса в поле. Задача — это название, запрос и правило: раз в день, по выбранным
дням недели или один раз в дату. Время задаётся вместе с часовым поясом, поэтому
«пятница, 17:00, Europe/Moscow» сработает в пятницу вечером по Москве, а не по часам
ноутбука, уехавшего в другую страну. Задачи хранятся в проекте — в папке `.chui`
(файл `schedules.json`) — и уезжают вместе с ним в репозиторий; настраиваются из AI →
«Расписание задач…». Каждый запуск — новая беседа, поэтому прошлый разговор её не
отяжеляет; список показывает, когда задача сработает в следующий раз и чем кончился
прошлый запуск — с итогом словами: «готово», «ошибка», «пропущен» (ассистент был занят или
выключен) или «остановлен» (генерацию прервали). У разовой задачи после срабатывания
дальше запускаться нечему, поэтому она выключается сама. Задачи срабатывают, пока проект
открыт: закрытое приложение ничего не запускает, а пропущенное время не догоняет пачкой —
задача просто срабатывает один раз после открытия. Задачу можно приостановить или
выполнить вручную, не дожидаясь её часа; вручную запускается и приостановленная.
Правило бывает и «каждые N минут» — от минуты до недели. Оно считается от прошлого запуска,
а не от часов на стене, и простой не догоняет: после недели отпуска задача сработает один раз,
а не три тысячи; в списке это читается словами — «каждую минуту», «каждые 3 часа», «каждые 2 дня».

Задачу можно поставить и словами в чате: «каждый будний день к девяти собери сводку по вчерашним
коммитам» — ассистент заводит её сам и потом показывает список с идентификаторами, правит на месте
(история запусков при этом не сбрасывается) и удаляет. Правит он только названное: менять правило
не значит заводить задачу заново.

**Программа вместо десятка вызовов.** Читать по одному файлу, искать, ещё раз искать, сводить
найденное — это оборот к модели на каждый шаг, и каждый оборот оплачен контекстом. Инструмент
`run_code` позволяет сделать то же одной программой на JavaScript: внутри неё инструменты —
обычные функции, а перебор, фильтрация и склейка идут кодом. `await tools.read_file({ path })`
возвращает `{ ok, summary, text }` — то же, что вернул бы обычный вызов, с теми же правами,
подтверждениями и записью правок. В программе доступны `await` и `return`, импорты не нужны
и типов TypeScript нет — это JavaScript.

Исполняется она отдельным процессом, и это не формальность: программа может зависнуть, упасть
или напечатать мегабайты, а беседа продолжает работать. Три ограничения держат её в рамках.
Файлы: читать можно проект и папку запуска, писать — только в папку запуска, поэтому правки
проекта делаются инструментами, где есть ревью и отмена. Потомки: запустить ещё один процесс
из программы нельзя — для команд есть `run_terminal`. Время и вызовы: 2 минуты и 80 вызовов
на запуск, и то и другое можно уменьшить. При включённой песочнице инструмент не предлагается:
программа Node внутри контейнера без инструментов бесполезна, а запуск её на хосте обошёл бы
обещание песочницы.

**Сценарий из агентов.** Когда работу надо не пройти по шагам, а раздать и разветвить по
отчётам — «проверь три версии и оставь ту, что прошла тесты», — есть `workflow`. Это тоже
программа на JavaScript, но вместо инструментов в ней подчинённые агенты:
`const a = await agents.run({ prompt, description })` возвращает отчёт
`{ ok, summary, text }`, а `agents.parallel([...])` запускает пачку разом. Отчёт — обычное
значение, поэтому сценарий ветвит по нему как угодно: `if`, `filter`, передача следующему
агенту дословно.

Инструментов в сценарии нет вовсе — читать и править проект умеют те, кому он раздал работу,
иначе это был бы `run_code` под другим именем. Пределы: 6 агентов и 5 минут (каждый агент —
отдельный прогон модели, то есть деньги), одновременно работают не больше трёх. Агенты — те же
подзадачи, что у `task`: только чтение, и сами они никого не запускают, поэтому дерево прогонов
не вырастает. Упавший агент не роняет сценарий — тот получает отказ и решает сам.

**Поиск и чтение страниц.** Два шага наружу, и включаются они по отдельности. Поиск
(`web_search`) отдаёт выдачу — заголовки, ссылки и короткие описания; сама страница остаётся
непрочитанной. Чтение (`web_fetch`) открывает ссылку и отдаёт её текстом: заголовок, содержимое
без разметки и ссылки со страницы, по которым ассистент идёт дальше. Разметка разбирается с
сохранением структуры — заголовки, списки, таблицы и блоки кода остаются узнаваемыми, — а
скрипты и стили выбрасываются: их содержимое текстом страницы не является. Открывается только
`http` и `https`, адрес проверяется до запроса, ответ ограничен по времени и размеру (тело — до
4 МБ, текста модели — 20 000 символов, больше 60 000 не отдаётся даже по просьбе). Если текста
почти нет, страницу, скорее всего, собирает скрипт — тогда её смотрит браузер, и об этом в ответе
сказано прямо. Файлы (картинки, архивы, pdf) чтение страниц не берёт, а отказы называются словами:
«сайт не пускает без входа», «такой страницы нет», «по адресу лежит файл». Настройки —
`ai.webSearch` и `ai.webFetch.enabled` в разделе AI; по умолчанию оба выключены, потому что это
единственные действия ассистента, которые ходят в интернет.

**Браузер.** Ассистент может открыть страницу, снять её снимок (заголовок, адрес, интерактивные
элементы и видимый текст), нажать, ввести текст, вычислить выражение и менять масштаб страницы —
чтобы посмотреть вёрстку в другой ширине. Открываются только `http` и `https`. Действия на
странице спрашивают подтверждение карточкой в ленте; масштаб — нет, он ничего на странице не
меняет. Настройка `ai.browser.integrated` выбирает, работать ли во встроенном браузере или в
отдельном.

**Долгие команды в фоне.** Сборка, установка зависимостей и прогон тестов занимают минуты,
и держать на них весь ответ незачем: такую команду ассистент запускает в фоне и получает номер
задания. Дальше он может заниматься другим, а состояние и новый вывод забирать по номеру —
по частям, а не заново, — и снять задание, если стало ясно, что запуск не тот. Заданий не
больше десяти, у каждого свой предел времени, а полный вывод сохраняется в файл, если он
длиннее того, что стоит держать в памяти. В песочнице фоновый запуск не поддерживается:
контейнер живёт ровно на время команды.

**Песочница.** Режим для команд и тестов: они выполняются в контейнере (`docker` или `podman`),
и внутрь отдаётся только корень проекта. Ни домашнего каталога, ни ключей контейнер не видит.
Если песочница включена, а движка нет, команда не выполняется — ни на хосте, ни как получится.
Настройка `ai.sandbox`.

**Как называется беседа.** Сразу после первого вопроса вкладка называется по нему — короткой
обрезкой, чтобы было понятно, о чём речь. Когда приходит ответ, ассистент переспрашивает
у модели название по сути разговора («Сборка падает на macOS» вместо «проверь, что тут
слома…»): в полосе из нескольких вкладок обрезки вопросов почти не различаются. Это один
короткий запрос без истории и инструментов; если модели нет или она промолчала, подпись
остаётся прежней.

**Где живёт беседа.** Обычно панелью справа, но её можно перенести в область редактора
(`Ctrl+Alt+E`) — тогда беседа становится вкладкой рядом с файлами: пока она открыта, код уступает
место, а переход к файлу возвращает полотно. Обратно — той же комбинацией или командой «Вернуть
чат в боковую панель». Кнопка «Информация о сессии» в строке состояния и её окно работают в обоих
случаях: окно раскрывается выше полотна и вкладок.

**Что было в прогоне.** Под ответом стоит короткая строка — сколько прогон занял, из
скольких шагов состоял и сколько сделал вызовов. Нажатие на неё открывает окно «Прогон»
(или команда «Прогон агента: трасса»): что именно ушло модели — системные инструкции и
контекст проекта отдельными блоками, приложенное к вопросу, — и каждый шаг с вызовами:
имя инструмента, аргументы, результат и сколько он занял. По этому видно, на что ушла
минута: ожидание модели или сборка в терминале, — а не приходится догадываться по ленте.
У вызова пять вкладок: сводка, аргументы (тот же JSON, но разложенный по полям), результат,
схема инструмента — та форма аргументов, которую видели модель (у внешних серверов MCP в том числе),
и время: когда вызов начался, сколько занял и какую часть шага составил.
В шапке окна сказано, чем прогон кончился — ответом, пределом шагов или остановкой, — а у
вызовов стоят пометки о том, что иначе выглядело бы странно: «повтор: не исполнялся»,
«диапазон уже прочитан», «режим плана». Шаги подзадачи (`task`) в список не подмешиваются:
у неё свой контекст, поэтому она отдельная строка — но её шаги входят в итог, они тоже
стоили токенов. Трасса живёт до перезапуска: в файл беседы она не пишется, иначе история
распухла бы выводами инструментов.

**Журнал прогонов.** Трасса под ответом живёт до перезапуска окна, а разбираются с ней обычно
на следующий день. Поэтому прогон можно записывать в файл: настройка «Писать журнал прогонов
в файл» в разделе AI, а смотреть — команда «Журнал прогонов…» (список последних прогонов,
путь к файлу, кнопки «Показать файл» и «Очистить»). Каждый прогон — одна строка JSON в журнале
в папке данных приложения: что ушло модели, шаги с вызовами, время и итог. Ключи и пароли
при записи вычищаются: узнаваемые (sk-, ghp_, AIza, AKIA и подобные), заголовок `Bearer`,
пароль в адресе и любое `api_key`/`token`/`secret`/`password` со значением — имя поля остаётся,
значение скрывается. По умолчанию выключено: в записи ваши инструкции и ответы модели, и файл
хоть и лежит только на этом компьютере, решать это вам.

**Контекст и расход.** Кнопка «Информация о сессии» показывает заполнение и разбивку по частям,
а «Сжать беседу» заменяет историю пересказом; при подходе к пределу окна модели беседа сжимается
сама. Панель показывает и последний обмен, и итог за беседу: число шагов, вызовов инструментов
и токенов со стоимостью. Перед отправкой модели вывод инструментов чистится от оформления
(прогресс-бары, повторы, служебные последовательности) — настройка «Сжимать вывод инструментов».
Крупные выводы не уезжают в историю целиком. Тела правок, которые уже легли в файл, из
контекста убираются: там от них остаётся строка «применено: N стр. — текст в файле». Это
видно только модели — в ленте и в файле беседы правка остаётся целиком, со своим текстом.
Так сделано ради префикса запроса: он кешируется у провайдера, и сжатие делается один раз,
сразу после шага, а не задним числом на каждом. Правка одного файла не стирает память о
прочитанном в остальных: заново читается только то, что изменилось. Если описания инструментов
не помещаются в окно, запрос не отправляется вовсе, а в ленте появляется объяснение с числами —
вес схем считается по составу строки, а не по длине: описания по-русски «весят» вдвое дороже.

## Темы и шрифты

**Оформление.** Палитра у приложения одна — тёмная. Цвета заданы ролями (поверхности, текст,
линии, акценты), а не оттенками по местам: поэтому панели, меню и подсказки выглядят одинаково
и подсветка кода нигде не спорит с оболочкой. Панели и полотно редактора лежат тёмными плитами
на светлом фоне окна, активная вкладка приподнята над полосой, попапы и меню — светлее всего
остального. Подсветка кода — привычная тёмная палитра.

**Своя тема.** В настройках, раздел «Оформление», есть «Тема из файла». «Импортировать…» берёт
JSON с частью ролей (фон, текст, акценты, цвета подсветки кода) и кладёт его поверх встроенной
палитры; «Сохранить шаблон…» отдаёт файл встроенной палитры целиком — из него удобно начать свою;
«Убрать» возвращает встроенные цвета. Рядом — «Масштаб интерфейса»: крупнее или плотнее оболочка,
панели, меню и дерево.

При системной настройке повышенного контраста берутся более контрастные ступени, при уменьшении
прозрачности всплывающие слои становятся плотными, при уменьшении движения анимации выключаются.

**Шрифты.** Оба семейства лежат в приложении, а не берутся из системы: интерфейс — Inter; код,
терминал и название приложения — моноширинный шрифт. Лицензия у обоих — SIL Open Font License 1.1.

## Правила проекта и исключения

Ассистенту подмешиваются путь к проекту и все найденные файлы правил: `.ai_rules`, `AGENTS.md`,
`CHUI.md`, `CLAUDE.md` — до 8 000 символов каждый и до 20 000 на все вместе. Имена разные потому,
что так их называют разные инструменты; правила из `.ai_rules` идут первыми и потому имеют последнее
слово. Читаются только файлы в корне проекта.

Поиск по содержимому, массовая замена, список файлов быстрого открывателя и поиск файлов по имени
учитывают `.gitignore` и `.ai_ignore` из корня проекта. `.ai_ignore` читается вторым, поэтому его
`!` перебивает исключение из `.gitignore`. Синтаксис — как у gitignore: `#` комментарий, `!` вернуть
обратно, хвостовой `/` — только папки, ведущий `/` — от корня, `**` перешагивает папки, `?` — один
символ, `[0-9]` — класс. Правила перечитываются на ходу, без переоткрытия проекта. Дерево проекта
эти исключения не трогают — у него своя настройка `explorer.exclude`.

## Безопасность

- Ключи и другие секреты остаются внутри приложения — в окне их не видно.
- Любой путь нормализуется и проверяется на выход за пределы рабочей папки.
- Удаление файлов — через корзину.
- Действия ассистента, меняющие файлы и окружение, спрашивают подтверждение карточкой в ленте;
  в режиме «План» изменения не выполняются вовсе. Спрашивать ли, решает выбранный уровень прав:
  при «Правках» и полном доступе правки и команды идут без вопроса — но необратимые команды
  всё равно могут спросить, пока включена страховка.
- Проверка подтверждений моделью (`ai.approvalReview`) по умолчанию выключена и решает
  только о командах: правки, действия git и браузера она не одобряет.
  Разрешить она может лишь то, что не попало в список необратимого; `rm`, `sudo`,
  `git push --force` и запись в системные каталоги она не трогает — их спрашивают у вас
  всегда. Судит она по тексту команды: что делает вызванный скрипт, проверка не видит,
  поэтому непонятное и всё, что похоже на запуск своего кода, лучше оставить на вопрос.
  Ошибка сети, таймаут и непонятный ответ означают вопрос человеку, а не разрешение.
- Поиск и чтение страниц включаются отдельно и по умолчанию выключены. Чтение открывает только
  `http` и `https` — проверка идёт до запроса, так что `file:`, `data:` и `javascript:` до сети
  не доходят. Содержимое чужой страницы помечено в ответе как данные, а не указания: просьбы
  и команды внутри текста ассистент выполнять не должен, а сам текст обрезан и об этом сказано.
- Картинка из проекта (`read_image`) — такое же чтение файла, как `read_file`: путь проверяется
  рабочей папкой, вопросов не задаётся. Но само изображение уходит провайдеру модели вместе
  с запросом — как и картинка, приложенная к вопросу руками. Если на скриншоте есть секреты
  (токен в окне, личные данные), они уедут туда же.

## Ограничения текущей версии

- Переводы строк нормализуются к `\n` — файлы с CRLF перезаписываются в LF.
- Файлы больше 2 МБ открываются только для чтения (курсор, поиск и копирование работают, правка —
  нет), а больше 16 МБ не открываются и вовсе. К такому файлу не подключается ни языковой сервер,
  ни проверка импортов.
- Переименование открытого файла закрывает и заново открывает его вкладку.
- Интерактивный rebase рассчитан на линейную историю последних коммитов и требует чистого рабочего
  дерева. Сообщение для `reword` сопоставляется по исходному тексту: если два коммита в списке имеют
  одно и то же сообщение, новое применится к обоим.
- Языковые серверы, которые едут с приложением, добавляют к размеру дистрибутива порядка 150 МБ.
  Подсветка, отступы, комментарии и запуск работают и без них.
- Записные книжки (ячейки Jupyter) не поддерживаются.
- Выбор элемента на странице видит обычный DOM: содержимое теневых деревьев и элементы внутри
  фреймов описываются как их хозяин, а не как то, что вы видите.
- Программа (`run_code`) — это JavaScript без типов и без импортов: она пишет `tools.<имя>(args)`,
  а не работает с проектом напрямую. Сеть из неё доступна, как и любому процессу Node, — файлы
  при этом закрыты, а правки идут только через инструменты.
- Чтение страницы по ссылке (`web_fetch`) снимает разметку, но не исполняет скрипты: у страниц,
  которые собираются в браузере, текста почти не будет — их смотрит инструмент браузера. Файлы
  (картинки, архивы, pdf) этот инструмент не читает; отдаётся только текст, поэтому содержимое
  PDF или таблицы по ссылке он не покажет.
- Картинку (`read_image`) модель видит только тем кадром, что пришёл в запросе: у GIF это один
  кадр, а TIFF, HEIC и SVG не отправляются вовсе (SVG — это текст, его читают `read_file`).
  В историю беседы картинка не пишется — в следующем вопросе её нет, и если она нужна снова,
  агент читает файл повторно. Внутри программы (`run_code`) инструмент недоступен.
- Задачи расписания срабатывают только при открытом проекте: приложение не держит
  службу, которая работала бы с закрытым окном, а пропущенные срабатывания не догоняются.
- Проверка подтверждений моделью судит по тексту команды и не знает содержимого скриптов,
  которые эта команда запускает.
- Трасса прогона живёт в памяти до перезапуска окна: в файл беседы она не пишется.
- Основной сценарий — Linux и macOS.

## Если окно не отвечает

Симптом: окно замирает и перестаёт реагировать, а загрузка ядра у его процесса держится
около 100 %.

Проверить стоит по состоянию — загрузка ядра отличает зацикливание от взаимной блокировки:

```sh
ps -o pcpu,args | grep chui
```

Остаётся закрыть окно и запустить приложение заново — несохранённые правки при этом теряются.
Встроенный отладчик в этом случае не помощник: пока приложение занято зацикливанием, оно
не отвечает даже на команды отладки.

## Если приложение упало

Сбои пишутся в журнал рядом с `settings.json`, в каталоге данных приложения. Туда же попадает
и стек, так что журнал — единственное место, где видна причина: без него от падения осталось бы
только закрывшееся окно.

Записываются необработанные ошибки и отклонённые обещания, падение окна и падение подсобных
процессов. О сбое приложение спрашивает диалогом: причина, путь к журналу и кнопка «Перезапустить».
Диалог показывается один раз за запуск, а перезапуск — по кнопке: несохранённые буферы живут
в окне, и молчаливый перезапуск их бы выбросил.
