# Правила проекта (Chui IDE)

Файл читается агентом при каждой сборке промпта
(`src/main/ai/workspace-context.ts`),
потолок — 4000 байт на файл и 6000 на все правила вместе. Держи коротко.

## Перед словом «готово»

- `npm run check:static` — typecheck, format:check, lint, check:layers.
- `npm test` — vitest. С покрытием и целиком — `npm run check`.

Не проверял — не говори, что работает.

## Слои

- `src/shared` — чистый TS: ни Node, ни Electron, ни DOM. Границы заданы в
  `src/shared/layer-rules.ts`, проверяются `npm run check:layers`.
- `src/main` — Node/Electron, ФС, процессы. `src/renderer` — только DOM.
- Связь между ними — IPC через `src/shared/api` и `src/preload`. Renderer про
  ФС и процессы не знает.

## Стиль

- biome: 2 пробела, 120 колонок, одинарные кавычки, `;`, trailing comma, LF.
- `any` в новом коде не заводить (линтер ругается). Неиспользуемый импорт —
  ошибка сборки, неиспользуемая переменная — предупреждение.
- Комментарии по-русски и про «почему так, а не иначе». Что делает код — видно
  из кода; JSDoc нужен там, где не видно (откуда число, почему этот порядок).
- Имена — английские. UI, сообщения, коммиты — русские.

## Тесты

- `tests/<модуль>.test.ts` называется по модулю из `src`.
- Настоящие git/rg/lsp не запускать: подделки — POSIX-скриптами, на Windows
  тест пропускается.
- Баг сначала воспроизводится тестом или замером (`scripts/*-probe.cjs`),
  потом правится.

## Правки

- Минимальный диф, не переписывать файл целиком.
- Не выдумывать API: сперва прочитать сигнатуру.
- Поведение сверять с запуском, а не с документацией.
- Чужой файл не переформатировать ради единообразия — только вокруг правки.

## Задачи и долги

- Открытые пункты — в `TASKS.md`; закрытые удаляются, историю там не держим.
- «Этого не делаем» — в `UPSTREAM.md`, раздел «Снято с рассмотрения».
- Свой бэклог не изобретать: только то, что попросили.
- Новая подсистема = smoke/probe-скрипт в `scripts/` по образцу уже имеющихся.

## Руки прочь

- `dist/`, `node_modules/`, номера версий зависимостей без нужды.
